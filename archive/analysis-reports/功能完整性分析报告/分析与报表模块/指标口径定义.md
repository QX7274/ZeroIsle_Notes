# 分析与报表模块 - 核心指标口径定义 v1.0

本文件旨在为"零屿笔记"项目的所有分析与报表功能提供一个统一、明确的核心指标定义标准。所有模块在进行数据统计、报表生成或业务分析时，都必须严格遵守此文件定义的口径，以确保数据的一致性、准确性和可比性。

---

## 1. 用户指标

### 1.1. 日活跃用户 (DAU - Daily Active Users)

-   **定义**: 在一个自然日（UTC 00:00:00 至 23:59:59）内，至少执行了一次有效操作的独立用户数。
-   **技术口径**:
    -   通过 `personal_activities` 集合进行统计。
    -   统计在指定日期范围内，有至少一条活动记录的 `user_id` 的去重总数。
    -   "有效操作" 指创建了任何类型的 `ActivityRecord`，包括但不限于笔记创建/编辑、任务完成、社区发帖等。
-   **伪代码**: `db.personal_activities.distinct('user_id', {'created_at': {$gte: date_start, $lte: date_end}}).length`

### 1.2. 月活跃用户 (MAU - Monthly Active Users)

-   **定义**: 在一个自然月内，至少执行了一次有效操作的独立用户数。
-   **技术口径**: 同DAU，但时间范围扩展至一个自然月。
-   **伪代码**: `db.personal_activities.distinct('user_id', {'created_at': {$gte: month_start, $lte: month_end}}).length`

### 1.3. 新增用户 (New Users)

-   **定义**: 在指定时间范围内（日、周、月）完成注册的独立用户数。
-   **技术口径**:
    -   通过 `users` 集合进行统计。
    -   统计 `date_joined` 字段落在指定时间范围内的用户总数。
-   **伪代码**: `db.users.count({'date_joined': {$gte: date_start, $lte: date_end}})`

### 1.4. 用户粘性 (Stickiness)

-   **定义**: 衡量用户活跃度的指标，通常以 DAU/MAU 的比率表示。
-   **技术口径**: `(当天的DAU) / (过去30天的MAU)`。
-   **注意**: 计算MAU时，应使用过去30天，而不是当前自然月，以获得更平滑的曲线。

### 1.5. 用户留存率 (User Retention Rate)

-   **定义**: 在特定时间周期（例如，某一天或某一周）内注册的新用户，在后续的某个时间点（例如，第1天、第7天、第30天）仍然活跃的比例。
-   **技术口径**:
    -   **队列 (Cohort)**: 按用户的 `date_joined` 字段进行分组，例如，按天分组。
    -   **活跃判断**: 在后续的第N天，检查该队列中的用户是否出现在当天的活跃用户列表（DAU）中。
    -   **计算**: `(第N天仍然活跃的队列用户数) / (队列总用户数)`。

## 2. 内容与功能指标

### 2.1. 内容创建量 (Content Creation)

-   **定义**: 在指定时间范围内，用户创建的各类核心内容的数量。
-   **技术口径**:
    -   **笔记创建**: `notes` 集合中，`created_at` 在指定范围内的文档总数。
    -   **社区帖子创建**: `community_posts` 集合中，`created_at` 在指定范围内的文档总数。
    -   **提醒创建**: `reminders` 集合中，`created_at` 在指定范围内的文档总数。

### 2.2. 功能使用次数 (Feature Engagement)

-   **定义**: 在指定时间范围内，特定功能被调用的次数。
-   **技术口径**:
    -   通过 `audit_logs` 集合进行统计。
    -   统计 `action` 字段匹配特定功能（如 `reminder_completed`, `document_converted` 等）且 `created_at` 在指定范围内的日志总数。
    -   **示例 - 搜索次数**: `db.audit_logs.count({'action': 'search_executed', 'created_at': {$gte: date_start, $lte: date_end}})`

---

## 3. 报表生成规范

1.  **时区**: 所有报表和统计都必须使用UTC标准时区，以避免歧义。
2.  **缓存**: 对于计算成本高的指标（如MAU、留存率），应建立定时任务（如每天一次）进行预计算，并将结果缓存到 `personal_activity_reports` 集合中，以提高查询性能。
3.  **数据源**: 必须严格遵守本文件定义的数据源和技术口径，禁止从其他未经授权的来源进行统计。
