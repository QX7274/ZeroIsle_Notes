# 版本追踪完整性分析报告

## 1. 功能概述
- 定位：为笔记提供修改留痕、历史版本浏览、版本对比与回滚能力。
- 场景：误删/误改恢复、审阅编辑过程、协作编辑后的差异核对。
- 模块关联：与“同步与离线（增量/冲突）”“导入导出（带历史）”“搜索（版本时间过滤）”联动。

## 2. 前端实现分析
- 关键路径：
  - 编辑屏幕：`src/screens/note/NoteEditorScreen.js`（保存时生成本地快照/updated_at）
  - 分页画布：`src/screens/note/SkiaPagedCanvasScreenNative.js`（画布版本与文本版本的协同，需确认）
  - 历史UI（需确认是否存在专用面板）：建议在 Note 详情页集成“历史版本”列表与对比视图。
  - 服务：`src/services/notes/enhancedNoteService.js`, `src/services/notes/noteService.js`（加载历史、回滚）
  - 模型/Schema：`src/models/Note.js`, `src/schemas/noteSchema.js`（应包含 version/updated_at; 历史可单独 collection）
- 交互：
  - 版本列表（时间、作者、摘要）→ 选择两版对比（左右分栏/高亮差异）→ 回滚当前版。
  - 未保存提醒：版本切换前的脏检查。
- 主题一致性：列表项、对比视图、按钮风格与主题统一。
- 问题清单：
  - 需确认：是否存在专门的历史版本数据结构（本地/远端）；
  - 需确认：回滚是否仅本地还是远端持久化生效；
  - 需确认：画布类笔记的历史粒度与合并策略。

## 3. 后端实现分析
- API端点（参考 `src/config/api.js`）：
  - `GET /notes/{id}/history/`（历史列表）
  - 建议新增：`POST /notes/{id}/history/rollback/`（回滚到指定版本）、`GET /notes/{id}/history/compare/?from=..&to=..`（差异）
- 模型：
  - `backend/notes/mongodb_models.py`（Note文档/时间戳/修改人），建议新增 NoteHistory 文档或嵌入式历史条目；
  - `backend/notes/serializers/*`（版本序列化）
  - `backend/notes/views/*`（历史拉取/对比/回滚）
- 业务：
  - 历史保存策略（按次/按时/按重要操作）；最大历史数/保留策略；
  - 回滚幂等性与权限（仅作者/管理员可回滚）；
  - 差异计算（后端生成diff，前端渲染高亮）。
