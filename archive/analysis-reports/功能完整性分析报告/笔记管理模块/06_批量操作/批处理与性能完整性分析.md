# 批处理与性能完整性分析报告

## 1. 功能概述
- 定位：针对多笔记的批量操作（批量标签/分类变更、批量删除/恢复、批量导出、批量分享设置），并保障在本地与远端的一致性与性能。
- 场景：一次性整理大批笔记标签、定期归档/删除、批量导出备份、批量设置权限。
- 关联：
  - 同步与离线：批量本地变更与增量同步、冲突合并；
  - 搜索：筛选后批量操作；
  - 导入导出：批量导出实现与后台任务；
  - 权限/日志：批量操作的审计记录。

## 2. 前端实现分析
- 关键路径：
  - 列表屏幕：`src/screens/note/CardNoteScreen.js`（建议支持多选与批量操作面板）
  - 服务：`src/services/notes/noteService.js`（应提供批量 PATCH/DELETE 调用）、`src/services/notes/enhancedNoteService.js`
  - 选择状态：Redux/Context 保存选中集合与批处理状态；
- 交互：
  - 列表进入批量模式 → 多选 → 打开批量操作面板（分类/标签/删除/导出/分享） → 提交任务 → 进度与结果提示；
- 主题一致性：批量模式的顶部工具条、菜单项风格与全局一致；Loading/Toast 统一。
- 问题清单（前端）：
  - 需确认：多选交互与状态持久化；
  - 需确认：批量任务进度/错误明细 UI。

## 3. 后端实现分析
- API端点（建议）：
  - `POST /notes/bulk/update/` → body `{ids:[], set:{category_id,tags}, unset:{}, mode:'merge|replace'}`
  - `POST /notes/bulk/delete/` → `{ids:[]}`（软删）
  - `POST /notes/bulk/restore/` → `{ids:[]}`
  - `POST /notes/bulk/export/` → `{ids:[], format}` → 返回 `{task_id}` 与下载状态端点
  - 权限：属主校验；
- 模型与索引：`backend/notes/mongodb_models.py`；操作需原子性/分批提交（每批500~1000）；
- 业务与边界：
  - 幂等与部分成功返回（统计成功/失败计数与失败列表）；
  - 审计：记录批处理摘要（操作者、数量、范围、字段变更）。
- 性能：
  - 分批 bulk_write；
  - 索引命中（user, category_id, tags）；
  - 导出走异步队列+流式输出。
