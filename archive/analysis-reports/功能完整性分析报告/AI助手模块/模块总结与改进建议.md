# AI助手模块 - 模块总结与改进建议

本总结基于对 AI 助手模块的逐功能完整性分析（文本处理、图像分析、语音交互）。整体能力完备，存在少量“契约不一致/平台差异/返回结构不统一”问题与若干UX细节待统一。

## 一、总体结论（模块层）
- 功能覆盖：文本处理 9/9 已打通；图像分析（iOS区域OCR完成，Android待实现；图片描述/分析后端有服务，前端调用链待标准化）；语音交互（转写链路完整但存在上传字段名不一致；TTS服务存在、未见集成）。
- 一致性：前端仍调用部分 legacy 端点（/translate、/summarize、/transcribe），与“统一 /process”策略不符；OpenAI SDK 在不同服务中存在新旧混用。
- 体验：工具栏样式基本统一；AIAssistantScreen 页头图标未与规划同步（psychology → smart-toy）。
- 质量：错误处理有多级兜底（在线→本地→模拟），建议引入统一重试、熔断、提示策略；后端返回结构需固化JSON schema，减少前端解析分支。

## 二、关键问题清单（按优先级）
### 🔴 高优先级
1) 语音转写上传字段名不一致
- 前端：`FormData.append('audio', ...)`（src/screens/ai/AIAssistantScreen.js 第321-326行）
- 后端：`transcribe_audio` 视图期待 `file` 字段（backend/ai_assistant/legacy_views.py 第131-145行）
- 影响：400 未上传文件 → 功能直接失败；
- 建议：前端字段改为 `file` 或后端容错 `request.FILES.get('audio') or request.FILES.get('file')`。

2) Android 平台 OCR 缺失
- 现状：iOS 完成区域OCR（原生实现）；Android 未实现；
- 影响：跨平台体验不一致；
- 建议：接入 Google ML Kit Text Recognition v2 并提供统一 JS 调用桥接。

### 🟡 中优先级
3) 端点不统一（legacy vs /process）
- 现状：translate/summarize 仍走 `/translate` `/summarize`；其余多走 `/process`；
- 影响：策略/体验/日志统计分裂；
- 建议：前端全部统一到 `/ai-assistant/process/` + `tool` 参数，后台按 tool 分支处理；保留 legacy 仅做兼容。

4) OpenAI SDK 混用
- 现状：TextProcessingService 使用新 SDK（openai.OpenAI(...).chat.completions.create）；WhisperService 使用旧式 `openai.Audio.transcribe`；ImageAnalysisService 使用 `openai.ChatCompletion.create` 旧接口；
- 建议：统一至新 SDK 接口族，集中封装错误分类、超时、重试策略。

5) 返回结构不统一
- 现状：代码识别/数学公式等功能可能返回字符串或JSON；前端存在多分支解析；
- 建议：后端固化 schema（例如 `{formatted_code, language}` / `{latex}` / `{keywords: string[]}`）。

6) TTS（语音合成）服务未集成
- 现状：`src/services/tts/ttsService.js` 存在，但全局未引用使用；
- 建议：在 AIAssistantScreen/ChatMessage 增加“朗读”操作；提供语速/语言/声音选择；
- 附：ttsService 当前代码疑似误用 `setDefaultVoice` 作为音量设置，需更正；字符串有编码异常（“语�? ”等）。

### 🟢 低优先级
7) UI 细节一致性
- 页头图标未统一（AIAssistantScreen 仍为 psychology）；
- 建议：统一为 smart-toy；核查圆角、阴影、间距是否与主题规范一致。

8) 图像分析前端调用链待标准化
- 现状：工具栏支持图片选择，但“图片→后端 analyze-image 的任务分派”由容器自行处理；
- 建议：提供统一的 `aiService.analyzeImage({ task })` 并在工具栏打通，支持 describe/analyze/extract_text。

## 三、改进路线图（两周计划）
- 第1-2天（高优先）
  - 修复转写字段名不一致（FE/BE 任一侧）
  - 统一 AIAssistantScreen 页头图标
- 第3-5天（平台与契约）
  - Android OCR（ML Kit）原生实现与 JS 桥接
  - 前端统一 `/process` 端点改造；后端保留 legacy 兼容
- 第6-8天（SDK/Schema）
  - 后端统一 OpenAI 新 SDK；固化文本处理/图像分析返回 JSON schema
- 第9-10天（体验增强）
  - 集成 TTS（朗读）；工具栏/消息项增加快捷操作
  - 前端错误统一处理：重试/熔断/用户提示

## 四、验收标准（节选）
- 语音转写：任一平台 10 次上传成功率 ≥ 99%，字段错误 0 次；
- OCR：iOS/Android 均可区域识别，截图/拍照文本提取准确度（可读率）≥ 85%；
- 端点：AI 文本处理前端仅调用 `/process`（监控日志验证）；
- SDK：openai client 使用一致接口，错误分类日志清晰；
- Schema：前端不再进行字符串/JSON双解析分支；
- TTS：在消息项可一键朗读，支持速率/语言选择。
