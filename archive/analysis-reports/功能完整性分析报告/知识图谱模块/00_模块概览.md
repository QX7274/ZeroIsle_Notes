# 知识图谱模块（Knowledge Graph）完整性分析总览

## 1. 模块职责与边界
- 职责：围绕“笔记/知识”的实体与关系进行构建、可视化、查询、分析、推理与导入导出；为搜索、AI助手、知识库等功能提供结构化语义支撑。
- 边界：
  - 输入：笔记内容/标签/分类、AI抽取结果（关键词/概念/相似度）、批量导入文件（RDF/JSON-LD/CSV等）。
  - 输出：节点与关系（Mongo/Neo4j）、可视化视图、分析指标、查询结果、导出文件。
- 关键依赖：
  - 前端：`src/components/knowledge/*`、`src/adapters/knowledgeGraphAdapter.js`、Realm模型（`src/models/*`）。
  - 后端：`backend/knowledge_graph/*`（models/serializers/services/views/urls/utils），`backend/common/*`，`notes.mongodb_models`。
  - 外部：Neo4j（图算法/查询）、AI文本处理服务（抽取/标签/相似度）。

## 2. 主要数据流
1) 自动构建：笔记/文本 →（抽取/分类/相似）→ BuilderService → Mongo/Neo4j → 可视化/分析
2) 手动编辑：前端CRUD → REST(节点/边) → Mongo →（可选镜像到Neo4j）
3) 分析/查询：前端参数 → `/graph/analyze` `/graph/search` `/graph/find-path` → Neo4j/Cypher → 结果 → 可视化
4) 导入导出：文件 → 校验/映射/入库 → 失败回滚；导出 → 生成标准格式

## 3. 关键后端端点与服务
- 路由文件：`backend/knowledge_graph/urls.py`
  - 资源：
    - `GET/POST /knowledge-graph/nodes/`、`/edges/`（REST, ViewSet）
    - Mongo子路由：`/knowledge-graph/mongo/nodes|edges|graphs/`
  - 图谱API：
    - `GET /knowledge-graph/graph/`（列表/概览）
    - `POST /knowledge-graph/graph/find-path/`
    - `GET /knowledge-graph/graph/analyze/`
    - `GET /knowledge-graph/graph/search/`
    - `POST /knowledge-graph/graph/generate-tags/`
  - 自动与构建：
    - `POST /knowledge-graph/auto/auto-classify/`
    - `POST /knowledge-graph/auto/suggest-tags/`
    - `POST /knowledge-graph/auto/extract-keywords/`
    - `POST /knowledge-graph/auto/find-similar-notes/`
    - `POST /knowledge-graph/auto/integrate-notes/`
    - `POST /knowledge-graph/auto/build-graph/`
    - `POST /knowledge-graph/auto/build-user-graph/`
    - `POST /knowledge-graph/auto/analyze-connections/`
    - `POST /knowledge-graph/auto/suggest-related-content/`
- 服务层：
  - `services/knowledge_graph_builder_service.py`（自动构建）
  - `services/analysis_service.py`（统计/路径/子图）
  - `services/extraction_service.py`、`auto_classification_service.py`（抽取/分类/相似）
  - `services/neo4j_service.py`（Cypher/GDS接入）
  - `services/recommendation_service.py`（关联推荐/潜在连接）

## 5. 市场与最佳实践参考
- Neo4j Bloom：搜索优先体验、近自然语言查询、场景导出、Perspective 分类、高亮与模式搜索。
- Obsidian/Roam：全局Graph视图、过滤/高亮、反链、社区聚类；大图下聚合/抽样/隐藏孤点以保流畅度。

## 6. 风险与技术债（摘录）
- Mongo与Neo4j双存储一致性策略需明确（延迟/冲突/回滚）。
- 查询/构建/分析返回Schema需要固化，减少前端多分支解析压力。
- 大图可视化渲染性能（>1k节点）需采用阈值与聚合策略；WebGL优于SVG。
