# 图谱查询完整性分析报告

## 1. 功能概述
- 定位：提供自然语言（或近自然语言）与结构化两类查询能力，支持按属性/类型/模式/路径的检索与分页排序，服务于发现、导航与分析。
- 场景：
  - 查找满足特定模式的知识（例如“概念A -> 相关 -> 概念B”）；
  - 在两节点之间寻找最短路径并可视化；
  - 按标签/类型/时间范围筛选节点与边；
  - 结合全文/语义检索（来自 Search/AI）定位候选后在图中高亮导航。
- 关联：与“多维视图（过滤/高亮）”“节点分析（子图/路径）”“关系推理（候选连接验证）”联动。

## 2. 前端实现分析
### 2.1 UI组件与位置（需核对）
- 组件：
  - `src/components/knowledge/GraphToolbar.js`（提供查询入口/条件编辑）
  - `src/components/knowledge/PathVisualization.js`（路径可视化）
  - `src/components/knowledge/RelatedConceptsView.js`（相关概念/邻域浏览）
  - `src/components/knowledge/KnowledgeGraph.js`（容器态，协调查询与渲染）
- 屏幕：
  - `src/screens/knowledge/KnowledgeGraphScreen.js`、`GraphTab.js`
- 交互流程（建议）
  1) 在 Toolbar 打开“查询面板”，支持结构化（类型/属性/范围/模式）与关键字；
  2) 发起查询 → 展示结果列表（分页）与“在图中高亮”按钮；
  3) 路径查询：选择起点/终点 → 调用最短路径API → PathVisualization 展示；
  4) 支持导出当前结果（CSV/JSON）。
- 状态管理：
  - 当前查询参数/页码/排序与结果缓存；
  - 与可视化共享高亮集合；
  - 主题/UI一致性（按钮、表单、间距）需遵循全局规范。

### 2.2 问题清单（前端）
- 需确认：是否提供“查询DSL/模式编辑器”UI；
- 需确认：分页/排序在前端的默认上限与空态提示；
- 需确认：路径查询的最大深度与失败提示（无路径/超时）。

## 3. 后端实现分析
### 3.1 API端点（`backend/knowledge_graph/urls.py`）
- 图谱接口：
  - `POST /knowledge-graph/graph/find-path/`（最短路径）
  - `GET /knowledge-graph/graph/analyze/`（可返回聚合/统计，支持多维视图）
  - `GET /knowledge-graph/graph/search/`（结构化/模式搜索—需确认支持参数）
  - `POST /knowledge-graph/graph/generate-tags/`（辅助主题归纳）
- 节点接口：
  - `GET /knowledge-graph/nodes/<id>/related/`、`/related-concepts/`
- 自动/AI辅助接口：
  - `POST /knowledge-graph/auto/analyze-connections/`（可用于候选边验证）

### 3.2 服务与实现
- `backend/knowledge_graph/services/analysis_service.py`
  - `get_path_between_nodes(start,end,user_id,max_depth)` 使用 Cypher shortestPath；
  - `get_subgraph(node_id,user_id,depth)` 提供邻域子图；
  - `get_node_statistics/relationship_statistics/get_central_nodes` 用于聚合与多维视图；
- `neo4j_service.py` 封装 Cypher 执行；建议扩展分页/排序/注入防护。

### 3.3 参数与安全（建议约束）
- 分页上限：`page_size <= 100`（可配置），页码>=1；
- 排序白名单：字段与方向（asc/desc）白名单；
- 过滤白名单：节点/边属性键与比较操作限定；
- 深度限制：最短路径 `max_depth <= 6`；子图 `depth <= 3`；
- 防注入：严格参数化，禁止拼接原始 Cypher 片段；
- 审计：记录查询人、参数、耗时、命中量（方便性能调优）。

### 3.4 返回结构（建议固化）
- 搜索：`{ total, page, page_size, items: [{node|edge}] }`
- 路径：`{ nodes: [...], relationships: [...] }`
- 子图：`{ nodes: [...], relationships: [...] }`
- 统一错误：`{ error_code, message, details }`

### 3.5 性能
- 预筛：先按标签/类型/时间范围筛选候选集，再做精确匹配；
- 索引：节点(label/type/title/user)、边(type/source/target/user)
- 缓存：用户最近查询参数与结果（ETag/短期缓存）；
- 速率限制：防止大规模“全图扫描”造成压力。

## 4. 规划一致性检查
- 目标：自然语言/结构化查询 + 路径/子图 + 分页/排序/过滤 + 安全白名单；

## 6. 问题清单
### 高优先级
- 缺统一“搜索参数Schema/排序白名单/分页上限”；
- 路径/子图深度缺跨服务统一限制；

### 中优先级
- 近自然语言查询未落地（可做“搜索短语”到 Cypher 的映射表）。

### 低优先级
- 结果导出的格式与字段映射需定义。

## 7. 改进建议

- 增加导出接口：`/graph/export?format=csv|json`；
