# 多维视图完整性分析报告

## 1. 功能概述
- 定位：为知识图谱提供主题/时间线/关联度等多视角浏览能力，支持过滤与高亮，帮助用户从不同维度理解知识结构。
- 典型场景：
  - 主题视图：按标签/类别/概念类型分组，观察某主题下的核心节点与外延；
  - 时间线视图：按创建/更新时间分桶，查看知识的演化轨迹；
  - 关联度视图：基于边权重/共现次数/相似度高亮强连接区域；
  - 过滤与高亮：按类型/标签/属性筛选节点边，并突出显示命中部分。
- 关联：与“图谱查询”“节点分析”“可视化引擎”紧密耦合，UI控制在 GraphToolbar/ControlPanel，渲染在 GraphVisualization。

## 2. 前端实现分析（续）
### 2.6 性能要点（当前实现与建议）
- 现状：`GraphVisualization.js` 使用 react-native-svg 渲染 + reanimated/gesture-handler 实现缩放/平移；在 300~800 节点应可流畅，>1k 节点可能掉帧。
- 建议：
  - 大图阈值与聚合：>1k 节点启用“社区聚合/按标签聚合/隐藏孤点/抽样边”。
  - 标签延迟渲染：缩放比低于阈值时隐藏文字，仅显示节点；放大后再显示标签。
  - 边抽样与样式优化：长边/重叠边降透明度或聚合为“汇总边”。
  - 预计算布局：后端生成布局坐标（存储在 node.position），前端仅做微调。

## 3. 后端实现分析
### 3.1 API端点与示例
- `GET /knowledge-graph/graph/analyze/`（统计/聚合）
- `GET /knowledge-graph/graph/search/?q=...&type=...&page=1&page_size=20`（属性/模式搜索）
- `POST /knowledge-graph/graph/generate-tags/`（基于内容/邻接生成主题标签）
- 可补充：`GET /knowledge-graph/graph/timeline?bucket=month`（时间桶化）

### 3.2 服务层与返回Schema（建议固化）
- analysis_service：
  - 节点/关系计数：`{ total_nodes, concept_count, entity_count, note_count, total_relationships, relationship_types }`
  - 中心节点：`[{ id, name, type, degree }]`
  - 子图：`{ nodes: [{id,label,type,...}], relationships: [{id,type,start_node,end_node,...}] }`
- 建议：时间线/类型/标签聚合返回结构标准化，前端无需分支解析。

### 3.3 错误处理与缓存
- 错误分类：参数缺失/无权限/超时/内部错误；统一 `{error_code,message,details}`。
- 缓存：用户维度的聚合与时间线结果（ETag/Cache-Control），定期失效或按数据更新事件失效。

## 4. 规划一致性检查
- 目标：三大视图 + 过滤/高亮 + 统计/时间线/聚合。
- 现状：渲染/交互完备，统计/聚合接口缺少统一 Schema 与时间线桶化。
- 影响：前端需要额外适配，性能优化滞后于大图要求。
