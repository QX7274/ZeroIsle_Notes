# 手动编辑完整性分析报告

## 1. 功能概述
- 定位：面向用户的“节点/关系”手动维护能力，覆盖创建、编辑、删除、类型管理、属性编辑与批量操作。
- 场景：整理专题知识时人为补充概念、修正自动抽取错误、定义规范化的关系类型与属性模板。
- 关联：自动构建（共存并可复核）、可视化（所见即所得编辑）、查询（验证结果）、同步（Mongo→Neo4j镜像）。

## 2. 前端实现分析
### 2.1 UI组件（需核对）
- 组件目录：`src/components/knowledge/`
  - `NodeEditor.js`（节点表单/属性编辑）
  - `EdgeEditor.js`（关系表单/属性编辑）
  - `GraphVisualization.js`（选中/拖拽/缩放/点击/长按触发编辑）
  - `GraphToolbar.js`、`GraphControlPanel.js`（工具与过滤）
  - `KnowledgeGraph.js`、`KnowledgeGraphBuilder.js`（容器/流程）
- 屏幕：`src/screens/knowledge/`
  - `KnowledgeGraphScreen.js`、`KnowledgeNodeEditScreen.js`、`EdgeEditScreen.js`
- 交互流程（建议与现有逻辑对齐）：
  1) 选中节点/边 → 打开编辑器（侧栏/弹窗）；
  2) 输入校验 → 保存（本地/远端）→ 成功提示与列表更新；
  3) 支持撤销/重做（本地草稿、脏检查）；
  4) 批量选择→批量删除/类型变更/属性填充。
- 状态管理：
  - Redux/Context 保存当前选中元素、临时表单状态、未保存更改计数；
  - 与 Realm 本地模型联动（`KnowledgeNode/Edge/Graph`）。
- UI一致性：
  - 按主题 colors/typography/spacing；按钮圆角/阴影与知识模块其它组件一致；
  - 表单校验、禁用态、错误态提示风格统一。

## 3. 后端实现分析
### 3.1 API端点（urls: `backend/knowledge_graph/urls.py`）
- REST资源：
  - `/knowledge-graph/nodes/`（ViewSet）
  - `/knowledge-graph/edges/`（ViewSet）
- Mongo变体：
  - `/knowledge-graph/mongo/nodes|edges|graphs/`（MongoViewSets）
- 需要核对的操作：分页/排序/过滤参数白名单、最大页大小限制、鉴权（IsAuthenticated + 属主校验）。

### 3.2 数据模型（`backend/knowledge_graph/mongodb_models.py`）
- KnowledgeNode：id(UUID), user(Ref), title, description, type(choices: note/tag/category/concept/entity/...), note(Ref), 坐标/颜色/尺寸/icon、properties、is_public、timestamps；索引：user/type/title/is_public/created/updated。
- KnowledgeEdge：id(UUID), user, source(node), target(node), type(choices: related/cause/include/.../custom), label, description, weight, color, properties, is_public, timestamps；保存时校验 source!=target；索引：user/source/target/type/...
- KnowledgeGraph：id(UUID), user, name, description, nodes[], edges[], settings, thumbnail, is_public, timestamps；node_count/edge_count 由列表长度推算。

### 3.3 业务与边界
- 并发控制：建议使用乐观锁（If-Match/ETag 或 updated_at 对比）；
- 约束校验：
  - 边创建前校验节点存在且属同一用户；
  - 禁止自环/非法类型；
  - 节点删除需级联处理相关边（或返回冲突清单用于确认）。
- 权限/审计：
  - 属主/协作成员权限（读/写）；
  - 操作审计日志（谁在何时修改了什么）。
- 性能：
  - 批量写入接口（bulk）用于大量编辑；
  - 常见查询建立复合索引（user+type、user+source/target）。

### 3.4 错误处理
- 分类：400（校验失败）、403（无权限）、404（不存在/属主不匹配）、409（并发冲突）、429（限流）、5xx（内部/存储层）。
- 返回结构：统一 `{error_code, message, details}`；前端按 code 显示可读提示。

## 6. 问题清单
### 高优先级
- 缺少并发控制（ETag/版本号）与 bulk 编辑接口；
- 节点删除的边级联策略需明确（软删/硬删/保护）。

### 中优先级
- 类型管理的前端表单/后端模板化Schema；
- 批量选择/编辑的UI与权限检查。

### 低优先级
- 自定义校验规则与提示多语言化；
- 关系可视化的模板化样式（按 type 自动配色/箭头）。

## 7. UI统一性检查
- 标题/正文字号、主辅色、间距（8/12/16）是否一致；
- 表单输入态/禁用态/错误态风格统一；
- 弹窗圆角/阴影与全站一致。

## 8. 改进建议
- 后端：补充 bulk 接口、ETag/updated_at 并发控制、审计日志、软删策略；
- 前端：提供类型模板管理UI、批量编辑、未保存提醒与撤销；
- 性能：批量写与复合索引；
- 契约：固定错误码与响应Schema。
