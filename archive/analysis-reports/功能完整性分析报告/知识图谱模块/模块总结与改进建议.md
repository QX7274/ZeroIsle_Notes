# 知识图谱模块 - 模块总结与改进建议

本总结基于“图谱构建（自动/手动）/多维视图/节点分析/图谱查询/关系推理/可视化引擎/导入导出”七大子功能的完整性审查。整体架构清晰，端到端链路基本具备；主要改进集中在“契约统一、任务可观测、性能阈值策略、导入导出与推理标准化”。

## 一、总体评估
- 功能覆盖：8.5/10（构建、查询、分析齐备；导入导出与推理需补齐统一接口与Schema）
- 代码质量：8/10（服务分层合理；少量新旧模式与返回结构未统一）
- 契约一致性：8/10（REST + Mongo变体 + Neo4j 查询并存，需固化输入/输出Schema与错误码）
- UI一致性：8.5/10（主题/控件一致；需补视图模式、进度/报表UI）
- 错误处理：8/10（建议统一错误分类、重试/熔断、状态追踪）
- 性能优化：8/10（批量/索引具备；大图渲染阈值与聚合、GDS缓存待完善）
- 文档完善度：8.5/10（代码文档较全；需新增IO映射、推理证据Schema、DSL说明）

## 二、关键问题分级
### 🔴 高优先级
1) 构建任务“可观测性”不足：缺任务ID/状态查询/结果报表接口（前端无统一进度UI）。
2) 关系推理“候选边”接口与证据Schema未固化：无法批量采纳/忽略并记录。
3) 查询与分析结果Schema未统一：前端需多分支解析；缺分页/排序白名单与上限保护。
4) 大图可视化阈值/聚合策略缺失：>1k节点时可能掉帧，影响可用性。

### 🟡 中优先级
5) Mongo ↔ Neo4j 镜像一致性与延迟未定义：分析/查询依赖图数据库，需保证写入后的一致性策略。
6) 导入导出端点缺失：标准格式（RDF/JSON-LD/CSV/GraphML）未落地，幂等与回滚策略未实现。
7) GDS（PageRank/Betweenness/Louvain）未统一封装：指标面板与缓存策略未建立。

### 🟢 低优先级
8) 视图模式（主题/时间线/关联度）的预设/分享能力缺失。
9) 错误码与日志追踪规范化（审计/告警/慢查询记录）待完善。

## 三、两阶段路线图（2~4周）
### 第1阶段（第1~2周）：契约统一 + 可观测 + 阈值策略
- 后端
  - /auto/build-* 任务化：`POST /auto/build-graph` → 返回 `{task_id}`；`GET /auto/build-status/<task_id>` 返回 `{status, progress, stats, errors}`。
  - /graph/search、/graph/analyze、/nodes/* 返回Schema固化（分页/排序白名单、上限），统一错误 `{error_code,message,details}`。
  - /auto/suggest-edges：返回候选边 `[{source,target,type,confidence,evidence[]}]`；/auto/accept-suggestions、/auto/ignore-suggestions（批量）。
- 前端
  - 构建面板：范围/参数、进度条、统计卡、错误明细、增量子图跳转。
  - 查询面板：结构化表单 + 结果列表 + “在图中高亮”。
  - 可视化阈值策略：>1k 节点聚合、隐藏孤点、标签延迟、边抽样；布局预计算接入。

### 第2阶段（第3~4周）：IO与分析增强 + WebGL
- 后端
  - IO端点：`POST /io/import`（multipart + 映射 + dry-run）、`POST /io/export`（异步）与 `GET /io/*-status/<task_id>`；
  - GDS 封装 `/graph/metrics`：PageRank/Betweenness/Louvain，用户维度缓存；
  - 时间线桶化、类型/标签聚合接口；导出（csv/json/rdf/jsonld/graphml）。
- 前端
  - 导入向导（映射/预览/校验/执行/结果）与导出面板；
  - 分析面板：指标卡片/盲点清单；
  - WebView + WebGL（Cytoscape.js/Sigma.js）渲染通道（>2k 节点）。

## 四、验收标准（建议）
- 构建：1万笔记增量构建 ≤ 5 分钟；重复构建无重复节点/边；任务状态可观测。
- 查询：P95 ≤ 300ms（缓存命中）/ ≤ 1.5s（冷）；分页/排序白名单生效。
- 可视化：>2k 节点采用聚合/抽样情况下交互 ≥ 50fps；导出 PNG/SVG 成功率 100%。
- 推理：候选边 Top@K 采样准确率 ≥ 70%，证据可视化可用；可批量采纳/忽略。
- IO：10万行CSV分块导入成功率 100%；错误明细可下载；导出多格式可用。
- 分析：GDS 指标缓存命中率 ≥ 80%；指标页面加载 ≤ 500ms。

## 五、实现建议与接口草案
- 任务状态机（构建/导入/导出）
  - 状态：pending/running/success/failed/partial；
  - 结果：`{stats:{nodes_added,edges_added,skipped,conflicts}, errors:[{line,msg}]}`。
- 候选边 Schema
  - `[{ source, target, type, confidence:0..1, evidence:[{type:'cooccurrence|path|semantic|rule', score, detail}] }]`
- 搜索DSL（结构化）
  - `filter:{ node:{type:['concept'], created_at:{gte:'2025-01-01'}}, edge:{type:['related'], weight:{gte:0.5}} }`
- 错误码规范（示例）
  - `KG_400_INVALID_PARAM`, `KG_403_FORBIDDEN`, `KG_404_NOT_FOUND`, `KG_409_CONFLICT`, `KG_422_UNPROCESSABLE`, `KG_429_RATE_LIMIT`, `KG_500_INTERNAL`。

## 六、风险与缓解
- 大图性能风险：启用阈值策略 + WebGL 渲染 + 后端预计算布局；
- 一致性风险（Mongo↔Neo4j）：事件驱动镜像队列 + 失败补偿与重试日志；
- 推理误报风险：人机协同（批量忽略/采纳）、阈值调优、A/B 与离线评估样本集。
