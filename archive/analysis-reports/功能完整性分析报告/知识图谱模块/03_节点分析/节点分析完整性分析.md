# 节点分析完整性分析报告

## 1. 功能概述
- 定位：对知识图谱中节点进行结构性与语义性分析，包括中心度、重要性、相似度、盲点识别等，用于发现核心概念、薄弱环节与学习路径。
- 场景：
  - 找出关键知识点（高中心度）；
  - 识别知识空白（孤点/低度/无入出边）；
  - 相似节点聚类（合并冗余/创建上位概念）。
- 关联：与“图谱查询（子图/路径）”“关系推理（潜在连接）”“多维视图（关联度高亮）”联动。

## 2. 前端实现分析
### 2.1 UI与组件（建议/需核对）
- 位置：
  - `src/screens/knowledge/AnalysisTab.js`、`KnowledgeAnalysisScreen.js`
  - `src/components/knowledge/StructureAnalysis.js`（若作为分析面板）

- UI一致性：
  - 指标卡片/表格样式与主题统一；空态/加载态提示符合全局规范。

### 2.2 问题清单（前端）

## 3. 后端实现分析
### 3.1 端点与服务
- `backend/knowledge_graph/urls.py`
  - `GET /knowledge-graph/graph/analyze/`（总览/统计）
  - `POST /knowledge-graph/graph/find-path/`（最短路径）
- `backend/knowledge_graph/services/analysis_service.py`
  - `get_node_statistics(user_id)`：节点类型与计数
  - `get_relationship_statistics(user_id)`：关系类型与计数
  - `get_central_nodes(user_id, limit)`：按度数排序（可扩展 GDS PageRank/Betweenness）
  - `get_path_between_nodes(start,end,user_id,max_depth)`：最短路径
  - `get_subgraph(node_id,user_id,depth)`：子图
- `backend/knowledge_graph/services/neo4j_service.py`：执行 Cypher；可扩展 GDS。

### 3.2 模型与数据准备
- 节点/边在 Mongo 与 Neo4j 的镜像策略（需确认）：
  - 现状偏重 Neo4j 查询分析；
  - 建议：构建/CRUD后触发镜像任务以供图算法使用。

### 3.3 错误处理与边界
- 参数校验：`limit/max_depth/depth` 应设定上限与默认值；
- 无结果：返回空集合而非500；
- 超时与熔断：长路径或大子图需限制。

### 3.4 性能
- 预计算与缓存：
  - 统计与TopK中心节点按用户维度缓存；
  - 子图请求频繁时加ETag/短期缓存。
- GDS（Graph Data Science）：
  - 建议接入 PageRank/Betweenness/Louvain 等，离线计算+缓存。

## 4. 规划一致性检查

## 6. 问题清单
### 高优先级
- GDS算法未统一封装与缓存策略；
- 镜像一致性（Mongo→Neo4j）与延迟未定义；
- 子图/路径参数缺上限（潜在重查询风险）。

### 中优先级

- 指标卡片导出/分享。
