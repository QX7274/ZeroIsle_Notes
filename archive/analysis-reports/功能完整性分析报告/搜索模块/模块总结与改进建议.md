# 搜索模块 - 模块总结与改进建议

## 总体评估
- 功能覆盖：8.5/10（全文/语义/建议与历史基本完备）
- 代码质量：8.5/10（向量器单例/持久化、统一到 MongoEngine）
- 契约一致性：8/10（融合排序/分页与白名单/错误码仍需固化）
- UI一致性：8.5/10（主题已统一，高亮与过滤器需二次核对）
- 错误处理：8.5/10（参数校验与上限良好，限流/429 提示待完善）
- 性能优化：8.5/10（预筛+TopK，有待补充缓存策略）
- 文档完善度：8.5/10（增强文档充分，需补融合排序与多语言分词说明）

## 关键问题（分级）
### 高优先级
1) 融合排序权重与阈值未配置化；
2) 分页/排序/过滤白名单与上限需统一到契约与文档；
3) 限流与缓存（热词/结果集）策略缺少落地说明。

### 中优先级
4) 中文/多语言分词器选择与一致性；
5) 命中高亮统一 renderer；
6) 建议与历史的脱敏与GDPR 删除入口。

### 低优先级
7) 搜索短语（Search phrase）→ 预定义查询语句的配置；
8) 聚合项（类型/标签/时间）UI 与API一致性增强。

## 改进建议
- 后端：
  - 融合排序参数配置化 + A/B；
  - 分页/排序/过滤白名单、上限统一；
  - 限流 + 热点缓存（热门 query/结果）；
- 前端：
  - 输入取消上一次请求、统一 429 提示；
  - 高亮 renderer 与过滤器 UI 统一；
- 文档：
  - 多语言分词与融合排序说明，错误码表。

## 验收标准
- P95 查询延迟 ≤ 300ms（缓存命中）/ ≤ 1.5s（冷）；
- 融合排序权重可调并可灰度；
- 429 告警与提示清晰；
- GDPR 删除可在 24h 生效并可审计。
