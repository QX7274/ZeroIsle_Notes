# 搜索模块（Search）完整性分析总览

## 1. 模块职责与边界
- 职责：为笔记/知识/附件等内容提供全文检索、语义（向量）检索、搜索建议与历史记录、统一的过滤/排序/分页与安全限流策略。
- 边界：
  - 输入：索引构建（内容/元数据/向量）、用户查询（关键词/语义/结构化过滤）。
  - 输出：排序后的结果集（分页）、建议词、历史记录统计与分析。
- 依赖：
  - 前端：`src/components/search/*`、`src/screens/search/*`、`src/services/search/*`、`src/tests/test_search_api.js`、`src/components/search/SearchResults.js`
  - 后端：`backend/search/*`（models|services|views|urls|serializers|tests）
  - 其他：`backend/knowledge_graph/services/vector_service.py`（若存在向量支持，见 README_ENHANCED）、`backend/common/*`

## 2. 数据流与交互
1) 索引构建：内容变更 → indexer_service（分词/字段抽取/向量化）→ 保存倒排/向量索引（Mongo/文件/ES）。
2) 查询请求：前端 query + filters + sort → `backend/search/views/*` → service 合并召回（关键词+向量）→ 排序融合 → 返回分页结果。
3) 搜索建议/历史：query keystroke → 提示建议；成功查询写入历史 → 用于个性化与热词。

## 3. 关键端点与文件
- 前端
  - 组件：`src/components/search/SearchResults.js`（主题修复历史）、`src/screens/search/*`（Search入口与结果页）
  - 服务：`src/services/search/*`（API封装、结果处理）
  - 配置：`src/config/api.js`（`API_ENDPOINTS.SEARCH.*`）
- 后端
  - URLs：`backend/search/urls.py`（`/search/text`, `/search/semantic`, `/search/suggestions`, `/search/history`, `/search/clear-history`, `/search/knowledge-graph` 等）
  - 服务：`backend/search/services/indexer_service.py`, `search_service.py`, `vector_service.py`（向量器单例/持久化/维度检查）
  - 模型：`backend/search/mongodb_models.py`（索引记录/历史/热词），`backend/search/README_ENHANCED.md`
  - 测试：`backend/tests/test_enhanced_search.py`、`backend/search/tests/*`

## 4. 风险与技术债（摘录）
- 全文/向量的“融合排序”契约未固化；
- 建议/历史的速率限制与脱敏策略需明确；
- 筛选/排序白名单与分页上限统一性。
