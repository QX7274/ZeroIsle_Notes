## 任务2: 统一API错误码和返回格式

### 问题分析
当前返回格式混乱：
- 有的返回 `{error: '...'}`
- 有的返回 `{detail: '...'}`
- 有的返回 `{message: '...'}`
- 有的返回 `{result: '...'}`

### 修复方案

#### 步骤1: 创建 backend/common/api_response.py
```python
from rest_framework.response import Response
from rest_framework import status

class APIResponse:
    @staticmethod
    def success(data=None, message='success', code=0):
        return Response({
            'code': code,
            'message': message,
            'data': data
        })
    
    @staticmethod
    def error(message, code=500, status_code=status.HTTP_400_BAD_REQUEST):
        return Response({
            'code': code,
            'message': message,
            'data': None
        }, status=status_code)
```

#### 步骤2: 创建 backend/common/error_codes.py
```python
# 认证/授权错误
UNAUTHORIZED = 1001
FORBIDDEN = 1002

# 资源错误
NOT_FOUND = 2001
CONFLICT = 2002

# 业务逻辑错误
INVALID_INPUT = 3001
OPERATION_FAILED = 3002

# 服务器错误
INTERNAL_ERROR = 5000
```

## 任务3: 修复Token刷新失败的安全问题

### 问题分析
当JWT刷新令牌失败时，系统未强制用户登出，可能导致：
- 使用过期Token继续操作
- 安全令牌泄露风险

### 修复方案

#### 后端修复
1. 创建 `backend/users/models.py` 中的TokenBlacklist模型
2. 在登出时将Token加入黑名单
3. 在中间件中检查黑名单

#### 前端修复
1. 在 `src/services/api/apiClient.js` 中处理刷新失败
2. 刷新失败时调用强制登出
3. 清除所有本地存储

### 验收标准
- ✅ Token刷新失败时自动强制登出
- ✅ 登出后旧Token无法继续使用
- ✅ 黑名单机制正常工作
