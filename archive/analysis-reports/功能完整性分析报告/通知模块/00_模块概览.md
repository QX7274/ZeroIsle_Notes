# 通知模块（Notification）完整性分析总览

## 1. 模块职责与边界
- 职责：为业务事件（提醒到期、评论回复、群组事件、导入导出状态、分析导出等）提供本地通知与远端推送，管理通知偏好（订阅/静音/渠道/重要级别），维护既读/未读与清理归档的一致性。
- 边界：
  - 输入：业务侧事件（reminder/community/notes/io/analytics…）、用户偏好设置；
  - 输出：系统/推送通知、既读状态、聚合计数、指标与审计。
- 依赖：
  - 前端：`src/services/notification/*`, `src/native/NotificationChannelModule.js`, 各业务模块的触达入口；
  - 后端：`backend/notification/*`（`mongodb_models.py|serializers.py|views.py|urls.py|signals.py`），`backend/common/*`；
  - 文档：`backend/ENHANCED_FEATURES_SUMMARY.md`、相关模块分析文档（提醒/社区/导入导出）。

## 2. 数据流
1) 业务事件 → 通知服务（合并/去重/模板渲染）→ 触达（本地/远端）→ 用户点击/忽略 → 既读回写；
2) 偏好更新 → 存储用户订阅/静音设置 → 影响后续触达；
3) 清理：过期/已读批量归档或删除 → 统计与审计。

## 3. 关键端点与文件
- 后端 URLs：`backend/notification/urls.py`（`/notifications/`, `/notifications/{id}/`, `/notifications/unread_count/`, `/notifications/mark_all_as_read/` 等）
- 后端模型/服务：`backend/notification/mongodb_models.py`, `backend/notification/services.py`, `backend/notification/signals.py`, `backend/notification/views.py`
- 前端：`src/services/notification/*`, `src/native/NotificationChannelModule.js`

## 4. 风险与技术债
- 去重与聚合策略（短时间多事件风暴）；
- 本地/远端双通道重复触达与去重；
- 既读一致性（多端同步）、批量清理与性能；
- 渠道与重要级别的跨平台差异。
