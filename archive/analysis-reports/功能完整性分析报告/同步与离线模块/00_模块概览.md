# 同步与离线模块（Sync/Realm/MongoDB）完整性分析总览

## 1. 模块职责与边界
- 职责：在离线优先架构下，提供本地Realm与远端MongoDB的数据双写/同步、冲突解决、增量与版本控制、连接与安全、可观测性与重试等能力。
- 边界：
  - 输入：前端本地写入/变更事件、后端数据变更、外部导入任务；
  - 输出：本地与远端一致的数据、冲突解决结果、同步状态与日志。
- 依赖：
  - 前端：`src/services/database/realmService.js`、`src/utils/realmStorage.js`、`src/services/sync/*`（`syncManager.js`, `syncService.js`, `syncEvents.js`, `syncUtils.js`）
  - 后端：`backend/sync/services/mongodb_service.py`、`backend/sync/services/sync_service.py`、`backend/sync/views.py`、`backend/sync/urls.py`、`backend/sync/signals.py`
  - 相关：`backend/mongodb_service.py`、`backend/realm_service.py`、`docs/offline-sync.md`、`docs/realm_setup.md`、`backend/QUICK_START_GUIDE.md`

## 2. 数据流与协议
1) 本地写入（Realm）→ 记录变更（local change set）→ syncService（前端）排队 → 调后端 /sync/* → 后端批量 upsert（ObjectId统一/时间戳统一）→ 回传结果 → 标记已同步。
2) 后端下行 → 查询服务端更新（updated_at > last_sync_at）→ 增量合并到本地 → 触发索引/图谱。
3) 冲突解决 → server/client/latest 策略（代码参考 `backend/sync/services/sync_service.py`）。

## 3. 关键代码与端点
- 前端
  - `src/services/sync/syncManager.js`（同步调度/周期/事件订阅）
  - `src/services/sync/syncService.js`（上传/下载/合并/标记）
  - `src/services/database/realmService.js`、`src/utils/realmStorage.js`（本地数据访问）
- 后端
  - `backend/sync/services/mongodb_service.py`（安全连接、TLS、单例、批量写、ObjectId 统一）
  - `backend/sync/services/sync_service.py`（冲突策略、版本控制、批量 upsert、结果统计）
  - `backend/sync/urls.py`、`backend/sync/views.py`（REST端点，如 `/sync/push`, `/sync/pull` 等——需确认）
  - 支撑：`backend/common/utils.py`（上传校验）、`backend/backend/settings.py`（连接配置）

## 4. 风险与技术债（摘录）
- 端到端任务“可观测性”不足（task_id/状态端点/统计页面）；
- 本地变更集的幂等/回放与失败补偿策略待明确；
- ObjectId、时间戳统一与时区一致性容易出错；
- 限流与指数退避策略、慢同步报警。
