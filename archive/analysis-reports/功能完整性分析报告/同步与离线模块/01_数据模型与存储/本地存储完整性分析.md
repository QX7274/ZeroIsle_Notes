# 本地存储完整性分析报告（Realm Schema/索引/容量）

## 1. 功能概述
- 定位：移动端离线优先的数据承载层，基于 Realm 存储笔记、知识图谱、设置、同步队列等数据，支持快速查询与本地事务。
- 场景：离线编辑/浏览、开机快速恢复、批量操作的本地落盘；作为与远端 MongoDB 同步的前置缓冲层。
- 模块关联：笔记管理、知识图谱、搜索索引缓存、同步与离线、通知与提醒。

## 2. 前端实现分析
- 关键路径：
  - Realm 封装：`src/services/database/realmService.js`, `src/utils/realmStorage.js`
  - 模型（示例）：`src/models/KnowledgeGraph.js`, `src/models/Note.js`, `src/models/*`
  - Schema：`src/schemas/*.js`（`noteSchema.js`, `knowledgeNodeSchema.js`, `knowledgeEdgeSchema.js` 等）
- 交互与数据流：
  - 读写通过 realmService 统一封装，保证写事务一致性；
  - 上层服务（notes/knowledge/…）依赖 realmService；
  - 同步模块监听本地变更，形成 change set 上传。
- 主题一致性：不适用（数据层）。
- 问题清单（前端）
  - 需确认：所有强一致对象均有 primaryKey，并与远端 id/ObjectId 对齐；
  - 需确认：`is_deleted/is_synced/updated_at` 等同步标记字段在各 Schema 的一致性；
  - 需确认：容量上限与清理策略（历史/垃圾回收）。

## 3. 后端实现分析（配合）
- 端点/服务：`backend/sync/services/mongodb_service.py`、`backend/sync/services/sync_service.py`
  - 统一 ObjectId/时间戳；批量 upsert；冲突策略；
- 模型：MongoEngine 文档（例如 `backend/notes/mongodb_models.py`, `backend/knowledge_graph/mongodb_models.py`）与 Realm 模型字段映射需一致。
- 边界：
  - 时区/时间戳与服务器端统一（UTC + tz-aware）；
  - 字段类型与枚举（如节点类型）一致；
  - 软删除（is_deleted）与索引策略。

## 4. 规划一致性检查
- 文档：`docs/realm_setup.md`, `docs/offline-sync.md`
- 偏差：若部分 Schema 缺少同步标记字段或主键/类型不一致，将导致增量同步异常。
