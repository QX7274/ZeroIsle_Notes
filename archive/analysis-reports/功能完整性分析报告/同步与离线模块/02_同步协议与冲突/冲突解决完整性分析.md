# 冲突解决完整性分析报告（server/client/latest 策略）

## 1. 功能概述
- 定位：前端本地变更与远端数据在同步过程中产生冲突时的处理策略与落地实现，确保数据一致性、可追溯与可恢复。
- 场景：离线编辑后回连、多人多端并发编辑、导入批量变更与后端更新交错。
- 关联：增量同步与版本控制、可观测（冲突统计与审计）、通知（冲突提示）。

## 2. 前端实现分析
- 关键路径：`src/services/sync/syncManager.js`（调度）、`src/services/sync/syncService.js`（push/pull/merge）、`src/services/sync/syncUtils.js`（工具）、`src/services/sync/syncEvents.js`（事件）
- 交互：
  - 冲突发生 → 选择策略（默认/按模型）→ 合并或覆盖 → 本地标记与日志；
  - 用户提示：Toast/对话框（需统一文案），冲突详情可视化（建议）
- 状态管理：
  - 变更队列：每条变更包含 `model, id, updated_at, version`；
  - 冲突结果缓存：供后续分析与回滚；
- 问题清单（前端）：
  - 需确认：是否允许用户在 UI 上选择策略；
  - 需确认：冲突详情（本地值/远端值/合并值）是否可视化；

## 3. 后端实现分析
- 关键文件：`backend/sync/services/sync_service.py`
  - 已实现：server/client/latest 3种策略、版本控制、批量写（bulk_write）与结果统计；
  - 统一 ObjectId 与时间戳；
- 端点：`backend/sync/urls.py`、`views.py`（需确认具体 push/pull 路径）；
- 业务边界：
  - 粒度：按文档 vs 按字段合并（当前多为文档级策略，字段级合并需扩展）；
  - 日志：冲突详情、合并规则、责任人（操作者）与时间；
  - 审计：保留冲突样本若干天；

## 4. 规划一致性检查
- 文档：`docs/offline-sync.md`、`模块功能核查与优化记录/【同步模块】*`
