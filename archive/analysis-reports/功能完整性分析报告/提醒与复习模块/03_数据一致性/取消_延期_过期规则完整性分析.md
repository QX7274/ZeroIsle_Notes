# 取消/延期/过期规则完整性分析报告

## 1. 功能概述
- 定位：保证提醒从“planned→due→done/cancelled/overdue→rescheduled”的状态机正确运转，支持延期（snooze）、取消（cancel）、过期（overdue）以及统计口径一致。
- 场景：用户在接收到提醒后选择“稍后提醒/明天/自定义时间”、取消本次/全部重复、过期任务自动入“逾期”。
- 关联：计划与重复（下一次生成）、通知与执行（触发/回执）、同步与离线（本地→远端一致）。

## 2. 前端实现分析
- 路径：
  - 组件：`src/components/reminder/*`（提醒卡片/操作按钮）
  - 屏幕：`src/screens/reminder/*`
  - 服务：`src/services/reminder/*`, `src/services/notification/*`
- 交互：
  - 在通知/列表项提供“完成/延期/取消”；延期提供常用快捷（+10m/+1h/次日9点）与自定义；
  - 重复提醒：仅本次 or 所有后续（需确认UI）；
- 状态：
  - 本地 Realm 更新 `status` 与 `scheduled_time`（延期），打 `is_synced=false` 等待同步；
- 主题：按钮与对话框风格一致；过期标记颜色/角标统一。
- 问题清单：
  - 需确认：列表中“过期组”与“延期组”的展示；
  - 需确认：重复提醒“仅本次/全部”的 UX 流程。

## 3. 后端实现分析
- 端点（建议）：
  - `POST /reminder/reminders/{id}/complete/`、`/cancel/`、`/snooze/`（延期，body 包含新 `scheduled_time` 与 reason）
  - 列表：`/reminder/today/`, `/upcoming/`, `/overdue/`
- 模型：`backend/reminder/mongodb_models.py`
  - 字段：`status in {planned, done, cancelled, overdue}`, `scheduled_time`, `repeat_rule`, `repeat_end_date`, `snooze_count`, `priority`；
  - 约束：完成/取消/延期时更新 `updated_at` 与统计；
- 业务：
  - 过期判定：以服务器时间为准（时区统一）；
  - 延期：若为重复项，仅影响当前“实例”（生成 occurrence 概念或存储“例外”）；
  - 统计：按天/周统计完成率、过期率、平均延期次数；
- 问题清单：
  - Instance/Exception 模型是否已实现（重复提醒的例外处理）；
  - 过期判定是否考虑夏令时；
  - 并发操作（多端同时延期/取消）的乐观锁与冲突处理。
