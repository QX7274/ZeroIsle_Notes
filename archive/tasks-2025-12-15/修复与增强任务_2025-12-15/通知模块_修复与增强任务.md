# 通知模块 — 修复与增强任务（P1）

依据：
- 功能完整性分析报告/通知模块
- 模块功能核查与优化记录/【通知功能】【通知模块】
- 代码核查：backend/notification/services.py、notification/views.py、users/settings 偏好

关键问题与修复方向：
1) 去重与合并策略落地（高）
- 现状：NotificationService.create_notification 已支持在一定窗口内合并/去重（MERGEABLE_TYPES like/follow）。
- 任务：
  - 将 MERGEABLE_TYPES、窗口秒数 dedupe_seconds 参数化（env/DB 配置）。
  - 合并后的计数、发送者列表序列化在 API 输出中体现；前端聚合展示。

2) 调度能力与 Celery 任务（高）
- 现状：schedule_notification 依赖 common.tasks Celery 任务 send_notification；仓库未确认该任务存在。
- 任务：
  - 若缺失：新增 Celery app 与 send_notification 任务；
  - schedule_notification 增强：
    - 校验 scheduled_time 必须为 timezone-aware 且晚于当前；
    - 失败返回结构化错误码；

3) 用户偏好联动（中）
- 现状：用户偏好由 users.services.user_settings_service 读取；
- 任务：
  - 对应 API：读取/更新用户通知偏好；
  - create_notification/schedule_notification 严格尊重偏好（push/email）；

4) API 与分页（中）
- 任务：
  - 新增/完善：获取未读数量、列表分页、批量已读、批量删除；
  - 列表过滤：按类型/已读；

5) 审计与幂等（中）
- 任务：
  - 幂等键（用户+类型+对象+窗口）避免重复创建；
  - create_notification 与 schedule_notification 写审计日志（common.services.audit_service）。

实施改动点：
- backend/notification/services.py：
  - 参数化 MERGEABLE_TYPES/dedupe_seconds；
  - schedule_notification 增强（校验/错误结构化返回）；
- backend/notification/views.py：
  - 新增批量已读/删除端点；
  - 输出字段包含 merged_count/merged_senders；
- Celery：
  - common/tasks.py 定义 send_notification；部署说明（worker/beat）。

验收标准：
- 去重与合并生效且可配置；
- 定时通知按期触发，失败有可诊断错误；
- API 分页/过滤可用；
- 单测：去重/合并、定时调度、偏好生效、幂等。

工期：0.5 天；风险：Celery 部署与时区问题。
