# 【社区功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：社区功能（帖子/评论/点赞/关注/通知）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/community/views/post.py（PostViewSet：列表/检索/创建/更新/删除/推荐/热门/点赞/关注）
  - backend/community/views/comment.py（CommentViewSet：列表/创建/更新/删除/点赞/回复/按帖子查询/我的评论）
  - backend/community/views/like.py（LikeViewSet：我的点赞/切换点赞/按对象查询）
  - backend/community/services/*.py（post/comment/like/follow/notification 业务逻辑）
  - backend/community/mongodb_models.py（Post/Comment/Like/Follow 等文档模型）
  - backend/community/serializers/*.py（序列化器）

## 2. 功能实现结论
- 结论：基本可用（核心发帖/浏览/检索/评论/点赞/关注/分页），但在内容安全、权限与范围、富交互、推荐与排序策略、媒体处理、审计与风控、性能与索引等方面需要增强。

### 2.1 已实现能力（功能面）
- 帖子 Post
  - 列表：支持 filterset（category/status/is_pinned/is_featured/is_public）、search（title/content/excerpt）、ordering（created/published/view/like/comment），分页；
  - 权限：本人所有状态可见；他人仅“公开且已发布”；
  - 详情：非公开仅作者可见；自动 view_count++；
  - 创建：支持 multipart（封面、多个附件元信息+文件）与 JSON 两种路径；自动 excerpt；published 状态设置 published_at；
  - 更新/删除：作者可更新/软删；
  - 扩展：featured、popular、my 筛选；like（切换计数）、follow（关注作者）。
- 评论 Comment
  - 列表/详情/创建/更新/删除（软删）；
  - 点赞切换；
  - 回复列表（分页）；
  - 按帖子取顶级评论（分页），我的评论（分页）。
- 点赞 Like
  - 通用切换接口（Post/Comment/User）；
  - 我的点赞、按对象取点赞（分页）。

### 2.2 关键缺陷/缺失（功能可用性与安全）
1) 内容与媒体安全
- 富文本/内容未进行 HTML 白名单/XSS 清洗；
- 封面/附件文件缺类型白名单、大小上限、杀毒扫描、路径/文件名安全（当前直接保存到 MEDIA，文件名原样写入，可能覆盖或注入）；
- 附件元信息未严格校验（size/type/name 信任客户端）。

2) 权限与范围
- 仅“本人/公开”，缺组织/群组/粉丝可见等范围；
- 评论接口未校验“帖子是否允许评论/是否公开”；
- 关注作者 follow 未做隐私/拉黑/双向关系等策略；

3) 互动与体验
- 点赞/关注未防重复并发（竞态可能导致计数不准）；
- 缺收藏/转发/举报/屏蔽/置顶评论等；
- 缺富文本编辑（安全白名单）、话题/提及 @user、表情、图片/视频预处理；

4) 推荐与排序
- popular/featured 仅基于静态字段与简单排序，缺热度算法（时间衰减/加权）；

5) 审计与风控
- 无敏感词/垃圾检测（频率/相似内容/黑名单）；
- 无操作审计（发布/删除/举报/封禁）；
- 点赞/关注/评论端点无节流，易被滥用；

6) 一致性与性能
- view_count/like_count 直接累加，未使用原子操作；
- 未见必要索引说明（user/is_deleted/is_public/status/created_at/published_at/tags 等）；
- 附件/封面写入本地磁盘，规模化与分布式部署不友好；

7) 国际化与可访问性
- 返回消息与错误未统一 i18n；

## 3. 具体优化建议（可落地）
1) 内容与媒体安全（P0）
- 内容清洗：后端使用 bleach/自定义白名单清洗 HTML（标题/内容/评论）；
- 文件安全：MIME 与扩展名白名单、大小上限、病毒扫描（ClamAV）与失败阻断；
- 文件存储：采用对象存储（S3/OSS），使用短时签名 URL；生成安全文件名（UUID）与目录分层；

2) 权限与范围（P0）
- 发布范围：private/followers-only/group/org/public；
- 评论策略：per-post allow_comments 严格执行（接口侧校验），可加“仅关注可评、仅作者可评”等；
- 关注/拉黑体系：拉黑用户的互动限制；

3) 互动与并发（P0）
- 点赞/关注使用原子更新（$inc/$set with filter）或事务；
- 去抖限流：同用户对同目标点赞/关注的节流；
- 收藏/举报：新增 endpoints 与流程；

4) 推荐与排序（P1）
- 热度分：score = a*likes + b*comments + c*views + d*time_decay；
- 个性化：基于关注/标签/浏览历史的推荐；

5) 风控与审计（P1）
- 端点节流：发帖/评论/点赞/关注；
- 敏感词与垃圾检测策略（规则+模型）；
- 审计日志：关键操作记录操作者、对象、IP/UA、结果；

6) 性能与索引（P1）
- 为常用查询建立索引：
  - Post: (user,is_deleted), (is_public,status,published_at), (tags), (category), (is_featured), (view_count,like_count,comment_count)
  - Comment: (post_id,parent,is_deleted,created_at), (user,is_deleted)
  - Like: (user,content_type,object_id,is_active)
- 统计字段维护使用原子操作；

7) 体验（P2）
- 编辑器增强：支持图片/视频上传与处理（压缩/转码/尺寸限制），表情、@、#话题；
- 评论置顶/折叠长评；
- 订阅通知：帖子被评/被赞/被关注通知（结合 notification 模块）。

## 4. 关键代码改造建议（片段级思路）
- 内容清洗：
  - safe_html = bleach.clean(raw_html, tags=ALLOWED_TAGS, attributes=ALLOWED_ATTRS)
- 文件名与存储：
  - filename = f"{uuid4().hex}{suffix}"; storage.upload(file, path); url = storage.sign(path, ttl=600)
- 原子点赞：
  - res = likes.update_one(filter={'user':uid,'content_type':ct,'object_id':oid}, update={'$set': {...}}, upsert=True); posts.update_one({'_id':pid}, {'$inc': {'like_count': delta}})
- 热度排序：
  - order_by = '-score'; score 预计算与定时更新
- 节流：
  - throttle_scope = 'post_create/comment_create/like_toggle/follow_toggle'

—— 建议优先落地“内容与媒体安全 + 权限范围 + 原子互动与节流 + 索引与对象存储”的 P0；随后推进推荐与审计风控、编辑器增强，全面提升社区功能的安全性、可扩展性与体验。
