# 【语音转写功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：语音转写（Voice Transcription）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/voice_recognition/services/transcription_service.py（转录主流程：创建/处理/查询）
  - backend/voice_recognition/services/whisper_service.py（Whisper 在线/离线切换与API调用）
  - 其他引擎：xunfei_asr_service.py、baidu_asr_service.py（未展开）
  - 相关模型：voice_recognition.models.AudioFile、Transcription、Language（Django ORM）

## 2. 功能实现结论
- 结论：基本可用（支持 Whisper 在线/离线模式自动切换、讯飞/百度引擎选择；具备创建转录、处理转录、获取结果的主链路），但在异步任务与进度、文件与权限、安全与限流、质量与扩展（说话人分离、时间戳、段落组织）、可靠性与审计等方面仍需加强。

### 2.1 已实现能力（功能面）
- 转录创建 create_transcription(audio_file, language_code, model, user)：
  - 支持选择语言（Language 表）、模型（whisper-1/xunfei/baidu 等），状态初始化为 pending；
- 转录处理 process_transcription(transcription_id)：
  - 将状态置为 processing；按模型分发：
    - WhisperService.transcribe(audio_path, language, model)：
      - 在线优先（OpenAI API），失败时可回退离线；支持强制模式；
      - 返回 status/text/segments/language/duration；
    - Xunfei/Baidu 服务：transcribe(audio_path, language) 调用；
  - 原子事务更新 Transcription（status/text/segments/duration/error_message）与 AudioFile.is_processed；
- 结果获取 get_transcription(transcription_id, user)：
  - 对应用户访问校验，返回记录；
- WhisperService：
  - 单例；在线/离线自动切换（根据网络与API Key）；
  - 在线 _transcribe_api 通过 HTTP 调用 OpenAI Audio API（/v1/audio/transcriptions，response_format=verbose_json）；
  - 离线 OfflineWhisperService.transcribe；
  - 失败回退策略（在线失败→离线；离线失败→在线）。

### 2.2 功能缺陷/缺失（聚焦可用性与稳定性）
1) 同步阻塞与进度
- process_transcription 为同步阻塞，无任务化/后台执行；无进度与取消/重试机制；

2) 文件处理与权限
- 依赖 audio_file.file.path 的本地路径，缺文件存在性之外的校验（大小/MIME/采样率/时长上限）；
- 未见与上传链路/清理策略的集成（临时文件生命周期、配额）；
- 跨存储（对象存储）场景未考虑（应支持URL拉取/签名下载）。

3) 安全与风控
- 无限流与配额（用户/组织/每日分钟数上限、并发数上限）；
- 无成本控制（OpenAI API 计费、第三方调用重试策略与退避、错误分级）；
- 无敏感音频/隐私合规提示与数据保留策略。

4) 质量与结构化输出
- Whisper API返回段落/时间戳、说话人分离（diarization）未整合；
- segments 字段存在但无标准schema定义（字段类型/单位/偏移）；
- 语言检测与自动语言选择未在 TranscriptionService 统一（Whisper可自动检测）。

5) 可靠性与错误处理
- 在线调用未设请求超时/重试/幂等（Whisper _transcribe_api 直接 requests.post）；
- 仅以 status='failed' + error_message 记录失败，未区分可重试/不可重试；
- 事务只覆盖DB更新，未覆盖外部调用异常的回滚/告警。

6) 审计与通知
- 无操作审计（谁/何时/耗时/长度/模型/费用估算）；
- 无通知（转写完成/失败时回调或站内通知）。

7) 与业务集成
- 与笔记/搜索/知识库未自动联动（自动创建文本笔记、入索引/知识库、可搜索性增强）；

8) 兼容性与配置
- Whisper API URL、模型、温度/段落参数未配置化；
- 离线模型大小/选择未配置化（device, fp16/int8）。

## 3. 具体优化建议（可落地）
1) 任务化与进度（P0）
- 将 process_transcription 迁移至 Celery/RQ 任务：提交→返回 task_id；提供 /status、取消、重试；
- 在任务上下文定期写入进度（queued/processing/downloading/transcribing/postprocessing/completed/failed + percent）。

2) 文件校验与输入（P0）
- 转写前校验：MIME 白名单、最大时长/大小（如 ≤ 60 分钟或 100MB，可配置）、采样率/声道数（转码至标准如16kHz单声道）；
- 支持对象存储：输入可为 URL（短签名），后端下载至临时目录；
- 统一临时文件策略（随机文件名、生命周期、清理守护）。

3) 安全、限流与配额（P0）
- 用户/组织每日/每小时配额与并发上限；
- 端点节流与冷却时间；
- 成本与重试策略：对外调用设置超时（如 60s）、重试（指数退避，最大次数），记录费用估算与失败原因。

4) 质量增强（P1）
- 统一 segments schema：[{id, start_sec, end_sec, text, confidence?}]；
- 可选 diarization（说话人分离）并在 segments 中标注 speaker；
- 自动语言检测与返回语言码；
- 后处理：标点/大小写修复、分段合并/断句，关键词/摘要抽取（可复用 Search/AI 模块）。

5) 集成与回写（P1）
- 选择“生成笔记/附件文本/知识库条目”，自动入索引（SearchIndex）与知识库；
- 完成后发送 Notification；

6) 可靠性与监控（P1）
- Whisper API：设置 requests 超时、捕获429/5xx并重试；
- 指标：任务数、成功率、P95耗时、平均时长、费用估算；
- 审计：记录 user、audio_length、model、engine、cost_estimate、result_length、错误码。

7) 配置与可移植（P1）
- 模型与API配置集中化（settings/env）：API base/key、模型、超时、离线模型路径/设备、最大并发；
- 多引擎优先级与回退顺序可配置。

## 4. 关键代码改造建议（片段）
- 任务化：
  - task_id = transcribe_task.delay(transcription_id)
  - 任务内部分阶段写入 Transcription.progress 与 stage 字段
- Whisper API 调用：
  - requests.post(url, timeout=(10, 300)); if resp.status_code in [429,5xx]: retry with backoff
- Segments 规范化：
  - segments=[{'id':i,'start_sec':s,'end_sec':e,'text':t,'speaker':spk}]
- 文件校验：
  - if duration>MAX or size>MAX or mime not allowed: return 400
- 通知：
  - NotificationService().create_notification(user, 'transcription_done', ...)

—— 建议优先落地“任务化+限流与配额+文件与超时校验+Whisper调用超时重试+segments标准化”的 P0 改造，随后推进质量增强（diarization/后处理）、业务联动与审计监控，提升在真实场景下的可用性与可靠性。
