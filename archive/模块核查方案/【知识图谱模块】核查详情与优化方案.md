# 【知识图谱模块】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：知识图谱模块（Knowledge Graph）
- 核查日期：2025-11-17
- 核心代码路径：
  - 模型：/backend/knowledge_graph/mongodb_models.py（KnowledgeNode/KnowledgeEdge/KnowledgeGraph/Concept/Entity/Relation）
  - 服务：/backend/knowledge_graph/services/knowledge_graph_builder_service.py
  - 相关服务：auto_classification_service.py、analysis_service.py 等

## 2. 核查结果
### 2.1 功能实现
- 结论：部分实现（存在“字段不匹配导致运行期错误”的关键问题）
- 已实现（代码路径存在且逻辑基本完整）：
  - 从单笔记/多笔记/整用户的图谱构建（节点：笔记/标签/分类/概念；边：has_tag/belongs_to/mentions/related_to/has_subcategory）
  - 基于提取概念与相似笔记的边生成；
  - 关联分析（analyze_note_connections）：出/入边聚合并按相似度或权重排序；
  - 内容推荐（suggest_related_content）：依据概念节点关联推荐相关笔记和“推荐标签”。
- 未实现/缺陷：
  1) 模型与服务字段不一致（致命）：
     - 服务中多处使用 is_deleted=False 过滤节点/边（如 build_graph_for_user 第178-180行、analyze_note_connections 第211、233、239行、_get_or_create_* 查询等），但 KnowledgeNode/KnowledgeEdge 模型并无 is_deleted 字段；
     - 结果：运行期查询会抛出字段不存在或条件无效的错误，整体功能不可用。
  2) “重复/幂等”保证不足：
     - 边的去重仅按(user, source, target, type)＋is_deleted过滤；若属性不同（weight/similarity）不会创建重复，但更新属性采用覆盖合并，缺少幂等策略说明；
     - 节点的去重依赖 properties__{id}（如note_id/tag_id/category_id）或(title,type)组合，缺统一唯一约束；
  3) 依赖服务的可用性与回退：
     - 依赖 AutoClassificationService.find_similar_notes 与 TextProcessingService.process_text；异常时有回退（关键词提取），但未区分可重试/失败记录；
  4) 属性设计与索引：
     - 大量通过 properties 子字段过滤（properties__note_id 等），未在模型索引中体现（models未对properties建立具体子键索引）；
  5) 数据一致性：
     - 与笔记/标签/分类的变更同步策略未定义（删除/重命名如何反映到图谱）；
  6) 权限与公开性：
     - 模型有 is_public，但服务侧创建/查询未考虑跨用户可见性与权限边界；
  7) 性能：
     - 构建时对每个标签/分类/概念均可能触发多次数据库读写，缺少批量/缓存；

### 2.2 代码质量
- 问题清单：
  1) is_deleted 字段缺失与使用不一致（致命）：
     - 模型未定义 is_deleted/deleted_at；服务大量使用 is_deleted 过滤。
  2) 属性字段滥用：
     - 通过 properties 存储关键外键（note_id/tag_id/category_id），但未配套索引；建议改为显式字段或对常用属性建索引。
  3) 缺少事务/一致性边界：
     - 多节点/多边创建更新未在事务中处理，部分成功会造成结构半成品；
  4) 魔法常量：
     - 边类型/标签映射为硬编码字典，建议集中常量与校验；
  5) 错误处理：
     - 捕获广泛异常并返回{'error': ...}，缺少错误码与可观测性（日志字段、trace）。

- 改进方向：
  - 字段与模型对齐：
    - 方案A：在 Node/Edge 增加 is_deleted/ deleted_at 字段，并在所有查询/创建写入对齐；
    - 方案B：移除服务中 is_deleted 过滤，统一以存在性判断；
  - 唯一与索引：
    - 为常用查询建立索引（user+type+properties.note_id 等）；或将 note_id/tag_id/category_id 升级为显式字段，减少深层属性查询；
  - 幂等与重复控制：
    - 统一节点的唯一键策略（如(user,type,properties.note_id)）；边(user,source,target,type)唯一；
  - 数据同步：
    - 定义与笔记/标签/分类变更的同步机制（信号/任务），保持图谱更新；
  - 权限：
    - 构建/查询时考虑 is_public 与用户边界；
  - 性能：
    - 构建阶段引入缓存/批量查询与批量写入；

### 2.3 可维护性
- 问题：模型与服务脱节；属性字段语义分散；错误处理与监控弱。
- 建议：抽取 GraphService（统一增删改查、唯一与幂等策略）、常量模块（节点/边类型）、索引策略文档；补充单元测试覆盖节点/边幂等、属性查询、异常回退。

### 2.4 集成情况（直接关联模块）
- 与笔记模块：依赖Note内容、标签、分类；
- 与AI助手：文本处理与概念抽取；
- 与搜索：可将概念与节点摘要进入索引（后续方案）。

## 3. 具体优化建议（可直接落地）
1) 立即修复字段不一致：
   - 在KnowledgeNode/KnowledgeEdge模型中新增is_deleted(BooleanField, 默认False)与deleted_at(DateTimeField)；或在服务内移除所有is_deleted过滤，短期保证可用；
2) 唯一与索引：
   - 增加索引：
     - KnowledgeNode: (user,type,properties.note_id)、(user,type,title)
     - KnowledgeEdge: (user,source,target,type)
   - 边按唯一键update_or_create保障幂等；
3) 属性字段优化：
   - 将note_id/tag_id/category_id提升为显式字段（可选）；否则在properties子键上创建稀疏索引；
4) 同步与清理：
   - 监听笔记/标签/分类的软删除与重命名，更新或软删对应节点与边；
5) 性能与可观测性：
   - 构建流程加入简单缓存；
   - 为AI与相似笔记调用添加失败计数与重试策略；
6) 权限：
   - 构建/查询接口侧尊重is_public，跨用户访问需限制；

## 4. 建议的改动点清单（代码级）
- mongodb_models.py：
  - 为KnowledgeNode/KnowledgeEdge新增is_deleted/deleted_at字段与索引；或决定彻底移除服务里的is_deleted使用；
  - 为properties常用子键建立索引或转显式字段；
- services/knowledge_graph_builder_service.py：
  - 移除/对齐is_deleted过滤；为create/update引入幂等（update_or_create）策略；
  - 提取边/节点类型常量，避免硬编码；
  - 捕获异常分类与结构化日志。

## 5. 预期影响与回滚
- 影响：修复后图谱构建与分析/推荐路径可用；重复创建降低；查询性能提升；
- 回滚：改动集中于知识图谱模型与服务。先以“移除is_deleted过滤”方式止血，验证后再引入软删除字段与索引。
