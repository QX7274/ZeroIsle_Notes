# 【群组功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：群组与成员、邀请（Groups & Members & Invitations）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/groups/views.py（GroupViewSet、GroupInvitationViewSet、SharedScreenViewSet 内含群组相关逻辑）
  - backend/groups/mongodb_models.py（Group、GroupMember、GroupInvitation、SharedScreen 文档模型）
  - backend/groups/serializers.py（序列化器）
  - 关联：backend/notification/services.py（邀请通知）

## 2. 功能实现结论
- 结论：基本可用（建群、成员聚合可见、加入码、邀请/接受/拒绝、离开群组、成员列表、共享屏幕联动），但权限粒度、入组风控、成员角色治理、审计与指标、分页与查询等仍需增强。

### 2.1 已实现能力（功能面）
- 可见范围：
  - get_queryset = 我创建 + 我加入 的群组（is_active=True, distinct）；
- 邀请/加入：
  - 生成加入码（creator/admin，expires_in 5~1440 分钟）；
  - join_by_code：校验码有效期、复用激活、首次加入创建 GroupMember；
  - 邀请 invite：校验权限、检查重复/待处理邀请、创建邀请，发送站内通知；
  - 邀请收件箱：GroupInvitationViewSet 列出 pending + 未过期；
  - 接受/拒绝：accept → 创建成员并更新邀请状态；reject → 更新状态；
- 成员管理：members 列出成员（仅成员可查）；leave 离开（创建者不可离开）；

### 2.2 功能缺陷/缺失（聚焦可用性）
1) 权限与角色
- 仅存在 creator/admin/member 的检查，但未见成员权限升级/降级接口与更多动作权限（管理成员、删除群组、编辑群信息等）；
- 缺团队/组织边界限制（跨租户加入）；

2) 入组与风控
- 加入码长度与复杂度不明、未限错次数/频率；
- 邀请接受未设置节流；
- 未提供黑名单/封禁成员；

3) 审计与治理
- 未记录群操作审计（生成码、邀请、加入、离开、踢人、角色变更）；
- 未提供活跃度/成员增长/邀请转化等指标；

4) 数据与分页
- 列表/成员列表未分页；
- 查询过滤有限（按名称/创建时间/成员数等未提供）；

5) 体验
- 生成加入码不支持一次性/限制次数；
- 邀请有效期与提醒策略固定（默认7天）；
- 无“转让群组所有权”；

6) 安全
- 未对加入码/邀请做租户范围校验；
- 未对常用敏感操作加二次确认；

## 3. 具体优化建议（可落地）
1) 权限与角色（P0）
- 引入角色矩阵：owner/admin/moderator/member/guest；
- 动作授权：管理成员/修改群信息/生成加入码/删除群/解散/转让所有权；
- 接口：升级/降级成员、移除成员、转让所有权；

2) 入组风控（P0）
- 加入码：长度≥12、一次性/次数上限/IP 限制；错误次数阈值与冷却；
- 邀请：速率限制与配额；

3) 审计与指标（P0）
- 审计：操作类型、操作者、对象、时间、IP/UA；
- 指标：成员增长、加入码使用、邀请接受率；

4) 分页与检索（P0）
- groups/members 端点增加分页/排序/搜索（名称 like、创建时间、成员数）；

5) 安全与多租户（P0）
- 限制加入码与邀请仅在同租户内有效；
- 敏感操作二次确认；

6) 体验（P1）
- 加入码管理：立即失效、重置、查看历史；
- 邀请提醒：将到期前发送提醒；

## 4. 关键代码改造建议（片段）
- 角色授权：
  - def has_group_perm(user, group, action): ...
- 加入码：
  - join_code = secrets.token_urlsafe(16); store usage_limit; decrement on use
- 节流：
  - throttle_scope = 'group_invite/join'; DEFAULTS {'group_invite':'30/min','group_join':'60/min'}

—— 建议优先落地“角色矩阵与授权 + 入组风控 + 审计与分页检索”的 P0，随后完善多租户与体验，使群组协作更可控与可运营。
