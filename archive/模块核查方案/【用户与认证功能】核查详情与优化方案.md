# 【用户与认证功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：用户与认证（Users & Auth）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/users/views.py（基于表单的注册与登录：register_user、login_user）
  - backend/users/mongodb_models.py（Mongo 用户文档模型，与 Django User 并存）
  - backend/users/permissions.py（IsOwnerOrAdmin 基础对象权限）
  - 依赖：mongodb_service（用户同步/查询）

## 2. 功能实现结论
- 结论：基础可用（表单注册/登录 + 将 Django 用户信息写入/读取 Mongo），但存在严重的一致性与安全风险，缺 JWT/API 认证、会话管理、防爆破/风控、邮箱验证与密码重置、SSO/第三方登录等完整路径。

### 2.1 已实现能力
- 注册 register_user：
  - 使用 Django 自带 UserCreationForm 创建 Django User；
  - 将相关信息写入 Mongo（django_user_id/username/email/date_joined ISO 字符串）；
  - 插入成功后自动登录并跳转首页；
- 登录 login_user：
  - 先从 Mongo 查询用户（通过用户名），再回查 Django User 并验证密码，成功则 login() 建立 Django 会话；
- 权限类 IsOwnerOrAdmin：提供对象级“对象.user == request.user 或管理员”通过。

### 2.2 关键缺陷/缺失（功能可用性与安全）
1) 双源用户数据不一致
- 登录依赖 Mongo 存的 django_user_id；若 Mongo 与 Django 不一致（写入失败/迁移/清理），会导致登录失败；
- 注册写入 Mongo 使用自定义 mongodb_service.insert_user_sync，失败即 500，未重试/补偿；

2) 认证形态单一
- 仅支持基于服务器渲染页面的表单登录；缺 REST/JWT Token（适配前后端分离与移动端）；
- 缺刷新令牌/短期 Token 与续期策略；

3) 安全与风控
- 登录无节流/防爆破（IP/用户），无 CAPTCHA；
- 未记录登录失败审计，未封禁策略；
- 未做邮箱验证/密码重置流程；

4) 会话与CSRF
- 使用 login() 建立 Django Session，但未说明 CSRF 防护/跨站请求；
- 未提供登出/会话失效/多端登录限制；

5) 密码与凭据
- 注册使用 UserCreationForm 但未强制密码复杂度策略；
- Mongo 用户模型也含 password 哈希字段（与 Django 重复），存在冗余与一致性风险；

6) 多租户与角色
- 未提供角色/组织/租户字段与授权体系；权限类仅 IsOwnerOrAdmin，粒度过粗；

7) 国际化与第三方登录
- mongodb_models 预留了 wechat/qq 字段，但未有端到端认证流程；

## 3. 具体优化建议（可落地）
1) 认证方式（P0）
- 引入 JWT/OAuth2：
  - 使用 djangorestframework-simplejwt 提供 /auth/login /auth/refresh 接口；
  - 统一前后端分离认证；
- 保留现有 Session 登录仅用于后台管理；

2) 用户源一致性（P0）
- 统一用户主源（建议 Django User 为权威源），Mongo 仅保存扩展资料；
- 注册落库使用事务/补偿：Django 成功→写 Mongo；若 Mongo 失败，标记重试队列；
- 登录时以 Django 为准，Mongo 仅作资料；

3) 安全与风控（P0）
- 登录节流（用户名+IP 维度），失败次数阈值 → 临时封禁；
- 可选 CAPTCHA；
- 强密码策略与密码历史/重试间隔；
- 邮箱验证、重置密码（含令牌有效期/单次使用）；

4) 会话与登出（P0）
- 提供 /auth/logout 使会话失效；
- CSRF 防护与 SameSite Cookie 策略；

5) 角色/组织/租户（P1）
- 引入 Role/Org/Tenant 模型与绑定；
- 在权限类中注入组织/租户检查；

6) SSO/第三方（P1）
- 对接 OAuth（Google/GitHub/WeChat/…），统一回调与账号绑定；

7) 审计与指标（P1）
- 记录注册/登录成功/失败、来源、IP/UA、耗时；
- 指标：登录失败率、爆破拦截次数、JWT 刷新量；

## 4. 关键代码改造建议（片段级思路）
- JWT 登录：
  - POST /api/auth/login → authenticate → jwt pair 返回；
- 登录节流：
  - DRF throttle_classes + 缓存计数；失败阈值→429/403；
- 一致性：
  - try: save Django → enqueue Mongo write; except: rollback or mark pending

—— 建议优先“JWT 认证 + 风控节流 + 用户源一致性 + 邮箱验证/重置”四项 P0，随后推进多租户与角色权限，确保安全与可用性。
