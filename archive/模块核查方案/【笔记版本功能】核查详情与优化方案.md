# 【笔记版本功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：笔记版本功能（Note Version）
- 核查日期：2025-11-17
- 核心代码路径：
  - 后端：/backend/notes/
    - Django模型：/backend/notes/models/version.py
    - MongoEngine模型：/backend/notes/mongodb_models/note_version.py
    - 视图：/backend/notes/views/version.py
    - 序列化器：/backend/notes/serializers/version.py（视图已引用，未展开）

## 2. 核查结果
### 2.1 功能实现
- 结论：未实现/实现存在重大不一致，当前接口在运行期高概率报错
- 已实现（框架）：
  - 版本列表、详情、创建版本、更新版本、删除版本（标注软删除）、恢复版本、自动保存版本获取与创建等接口骨架。
- 未实现/缺陷（关键不一致点）：
  1) 模型与视图字段严重不匹配：
     - 视图按MongoEngine导入：from notes.mongodb_models import NoteVersion, Note；
     - MongoEngine模型字段：title、content、version_number、created_by、comment、is_auto_save、created_at；无user、description、is_current、updated_at、is_deleted等字段；
     - 视图大量使用不存在字段：
       - list/filter使用 is_deleted、user；
       - create 使用 user、description、is_current、updated_at；
       - update 使用 description、is_current、updated_at；
       - destroy 使用 is_deleted 语义但调用 delete()；
       - restore 亦依赖 is_current、description 等；
     - 结论：当前视图与MongoEngine模型不兼容，运行期会抛出字段不存在或查询构造错误。
  2) Django模型与MongoEngine模型并存且定义差异：
     - Django版NoteVersion字段：created_by、comment、is_auto_save、created_at；排序、唯一约束与MongoEngine不同；
     - 视图完全未使用Django模型，双实现混淆风险高。
  3) 版本号与“当前版本”语义：
     - 视图实现了“is_current”概念并在更新时切换当前版本，但MongoEngine模型无此字段；
     - 切换当前版本时“将其他版本is_current=False”的操作无法执行。
  4) 自动保存/恢复逻辑不完整：
     - create_auto_save 计算version_number但未显式设置is_auto_save=True；
     - auto_save查询依赖description包含“自动保存”，脆弱且与模型is_auto_save字段不一致（MongoEngine模型有is_auto_save）。

### 2.2 代码质量
- 问题清单：
  1) 模型与视图不一致（致命）：字段与查询条件大面积不匹配，导致API不可用；
  2) 软删除语义不一致：视图以is_deleted过滤，但模型无该字段且destroy调用delete()物理删除；
  3) 版本切换逻辑未与笔记内容变更的原子性绑定：部分路径直接修改Note并更新其他版本is_current；在模型不一致情况下无法生效；
  4) 性能与分页：版本列表未分页，历史版本较多时响应膨胀；
  5) 校验与约束：未对version_number并发增长做校验；未对标题/内容长度做限制与清洗；
  6) 一致性与审计：缺少updated_at/updated_by、恢复操作审计记录。

- 改进方向：
  - 统一数据模型（强烈建议）：保留MongoEngine或切换Django ORM，任选其一，并让视图/序列化器与之完全对齐；
  - 明确字段：user/created_by统一；description与comment统一；增加is_current、updated_at、is_deleted、restored_from（可选）；
  - 软删除统一语义：统一使用is_deleted布尔+deleted_at；
  - 版本号生成与并发：在创建版本时以note维度获取max(version_number)+1，或使用原子$inc字段；
  - 自动保存：使用is_auto_save布尔字段，不依赖description字符串；
  - 分页与排序：列表分页，默认按version_number desc或created_at desc；
  - 恢复/切换当前版本：封装在Service中，以事务或一致性操作保障Note内容与版本标记的一致；
  - 单元测试覆盖：创建/更新/恢复/自动保存/分页/并发递增。

### 2.3 可维护性
- 问题：双模型并存、字段命名不统一、视图逻辑与模型脱节、无Service分层；
- 建议：抽取VersionService（create_version/restore/set_current/list），视图仅编排；统一ORM；补足DTO/Serializer派生字段。

### 2.4 集成情况（直接关联模块）
- 与笔记模块（Note）：切换版本会回写Note内容，需原子保障；
- 与同步模块：版本操作需要在Sync层考虑冲突与版本增长；
- 与搜索模块：版本内容是否入索引需策略化（默认仅当前版本入索引）。

## 3. 具体优化建议（可直接落地）
1) 统一模型并校对字段：
   - 若保留MongoEngine：为NoteVersion新增字段 user(=created_by)、description(=comment)、is_current、updated_at、is_deleted、restored_from；或调整视图与序列化器仅使用现有字段并移除不支持的逻辑；
   - 若迁移到Django ORM：将视图改为Django模型查询语法，保留is_current/updated_at/is_deleted等字段，迁移数据后启用。
2) 软删除一体化：
   - 所有查询加is_deleted=False，destroy仅置位不物理删除；
3) 当前版本切换：
   - VersionService.set_current(note, version_id) 内部将其他版本清零、更新Note内容，并写入审计；
4) 自动保存：
   - create_auto_save设置is_auto_save=True，并以“最近N分钟+is_auto_save=True”过滤；
5) 分页与校验：
   - 列表分页；version_number并发安全；标题/内容长度限制与清洗；
6) 测试：
   - 覆盖创建、恢复、切换当前、自动保存、软删除与分页等典型路径。

## 4. 建议的改动点清单（代码级）
- 视图：/backend/notes/views/version.py
  - 去除对不存在字段的使用；接入分页；下沉到VersionService；
- 模型：/backend/notes/mongodb_models/note_version.py 或 /models/version.py
  - 对齐字段；新增/移除字段以匹配视图；
- 序列化器：描述/字段名与模型一致；

## 5. 预期影响与回滚
- 影响：版本功能可用性恢复；数据一致性提升；
- 回滚：改动集中于版本功能，按“统一模型→修正视图→补充测试”三步上线，任一步可回滚。
