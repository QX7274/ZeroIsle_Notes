# 【用户与认证模块】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：用户与认证（Users & Auth）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/users/services/auth_service.py（注册/登录/重置密码/第三方登录/设备记录）
  - backend/users/models/*（User、UserProfile、UserSettings、UserDevice、VerificationCode、ThirdPartyAccount 等）
  - backend/users/views/*（auth、third_party、profile、settings、device 等）
  - backend/users/jwt_auth.py、auth.py、permissions.py、middleware.py

## 2. 功能实现结论
- 结论：支持多登录方式（用户名/邮箱/手机号+密码、手机号+验证码、第三方登录）、JWT 发放、注册与密码重置、设备记录、邮件/短信通知等，覆盖常见场景。需要在安全（速率/风控/密码策略/验证码风险）、会话与JWT治理、第三方登录一致性、审计与可观测、国际化与多租户、数据与隐私合规上加强。

## 3. 已实现能力（概览）
- 注册：唯一性校验（用户名/邮箱/手机号），成功后可发送欢迎邮件。
- 登录：
  - 用户名/邮箱/手机号 + 密码；
  - 手机号 + 短信验证码（支持不存在即自动注册的路径）；
  - 第三方登录（provider + uid），不存在则创建账号并绑定 ThirdPartyAccount；
  - 登录成功回写 last_login、IP、记录 UserDevice；
  - 返回 JWT（access/refresh）。
- 重置密码：邮箱或手机号 + 验证码，设置新密码并通知。
- 设备：按 device_id upsert，保存属性与最近登录信息。

## 4. 主要问题（P0 优先级）
1) 安全与风控
- 登录/注册/重置密码/验证码缺统一的节流（IP/账号/设备维度）与风险控制；
- 密码策略（复杂度/历史密码/密码重用间隔）未见；
- 短信/邮箱验证码：发送频率、错误尝试次数、图形验证码/滑块、人机校验缺失；
- 手机号登录自动注册路径存在撞库与沉默拉新风险；

2) JWT 与会话
- JWT 生命周期、刷新、吊销（黑名单/撤销列表）与单设备登录策略未描述；
- 多端设备管理：登出、强制下线、设备令牌失效未实现；

3) 第三方登录
- 头像 URL 存储分 provider 字段，更新逻辑简单；
- token/refresh_token/过期时间未做加密与安全存储；
- 缺回收/解绑第三方账号接口与风控；

4) 审计与可观测
- 仅基本日志；缺登录失败/异常来源/风控命中等审计；
- 无指标（登录成功率、失败原因分布、验证码通过率、第三方登录占比）。

5) 国际化与多租户
- 账号命名、手机号/邮箱校验规则未按地区配置；
- 组织/租户上下文（org_id）未纳入账号与权限；

6) 隐私与合规
- IP、设备、第三方 token 存储与访问控制需符合隐私要求；
- 导出账户数据、删除账户（GDPR-style）流程未描述；

## 5. 可落地优化建议
1) 风控与节流（P0）
- DRF/中间件级 Throttle：按 IP、用户名/手机号、设备、端点类型设置限流；
- 验证码人机校验（图形/滑块/行为），错误次数阈值后强制；
- 登录失败惩罚性等待、IP 黑名单、设备风险画像；

2) 密码与验证码策略（P0）
- 密码复杂度/长度/历史密码禁止重用、密码有效期可选；
- 短信/邮件验证码发送限额、最短间隔、错误次数与锁定；

3) JWT 与会话治理（P0）
- 开启 SimpleJWT 黑名单（token 黑名单/旋转刷新令牌）；
- 设备级会话：设备登出/全部登出、限制同时在线设备数；

4) 第三方登录安全（P0）
- 第三方凭证加密存储（KMS/加密字段）；
- 绑定/解绑流程、登录保护（二次验证）；

5) 审计与可观测（P1）
- 登录/注册/重置指标与审计日志（用户、IP、UA、地理、原因码、耗时、设备）；
- 告警：暴力尝试、撞库、异常地区登录；

6) 多租户与国际化（P1）
- 引入 org_id/tenant_id，多租户域隔离；
- 手机号/邮箱校验与短信/邮件模板多语言；

7) 合规与用户权利（P1）
- 账号数据导出、删除、下载日志；
- 隐私策略告知与同意记录；

## 6. 关键改造片段（示例）
- 节流：
  - throttle_scope='auth_login'; 登录失败 Redis 计数，超过阈值锁定账号/设备/IP 若干分钟；
- JWT 黑名单：
  - SIMPLE_JWT = { 'BLACKLIST_AFTER_ROTATION': True, ... }
- 设备管理：
  - POST /users/devices/{id}/revoke → 将该设备 token 拉黑并设置 is_active=False；
- 第三方凭证加密：
  - 字段加密或外部 KMS；读取时解密，日志中避免输出。

—— 建议优先落地“节流/风控 + JWT黑名单与会话治理 + 密码与验证码策略 + 第三方凭证加密 + 审计指标”，随后推进多租户与国际化、合规流程，全面提升认证链路的安全性与可运营性。
