# 【群组与协作】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：群组与协作（Groups）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/groups/models.py（Group/GroupMember/GroupInvitation/SharedScreen 模型，软删、角色、邀请状态、共享屏幕）
  - backend/groups/views.py（群组 CRUD、入组码、邀请、成员列表、离开；邀请接受/拒绝；共享屏幕创建/暂停/恢复/结束/加入）
  - backend/groups/serializers.py、mongodb_models.py、consumers.py、routing.py（未展开）
  - 关联模块：notification.services（群组邀请通知）

## 2. 功能实现结论
- 结论：群组创建/加入/邀请/成员管理与基础共享屏幕流程已具备，权限粗粒度可用（创建者/管理员/成员）。存在一致性与字段/状态不匹配、权限边界、审计与风控、实时推送与房间管理、资源回收与清理、以及多租户与组织级治理等改进点。

## 3. 已实现能力（概览）
- 群组
  - Group：UUID 主键、创建者、公开标记、软删、时间戳；
  - GroupMember：管理员/成员角色、唯一(group,user)；
  - GroupInvitation：pending/accepted/rejected/expired，过期判断；
  - 视图：
    - 可见群组=我创建或我加入；
    - 加入码生成/校验加入；
    - 邀请（检查重复/过期），通知被邀请者；
    - 成员列表、退出群组；
- 共享屏幕
  - SharedScreen：标题/描述/流地址/开始结束时间；视图含 pause/resume/end/join 流程、webrtc_room_id 生成；

## 4. 主要问题（P0 优先级）
1) 字段/状态不一致
- models.SharedScreen 未见 status/webrtc_room_id 字段，而视图层使用 status 字段筛选与写入 webrtc_room_id，存在不匹配风险；
- Group 模型未见 join_code、join_code_expires_at 字段，但视图使用 group.generate_join_code 与 join_code_expires_at；应核对 mongodb_models 或补齐字段/方法。

2) 权限与边界
- IsGroupCreatorOrAdmin/IsGroupMember 基于 Mongo 模型（views 导入 mongodb_models.Group），与 models.py 的 Django 模型并存，需统一数据源与权限校验；
- 入组码/邀请接口缺节流与风控（暴力尝试/撞库/钓鱼）。

3) 通知与实时性
- 邀请已调用 NotificationService.create_notification，但无 WebSocket 实时推送与已读跟踪；
- 成员加入/退出、共享屏幕状态变更未推送群内广播事件（channels/WS）。

4) 共享屏幕可靠性
- webrtc 房间管理未与实际信令服/媒体服打通；
- 暂停/恢复/结束仅改状态，未处理流资源释放/观众同步；

5) 审计与风控
- 缺操作审计（创建/解散/邀请/入组/退组/共享屏幕）；
- 加入码生成与校验未记录尝试次数与IP/UA，缺失败告警；

6) 多租户与组织
- 未见组织/项目上下文；群组对跨模块资源（笔记/导图/图谱/帖子）授权策略需统一；

7) 数据一致性与清理
- 邀请过期清理任务；群组软删后的成员/邀请/共享屏幕清理；

## 5. 可落地优化建议
1) 模型对齐与迁移（P0）
- 为 SharedScreen 增加 status(Char: active/paused/ended)、webrtc_room_id、权限字段；
- 为 Group 增加 join_code、join_code_expires_at、generate_join_code()；
- 明确统一采用 MongoEngine 还是 Django ORM，避免混用导致权限/查询不一致。

2) 权限/风控与节流（P0）
- 入组码/邀请接口增加 DRF Throttling 与验证码/二次确认；
- 入组码长度/复杂度/有效期限制，尝试失败次数限制（短时封禁）；

3) 实时推送（P0）
- 使用 Django Channels：
  - 邀请/成员变更/共享屏幕状态更新 → 群组频道广播；
  - 客户端订阅 group_{id} 频道；

4) 共享屏幕打通（P0）
- 定义信令交换端点与权限校验；
- 结束时回收资源，广播结束事件；

5) 审计与可观测（P1）
- 记录邀请/加入/退出/共享屏幕操作日志（用户、对象、时间、IP/UA）；
- 指标：群组创建/加入率、邀请接受率、共享时长、并发观众数；

6) 多租户与授权（P1）
- 群组与资源绑定的 ACL：在各业务模块（笔记/导图/图谱/帖子）侧增加 group_ids/visibility 字段，查询时按组过滤；

7) 清理与维护（P1）
- 定时任务：邀请过期清理、无成员群组回收、结束的共享屏幕归档与URL失效；

## 6. 关键改造片段（示例）
- 模型补齐（Django ORM 示例）：
  - class SharedScreen(...): status=models.CharField(default='active', choices=...); webrtc_room_id=models.CharField(...)
  - class Group(...): join_code=models.CharField(...); join_code_expires_at=DateTimeField(...); def generate_join_code(...)
- WS 广播：
  - channel_layer.group_send(f"group_{gid}", {"type":"group.event","event":"member_joined","user":uid})
- 入组码节流：
  - throttle_scope='group_join_by_code'; 验证失败计数 Redis 自增，超过阈值封禁一段时间。

—— 建议优先完成“模型字段对齐 + 权限与节流 + 实时推送 + 信令打通”的 P0，随后推进多租户授权、审计指标与清理策略，保证群组协作在真实使用中的稳定性与安全性。
