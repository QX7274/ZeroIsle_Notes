# 【笔记备份功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：笔记备份（Note Backup）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/notes/views/backup.py（NoteBackupViewSet：列表/详情/创建/删除/恢复/导出/导入/自动备份）
  - backend/notes/mongodb_models.py（Note、NoteBackup 文档模型，含 GridFS 备份文件字段 backup_file、软删）
  - backend/notes/serializers.py（NoteBackupSerializer）

## 2. 功能实现结论
- 结论：基本可用（手动/自动备份、恢复、导入导出），但在一致性、权限与风控、备份内容完整性、容量保留策略、导出介质与签名下载、审计与告警等方面需增强。

### 2.1 已实现能力（功能面）
- 列表 list：
  - 支持按 note_id 获取该笔记的备份（校验所有权），或获取本人所有备份；
- 详情 retrieve：仅本人可见；
- 创建 create：
  - 校验笔记归属；
  - 记录标题与内容快照、类型（默认 manual），可附带备份文件 backup_file（存 GridFS）；
- 删除 destroy：软删；
- 恢复 restore：
  - 先为当前内容创建一条 auto 备份；
  - 再将笔记内容回写为所选备份的内容与标题；
- 导出 export：
  - 将该笔记所有备份导出为本地 JSON 文件（media/backups/{note_id}/yyyyMMdd_HHmmss.json），返回文件清单；
- 导入 import_backup：
  - 读取上传的 JSON 文件，创建一条备份记录（并保存原文件），可选回写笔记内容并触发知识图谱重建；
- 自动备份 auto_backup：
  - 直接对当前内容创建一条类型为 auto 的备份。

### 2.2 功能缺陷/缺失（聚焦可用性与可靠性）
1) 原子性与一致性
- 恢复流程先创建新备份再回写笔记，缺少事务保护，失败时可能出现“创建了备份但未成功回写”的不一致；
- 恢复/导入回写笔记时缺版本冲突检测（可能覆盖他人更新）。

2) 备份内容完整性
- 仅备份 title/content，未快照分类/标签/加密等其他可变字段；
- 未记录笔记的元数据（创建时间、最后编辑者、协作信息等）。

3) 容量与保留策略
- 未设置每笔记备份数量/空间上限；
- 自动备份频率与保留期未控制，可能快速膨胀；
- 软删后 GridFS 对象实际清理策略未说明。

4) 权限与风控
- 仅按所有者授权，未结合协作权限（协作者是否可备份/恢复/导入）；
- 导出到服务器本地目录，缺下载权限与签名 URL，存在泄露风险；
- 无节流与配额（可被滥用制造大量备份）。

5) 导出/导入体验与安全
- 导出生成服务器磁盘文件，未提供下载接口与短时签名；
- 导入 JSON 未做严格 schema 校验与大小限制；

6) 审计与可观测
- 关键操作（备份、恢复、导入、导出）未写审计；
- 无指标与告警（失败率、恢复时长、容量占用等）。

## 3. 具体优化建议（可落地）
1) 一致性与并发（P0）
- 恢复/导入回写使用事务或两阶段：创建“待恢复”记录→成功回写后提交；
- 回写笔记前做版本冲突检测（updated_at/版本号对比），冲突时提示或合并；

2) 完整快照（P0）
- NoteBackup 增加快照字段：category/tags/is_encrypted/metadata 等；
- 恢复时可选择“仅内容”或“含元数据”回滚；

3) 容量控制与保留（P0）
- 配置每笔记最大备份数（如 200）与自动备份保留期（如 30 天）；
- 自动备份去重与节流（内容未变化则跳过或合并）；
- 定时清理软删备份与孤儿 GridFS 对象；

4) 权限与风控（P0）
- 协作者权限矩阵：view/backup/restore/import/export 分级；
- 节流：每用户/每笔记的备份创建/恢复/导出速率限制；
- 配额：总备份空间与数量上限；

5) 导出/导入（P1）
- 导出改为打包 ZIP 并通过短时签名 URL 下载（S3/OSS 等对象存储）；
- 导入进行严格 schema 校验，限制文件大小、字段白名单；

6) 审计与指标（P1）
- 审计日志：操作类型、对象、操作者、结果、耗时、大小；
- 指标：备份创建/恢复/导入导出次数、失败率、平均耗时、存储占用；

7) 体验（P2）
- 恢复预览与差异对比；
- 批量导出选择范围与时间窗口；

## 4. 关键代码改造建议（片段）
- 并发保护：
  - if note.updated_at != client_last_seen: return 409 Conflict
- 自动备份节流：
  - last_auto = NoteBackup.objects.filter(note=...).order_by('-created_at').first(); if now-last_auto<5min: skip
- 导出签名：
  - url = storage.generate_presigned_url(path, expires=600)

—— 建议优先落地“事务/冲突检测+完整快照+保留与节流+导出签名与权限”的 P0 改造，确保备份功能在规模化与协作场景下可控且安全。
