# 【附件功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：附件功能（Attachment）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - admin_system/backend/content/models.py（Attachment 模型）
  - admin_system/backend/content/serializers.py（AttachmentSerializer/AttachmentListSerializer）
  - admin_system/backend/content/services.py（ContentService.sync_attachments / update_attachment_in_main_app / delete_attachment_in_main_app）
  - admin_system/backend/content/views.py（AttachmentViewSet：CRUD、筛选、批量删除、同步）

## 2. 核查结果

### 2.1 功能实现结论
- 结论：部分实现
- 已实现能力：
  - 模型：文件基础元数据（文件名/路径/类型/大小/MIME、关联笔记与用户、创建时间），常用索引（note/user_id/file_type/created_at）。
  - 后台接口：列表查询、按笔记/用户/类型/时间/大小过滤；创建、更新、删除、批量删除；从“主应用”同步（按 created_at 增量）；更新/删除时尝试回写主应用。
- 未实现/存在缺陷：
  1) 存储与下载链路未实现：仅保存 file_path 元数据，无实际上传接入、下载/预览接口、断点/Range 支持；
  2) 安全缺失：
     - 无文件大小上限与 MIME 白名单校验；
     - 未做病毒/恶意内容扫描；
     - file_path 由外部来源写入，存在路径穿越/越权读取风险；
     - 缺下载鉴权（仅 IsAuthenticated），未校验笔记归属或权限；
  3) 资源一致性：删除附件未见对应物理文件删除/对象存储删除；
  4) 同步与ID类型：sync_attachments 使用 created_at 增量，无法拿到更新；与主应用交互以 {"_id": attachment_id} 匹配，若主库为 ObjectId 则类型不匹配；
  5) 可用性与体验：无缩略图/预览（图片/PDF 首图）、无元数据自动填充（MIME/尺寸）、无重复内容去重（hash）；
  6) 额度与配额：缺用户/组织级容量限制、单文件大小限制与速率限制；
  7) 审计与日志：上传/下载/删除缺审计记录（操作者、IP、UA、大小、结果）；
  8) 性能与大文件：导入/导出无分片策略、未接入对象存储（S3/OSS）与签名 URL；
  9) 关联完整性：删除笔记未见联动清理附件；
  10) 更新回写数据不规范：views.perform_update 直接用 serializer.data 回写主应用，可能包含本地派生字段或字段名不一致。

### 2.2 代码质量问题清单与定位
- 增量与更新：services.sync_attachments 仅比较 created_at（第 736-742 行）；更新无法被增量捕捉；
- ID 类型：update_attachment_in_main_app/delete_attachment_in_main_app 以字符串匹配 _id（第 799、812 行），与主库 ObjectId 可能不匹配；
- 视图回写：views.AttachmentViewSet.perform_update 直接传 serializer.data 给主应用（第 1023-1026 行），需字段白名单与时间统一；
- 安全与权限：AttachmentViewSet 仅 IsAuthenticated（第 962 行），下载/读取接口缺失，且列表/详情未校验笔记所属权限；

### 2.3 可维护性
- 存储、元数据、扫描、缩略图、签名 URL 等能力应抽象为 StorageService；
- 与“内容服务”分离上传/下载职责，当前仅做同步与回写；
- 配置项（大小上限、白名单、存储类型、本地路径/桶名、签名时长）应进入 SystemSetting。

## 3. 具体优化建议（可落地操作）
1) 存储方案与下载链路（P0）
- 选型：
  - 开发环境：本地磁盘 + 统一存储根目录（不信任 file_path 输入）；
  - 生产：对象存储（S3/OSS/又拍）或 MongoDB GridFS（如需与Mongo同域）；
- 上传：后端接收文件流，生成安全文件名（UUID+扩展名），计算 SHA256/MD5，保存元数据（hash、大小、MIME、宽高）；
- 下载：提供 GET /attachments/{id}/download，
  - 鉴权：检查用户是否有该笔记访问权限；
  - 支持 Range/流式响应；
  - 对象存储优先返回短期签名 URL（可配置有效期）。

2) 安全（P0）
- 请求侧校验：限制单文件大小（如 <= 20MB，配置化）、MIME 白名单（images/pdf/文本等）；
- 病毒扫描：对大于阈值的文件异步扫描或第三方服务；
- file_path 内部生成，不接受外部绝对路径；
- 审计：上传/下载/删除都写 AdminOperationLog（模块：附件）。

3) 一致性与清理（P0）
- 删除附件：先删除存储中的对象，再删除元数据；失败回滚或标记垃圾回收重试；
- 删除笔记：联动删除其附件（事务/补偿）。

4) 同步与外部ID（P0）
- 同步改为按 updated_at 增量；
- 模型新增 external_id（字符串，索引），同步时 external_id=str(_id)；
- 与主应用交互时使用 ObjectId(external_id)。

5) 字段白名单与时间统一（P1）
- perform_update 回写仅允许：filename、mime_type、file_type、note_id（或 note 关联）、user_id；
- 自动设置 updated_at=UTC；去除派生字段。

6) 预览与体验（P1）
- 图片缩略图与PDF首图生成（异步），前端展示预览；
- 记录 image 尺寸与 EXIF 关键字段（脱敏）。

7) 配额与速率限制（P1）
- SystemSetting 增加 attachment.max_size_mb、attachment.total_quota_mb_per_user、attachment.allowed_mime 等；
- DRF Throttle 对上传/下载做速率限制；
- 超限时返回明确错误。

8) 去重与版本（P2）
- 通过内容哈希去重（同一hash仅存一份实体，引用计数）；
- 支持同名文件的版本化（可选）。

## 4. 关键代码改造建议（片段级思路）
- 生成安全文件名：safe = f"{uuid4().hex}{Path(orig).suffix.lower()}"；
- 白名单校验：
  - ALLOWED = {"image/png","image/jpeg","application/pdf",...}；
  - if mime not in ALLOWED or size > MAX: 拒绝；
- 下载鉴权：根据 attachment.note 的权限（作者/协作者/管理员），否则 403；
- Range：支持 Range 解析与206响应；
- 外部ID：attachment.external_id = str(doc['_id'])；更新使用 {'_id': ObjectId(external_id)}；

—— 本次模块核查到此结束，建议优先落地“上传/下载链路+安全校验+删除一致性+增量与外部ID”的P0项，随后实现预览/配额与去重等增强能力。
