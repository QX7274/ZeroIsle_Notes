# 【笔记分享功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：笔记分享功能（Note Share）
- 核查日期：2025-11-17
- 核心代码路径：
  - 后端：/backend/notes/
    - Django模型：/backend/notes/models/share.py
    - MongoEngine模型：/backend/notes/mongodb_models/note_share.py
    - 视图：/backend/notes/views/share.py
    - 序列化器：/backend/notes/serializers/share.py

## 2. 核查结果
### 2.1 功能实现
- 结论：部分实现（存在存储层混用与字段/查询不匹配导致的运行期风险）
- 已实现（代码存在对应逻辑）：
  - 创建分享、更新、撤销、按分享码查询（by_code）、按我分享/分享给我列表等接口骨架；
  - 分享码生成、过期判断、查看次数递增；
  - 支持多种分享类型：link/email/user；支持可选密码与过期时间。
- 未实现/缺陷：
  - 存储层混用严重：
    - 存在两套模型定义：Django ORM版NoteShare（models/share.py）与MongoEngine版NoteShare（mongodb_models/note_share.py）；
    - 视图与序列化器均从notes.mongodb_models导入NoteShare/Note，实际使用MongoEngine；而Django模型仍保留，容易混淆与误用。
  - 查询语法与MongoEngine能力不匹配：
    - views/share.py 第33行：NoteShare.objects.filter(note__user=user, note=note_id) 使用双下划线跨文档字段过滤，MongoEngine对ReferenceField的“反向字段”链式过滤支持有限，可能无效或报错；应改为先取Note，再filter(note=note_obj)。
    - views/share.py 多处使用NoteShare.objects.get(id=..., user=request.user)，MongoEngine ok；但list()分支else使用NoteShare.objects.filter(user=user)可用，而前一分支则可不生效。
  - 字段不一致与安全问题：
    - passwords：明文存储（mongodb_models/note_share.py 第23行），verify_password直接明文比对，缺少哈希与加盐；
    - share_code长度固定8位，易猜测，缺乏唯一约束；
    - serializer中share_type choices为['link','email','user']，与MongoEngine模型一致；但Django模型的choices不同（public/password/link/user），两处不一致。
  - 过期判断的API风格不统一：
    - MongoEngine模型提供is_expired(self)方法；
    - 序列化器另写了get_is_expired比较；视图中既有share.is_expired()调用，也有依赖序列化器字段的方式，易产生重复与不一致。
  - 权限与可见性：
    - by_code接口未见显式权限豁免（通常需允许未登录访问）；当前ViewSet默认IsOwnerOrReadOnly，可能导致外部无法通过分享码访问；
    - shared_with_me使用share_to与email/user id匹配，未对跨用户越权进行额外校验逻辑；
    - my_shares过滤条件使用user=request.user，但MongoEngine NoteShare字段名为user（是），与Django NoteShare的created_by含义不同，存在语义冲突。
  - 数据一致性：
    - view_count递增采用逐条save，缺少原子自增；高并发可能丢计数。
    - expires_at未加索引唯一性/清理策略；无定时任务清理过期分享。

### 2.2 代码质量
- 问题清单与位置：
  1) 双模型并存（高风险）：
     - /models/share.py 定义Django ORM模型；/mongodb_models/note_share.py 定义MongoEngine模型；视图与序列化器使用MongoEngine，但Django模型保留，后续维护易误用。
  2) 过滤语法可能无效：
     - /views/share.py 第33行 note__user 链式过滤，MongoEngine未保证支持；应改为先取Note对象引用再按note引用过滤。
  3) 密码安全：
     - 明文保存与比对，缺少哈希（如PBKDF2/BCrypt/Argon2）与迭代；没有错误次数与节流；
  4) 分享码与访问控制：
     - share_code长度与空间小、无唯一索引；by_code未做访问速率限制与验证码；
     - ViewSet权限策略可能阻断匿名访问by_code。
  5) 字段与语义混乱：
     - Django模型有created_by、allow_comment等字段，MongoEngine无；视图与序列化器面向MongoEngine，导致特性漂移。
  6) 可维护性：
     - 过期判断重复实现；
     - 视图层直接拼接业务（生成share_code、时间等），缺少Service聚合与单测覆盖。

- 改进方向：
  - 统一存储与模型：保留MongoEngine或迁移到Django ORM，二选一；移除另一套以避免混淆。
  - 抽取ShareService：统一创建/更新/撤销/校验密码/过期判断/统计递增等逻辑，视图仅编排。
  - 强化安全：密码哈希存储、错误次数与冷却、分享码长度与唯一索引、访问节流与审计日志。
  - 明确匿名访问策略：by_code/verify_password接口应AllowAny，但内部严格校验分享有效性与过期状态。
  - 修正查询：避免跨文档链式过滤，使用两步查询或聚合；
  - 原子自增：使用$inc实现view_count原子增长；
  - 生命周期与清理：定时失效处理、过期分享自动置is_active=False；
  - 字段统一：对齐share_type枚举、是否允许评论、协作成员等字段；

### 2.3 可维护性
- 问题：双模型导致心智负担与维护风险；视图内业务分散；缺少单元测试覆盖典型路径（by_code、密码、过期、权限）。
- 建议：统一ORM后补充测试；提供DTO/Serializer统一输出，集中派生字段（share_url/is_expired/type_display）。

### 2.4 集成情况（直接关联模块）
- 与笔记模块：Note为MongoEngine文档对象；应通过引用一致性与索引保障查询性能。
- 与用户模块：根据email或user.id进行分享匹配；需确认用户字段完整性（email唯一性）。

## 3. 具体优化建议（可直接落地）
1) 统一数据模型：
   - 选择MongoEngine为主：删除/停用Django ORM版NoteShare；在notes.mongodb_models.__init__中明确导出NoteShare/Note；
   - 或切换到Django ORM：相应重写视图与序列化器查询语法。
2) 修复查询：
   - list(note_id筛选)：先获取Note对象（校验归属），再filter(note=note)；
   - shared_with_me：将email与user id匹配统一为标准字段；
3) 强化安全：
   - 密码字段使用哈希（PBKDF2/BCrypt），verify_password做常数时间比较；
   - share_code长度改为至少16-24位，并对share_code建立唯一索引；
   - by_code接口AllowAny + 频控（IP+分享码组合），失败计数与冷却；
4) 可用性与审计：
   - view_count使用原子自增；
   - 增加审计日志（访问时间、IP、UserAgent，脱敏）；
5) 生命周期：
   - 定时任务：过期自动失效；
   - 新增“最大访问次数”可选限制。
6) API一致性：
   - 统一is_expired实现来源（仅模型方法或仅序列化器派生），避免重复；
   - 输出结构中提供type_display、share_url由统一函数生成。
7) 测试：
   - 覆盖创建、密码校验、过期、by_code匿名访问、撤销后不可访问、并发递增统计。

## 4. 建议的改动点清单（代码级）
- 移除/backend/notes/models/share.py 或标注弃用，避免双模型；
- /views/share.py：
  - 修正note筛选逻辑与权限（by_code/verify_password允许匿名，其他鉴权）；
  - 将业务逻辑下沉到ShareService；
- /mongodb_models/note_share.py：
  - 添加share_code唯一索引；
  - 提供安全的set_password/verify_password方法（哈希）；
  - 提供increment_view_count原子操作接口；

## 5. 预期影响与回滚
- 影响：分享访问稳定性与安全性提升；模型一致性改善；
- 回滚：改动限定在notes分享功能；先在测试环境验证迁移（若涉及从Django模型迁移数据）。
