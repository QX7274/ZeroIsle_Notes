# 【知识库功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：知识库（Knowledge Base）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/knowledge_base/views.py（KnowledgeBaseViewSet：CRUD、构建、问答、Markdown 导入、缺口分析）
  - backend/knowledge_base/mongodb_models.py（KnowledgeBase / Snapshot / Query 文档模型）
  - backend/knowledge_base/services/*.py（管理/构建/问答/应用服务）

## 2. 功能实现结论
- 结论：核心流程基本可用（创建/访问控制/从笔记构建/问答/导入/应用分析），但在权限细粒度、长任务与进度、检索/Embedding 质量、数据一致性与快照、审计与指标、分页与过滤等方面需完善。

### 2.1 已实现能力（功能面）
- 访问范围：get_queryset 支持“本人(owner) + 成员(members) + 公开(public) 且未删除”的并集；
- 列表检索：filter(type,is_public,is_archived,tags) + search(name,description) + ordering(created/updated/name/node_count) + 分页；
- 创建/删除：通过 ManagementService 执行；
- 构建 build：POST /{id}/build，调用 BuilderService.build_from_notes(kb_id,user,...)；
- 问答 ask：POST /{id}/ask，调用 QAService.ask_question(kb_id,user,...)；
- 导入 import_markdown：POST /{id}/import_markdown 传 content + source_name；
- 应用 analyze_gaps：GET /{id}/analyze_gaps 调用 ApplicationService.identify_knowledge_gaps。

### 2.2 功能缺陷/缺失（聚焦可用性）
1) 权限与范围
- IsAuthenticated + IsOwnerOrReadOnly 仅在对象级；成员(members)对“写、构建、导入、问答”等动作的授权细粒度不明确；
- 缺组织/租户范围、分享链接、只读/仅问答权限；

2) 长任务与进度
- 构建/导入可能耗时，当前接口同步返回 result；缺后台任务、进度查询、取消、重试；

3) 数据与快照
- Snapshot 模型存在但在视图中未体现自动/手动快照保存与回滚；
- 问答用到的索引/嵌入/切片策略未在视图层暴露版本/时间，难以审计与复现；

4) 检索与问答质量
- 未见混合检索（BM25+向量重排）与阈值/TopK 配置；
- 缺提示词/模型、引用证据、去幻觉策略、知识库版本绑定；

5) 过滤与分页体验
- 分面(facets)与更多过滤（标签多选、时间范围、成员数、来源类别）未提供；

6) 审计与指标
- 构建/导入/问答/缺口分析未写操作审计；
- 缺指标：构建耗时/成功率、问答命中率/参考率、空答率；

7) 安全与风控
- 导入 Markdown 未显示大小与格式限制；
- 问答接口缺速率限制、配额与敏感信息过滤；

8) 一致性与回收
- is_deleted 过滤仅在主查询；归档(is_archived)语义与权限未细化；

## 3. 具体优化建议（可落地）
1) 权限模型（P0）
- 在 KB 上定义 roles：owner/maintainer/editor/viewer/qa-only，并在各 action 校验；
- 扩展权限：build/import 仅 owner/maintainer；ask 允许成员与公开（可选登录限制）；
- 支持组织/租户字段与成员来源（用户/组）。

2) 长任务与进度（P0）
- 构建/导入改为异步任务（Celery/RQ），接口改为 202 + task_id；
- 提供 /build/status/{task_id}、取消/重试；任务里记录阶段、进度百分比与错误明细；

3) 快照与版本（P0）
- 构建完成后写 Snapshot（包含索引版本、嵌入模型、切片参数、数据源列表与对象计数）；
- 支持回滚到指定快照；

4) 问答质量（P0）
- 检索：关键词召回 TopN + 向量重排；
- 引用：返回每条答案的引用证据列表（片段与来源链接），并附评分与相似度阈值；
- 模型/提示：问答请求里记录使用的模型/提示模板版本；

5) 过滤与分面（P1）
- 列表提供 facets（标签/类型/时间），以及 tag 多选 AND/OR；

6) 审计与指标（P1）
- 审计：构建/导入/问答/缺口分析的操作者、参数、耗时、结果；
- 指标：构建成功率/P95、问答引用率、空答率、用户满意度（可选反馈）；

7) 风控与配额（P1）
- 导入大小上限与内容校验（格式可选 Markdown/HTML→MD 转换）；
- 问答速率限制与每日配额；

8) 体验（P2）
- 导入前分析预览（章节/字数/预估切片数）；
- 缺口分析返回可操作建议（新增文档、待标注内容）。

## 4. 关键代码改造建议（片段级思路）
- 权限：
  - def has_kb_permission(user, kb, action): ...; 在 build/ask/import 前统一校验
- 异步与状态：
  - task = enqueue(build_kb, kb_id, user, params); return 202, {'task_id': task.id}
  - GET /tasks/{id}: {status, progress, logs}
- 快照：
  - Snapshot(kb_id, version, embed_model, chunk_size, vector_count, built_at)
- 检索：
  - results = hybrid_search(query, kb_id, topk=50); answer, cites = llm.answer(results[:k])

—— 建议优先落地“权限细化 + 异步任务与状态 + 快照与版本 + 问答检索与引用”的 P0，随后推进分面过滤/审计与风控，提升知识库在真实使用场景下的可靠性与可控性。
