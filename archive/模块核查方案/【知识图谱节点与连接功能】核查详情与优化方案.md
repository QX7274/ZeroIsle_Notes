# 【知识图谱节点与连接功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：知识图谱节点与连接（Knowledge Graph Nodes & Edges）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/knowledge_graph/views/node.py（KnowledgeNodeViewSet：列表/详情/创建/更新/删除/相关节点/相关概念）
  - backend/knowledge_graph/views/edge.py（KnowledgeEdgeViewSet：列表/详情/创建/更新/删除）
  - backend/knowledge_graph/services/neo4j_service.py（与 Neo4j 同步的服务封装）
  - backend/knowledge_graph/mongodb_models.py（KnowledgeNode/KnowledgeEdge 文档模型，含软删与可见性）

## 2. 功能实现结论
- 结论：基本可用（节点/边 CRUD、权限校验、与 Neo4j 同步、相关节点/概念查询），但在权限粒度、并发与一致性、检索与可视化数据、批量与性能、审计与指标等方面需要增强。

### 2.1 已实现能力（功能面）
- 节点（Node）
  - 列表：仅返回 user=本人 且 is_deleted=False 的节点；
  - 详情：本人或 is_public=true 可见；
  - 创建：字段覆盖 title/description/type/note/坐标/样式/properties/is_public，并写入时间戳；
  - 更新/删除：仅本人；删除为软删（模型实现）；
  - 相关：
    - related：返回该节点相关的边和对端节点（仅 user=本人 且未删除的边）；
    - related_concepts：find_related_concepts(user, node_id, max_depth) 返回相关概念；
  - Neo4j 同步：create/update/delete 节点时尝试同步（异常不影响主流程）。
- 边（Edge）
  - 列表：仅返回 user=本人 且 is_deleted=False 的边；
  - 详情：本人或 is_public=true 可见；
  - 创建：校验源/目标节点均为本人节点；
  - 更新/删除：仅本人；删除为软删；
  - Neo4j 同步：create/update/delete 关系（异常不影响主流程）。

### 2.2 功能缺陷/缺失（聚焦可用性与一致性）
1) 权限与协作
- 仅支持“本人/公开”，未与群组/协作（collaboration）/组织范围联动；
- 节点/边 is_public 为布尔值，缺更细可见范围与动作权限（查看/编辑/连边/删除）。

2) 一致性与事务
- Mongo 与 Neo4j 同步采取“尽力而为”，失败不补偿；
- 节点删除未级联处理相关边（数据库层面靠软删一致性，缺自动清理/修复任务）；
- 更新字段较多但未使用部分更新/乐观锁，存在并发覆盖风险。

3) 批量与性能
- 列表无分页/排序/搜索；
- 相关节点查询通过取相关边再查询节点，缺分页与上限；
- 无索引策略说明（user、is_deleted、updated_at、source/target等），规模增大时可能性能不足。

4) 语义与可视化
- 坐标/样式存在，但未提供“布局计算/自动排布”；
- 相关概念的算法黑盒（find_related_concepts），缺参数化与解释；

5) 审计与指标
- 创建/更新/删除/连边等操作未写审计；
- 无指标：节点/边数量、用户图规模、平均度、操作耗时、Neo4j 同步失败率；

6) 数据质量与检索
- 缺按类型、标签、属性的过滤与分面；
- 未提供关键字搜索与高亮；

7) 多租户与范围
- 未体现 tenant/org 字段；跨团队环境下难以隔离。

## 3. 具体优化建议（可落地）
1) 权限与范围（P0）
- 可见范围：private/group/org/public；
- 动作权限：view/connect/edit/delete；
- 与群组功能联动：群组成员可在组内图谱上协作；

2) 一致性与同步（P0）
- 引入异步 Outbox：Mongo 写成功→写出站消息→异步更新 Neo4j，失败重试与死信队列；
- 定期一致性修复：扫描软删节点残留边、Neo4j 与 Mongo 差异；

3) 批量与分页（P0）
- list/related 分页与排序；
- 批量创建/更新节点与边接口；

4) 索引与性能（P0）
- 建立索引：
  - Node: user+is_deleted、updated_at、type、note、is_public；
  - Edge: user+is_deleted、source、target、type、updated_at；

5) 并发与乐观锁（P1）
- 增加版本号或 updated_at 条件更新，避免覆盖；

6) 检索与分面（P1）
- 按类型/属性/标签过滤；
- 关键字搜索（题目/描述/属性）与结果高亮；

7) 审计与指标（P1）
- 审计：节点/边增删改的操作者与字段变更；
- 指标：同步失败率、图规模、操作耗时；

8) 可视化与分析（P2）
- 自动布局（力导向/层次布局）；
- 相关概念算法参数化与解释；

## 4. 关键代码改造建议（片段级思路）
- Outbox：
  - on mongo write → outbox.insert({type:'node_created', payload:{...}}) → worker 同步至 Neo4j
- 分页：
  - qs = KnowledgeNode.objects.filter(...).order_by('-updated_at'); page=self.paginate_queryset(qs)
- 乐观锁：
  - filter={'id':id,'updated_at':client_seen}; update={'$set':fields,'$currentDate':{'updated_at':True}}

—— 建议优先落地“权限细化与群组联动 + Outbox异步同步 + 分页与索引 + 审计与并发保护”的 P0 改造，随后逐步增强检索、可视化与算法可解释性，提升图谱在协作场景下的可用性与可控性。
