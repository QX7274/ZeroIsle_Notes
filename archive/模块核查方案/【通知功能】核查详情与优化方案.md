# 【通知功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：通知功能（Notification）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/notification/services.py（NotificationService：创建/读取/标记已读/删除/统计）
  - backend/notification/views.py（NotificationViewSet：列表/详情/标记已读/全部已读/未读数/删除/清空）
  - backend/notification/mongodb_models.py（Notification 文档模型，未在本文展开）

## 2. 功能实现结论（聚焦功能）
- 结论：基本可用（站内通知读取与简单管理齐备），但发送链路、类型枚举、批量与实时推送、审计与风控等不完整。

### 2.1 已实现能力
- 创建通知：create_notification(recipient, type, title, message, sender, related_object)
  - 支持以用户ID或对象传入；记录 created_at；
- 列表与过滤：get_notifications(user_id, page, page_size, notification_type, is_read)
  - 支持类型与已读过滤、分页与总数；
- 标记已读：单条 mark_as_read、全部已读 mark_all_as_read；
- 统计：未读数量 get_unread_count；
- 删除：单条删除与全部删除；
- 接口：
  - GET /notifications（分页、过滤）
  - GET /notifications/{id}
  - POST /notifications/{id}/mark_as_read
  - POST /notifications/mark_all_as_read
  - GET /notifications/unread_count
  - DELETE /notifications/{id}
  - DELETE /notifications/delete_all

### 2.2 功能缺陷/缺失
1) 通知发送与分发
- 仅存储，不包含异步推送（WebSocket/Server-Sent Events/邮件/移动推送）；
- 无重试、失败状态与投递结果记录；

2) 通知类型与模板
- notification_type 为自由文本/未集中管理，缺枚举与显示模板（标题/内容变量占位）；
- 无多语言与本地化模板；

3) 归因与关联
- related_object 类型不明确定义；无统一的点击跳转 URL 生成策略；

4) 权限与安全
- delete_all 返回 204 但带 body；
- views.retrieve 通过 id+recipient 校验，但其它操作对权限依赖 service 内部模型查询，整体安全性需一致性审查；

5) 性能与批量
- 批量写入（如系统广播）未提供；
- 列表缺索引约束说明（recipient, is_read, created_at 应建索引）；

6) 观测与风控
- 未记录读取/投递指标；
- 未提供速率限制、配额、黑名单（防通知刷屏）。

7) 实时体验
- 未整合 Channels/WebSocket 实时推送与“未读数”自动更新；

## 3. 可落地优化建议（功能优先）
1) 推送与异步（P0）
- 引入通知分发器：
  - 站内实时：Django Channels + group=uid 推送；
  - 邮件/移动推送：异步任务队列（Celery/RQ）执行；
- 送达状态：pending/sent/failed，失败重试与原因记录；

2) 类型与模板（P0）
- 枚举与模板中心：定义类型枚举（comment_created, reply, reminder_due, share_invite, system ...），配置 title/message 模板；
- 模板变量统一（user, object, action, link）；
- i18n：根据用户语言选择模板；

3) API 与权限一致性（P0）
- delete_all 改为 200 返回结果或 204 无 body；
- 所有 service 查询均带 recipient 过滤，防越权；

4) 数据结构与索引（P0）
- 为 recipient, is_read, created_at 建复合索引；
- related_object 采用 {type, id} 结构，并提供生成跳转 URL 的 helper；

5) 批量与广播（P1）
- 支持批量创建（向组织、群组广播），异步入库与推送；
- 幂等键避免重复推送；

6) 观测与风控（P1）
- 指标：未读数分布、日推送量、送达率、读取延迟；
- 限流：同用户单位时间通知上限，系统广播节流；

7) 客户端体验（P2）
- 未读数实时订阅；
- 分组/分类视图（只看系统/互动/任务类）；
- 一键已读的分组选项；

## 4. 关键代码改造建议（片段）
- 推送（Channels）：
  - async_to_sync(channel_layer.group_send)(f"user_{uid}", {'type': 'notify', 'payload': notif_dto})
- 模板：
  - msg = templates[type].render(context)
- 批量：
  - Notification.objects.insert([ ... ])；或 Mongo bulk_write
- 权限：
  - service 内部所有 get/delete/update 均过滤 recipient=user

—— 建议优先落地“异步推送+类型与模板+索引与权限一致性”的 P0 改造，随后补齐批量广播与观测风控，提升通知的到达率与体验。
