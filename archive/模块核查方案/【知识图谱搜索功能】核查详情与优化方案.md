# 【知识图谱搜索功能】核查详情与优化方案

## 1. 基础信息
- 模块/功能名称：知识图谱搜索功能（Knowledge Graph Search）
- 核查日期：2025-11-18
- 核心代码所在路径：
  - backend/search/views/search.py（SearchViewSet.knowledge_graph 方法 413-452 行）
  - 依赖外部服务：knowledge_graph.services.KnowledgeGraphService（未在本仓库中核验实现）

## 2. 核查结果（聚焦功能）

### 2.1 功能实现结论
- 结论：部分实现
- 已实现能力：
  - 输入：POST /search/knowledge_graph，body: { query, options }；
  - 参数：options.max_results（默认20）、options.include_edges（默认True）；
  - 流程：校验 query 非空 → 调用 KnowledgeGraphService.search(query, user, max_results, include_edges) → 将 nodes 数量写入搜索历史（search_type='knowledge_graph'）→ 返回 KG 结果。

### 2.2 已实现的功能细项
- 结果结构：由外部服务返回（预期包含 nodes/edges 或类似结构），接口不做转换，直接透传；
- 历史记录：使用 SearchService.add_search_history 保存搜索记录（但仅保存 result_count=len(nodes) 的粗略统计）。

### 2.3 功能缺失/问题
1) 外部依赖可用性与接口约束
- KnowledgeGraphService 未在当前仓库核实是否存在与配置，运行期存在 ImportError 风险；
- 结果结构未定义约束（节点/边字段名、类型、属性），前端耦合风险高。

2) 查询语义与范围
- query 仅为自由文本；未提供实体类型/范围过滤（如仅检索“人物/概念/文档”），也未提供时间/标签/领域限制；
- 未支持按精确实体名/ID 查询与模糊检索切换；

3) 权限与可见性
- 未注入基于用户/组织/租户的可见性过滤；
- 搜索历史未记录与权限/范围相关的信息，难以审计与复现。

4) 结果规模与分页
- 仅提供 max_results 限制，没有 offset/page 的分页能力；
- 大图返回会超时或导致前端渲染卡顿；

5) 召回与排序
- 未说明实体/关系的排序依据（权重/置信度/热度/时间），结果不可预测；
- 未支持按得分/时间/类型排序与二次过滤。

6) 稳健性与错误处理
- 对外部服务未设置超时/重试/降级；
- 返回错误时统一 500/400，未细化“不可用/超时/无权限/超限”等；

7) 审计与指标
- 仅写入简单历史记录；
- 未记录调用耗时、节点/边数量、过滤条件、错误码等；

8) 联动能力
- 与通用搜索结果未联动：无法“从节点跳转到相关笔记/附件/评论”等；
- 未将节点属性写入搜索索引以增强后续检索。

## 3. 具体优化建议（可落地）
1) 外部服务契约（P0）
- 定义并校验 KnowledgeGraphService.search 的返回 schema：
  - nodes: [{id, type, label, score, properties, ...}]
  - edges: [{source, target, type, score, properties, ...}]
- 加载失败/不可用时返回明确错误码与提示；配置健康检查与超时（如 5-10s）与重试。

2) 查询参数扩展（P0）
- 支持 filters：types（节点类型列表）、relation_types、time_range、scope（user/org/public）、min_score；
- 支持分页：offset/limit 或 page/page_size；
- 支持 exact=true 开启精确实体匹配；

3) 权限与范围（P0）
- 将用户/组织/租户过滤传入服务层，确保仅返回可见实体与边；
- 搜索历史记录 meta 中写入范围/过滤信息；

4) 排序与质量（P1）
- 按 score/时间/度中心性等排序；
- 支持按类型/属性分面统计（facets）便于前端过滤；

5) 稳健性与降级（P1）
- 对调用设置超时/重试；
- 失败降级为“仅返回实体列表（不含边）”或“返回建议关键字/相关条目”；

6) 审计与指标（P1）
- 记录调用耗时、返回节点/边数量、过滤条件、错误码；
- 指标上报：QPS、P95、失败率、空结果率；

7) 联动与回写（P2）
- 节点链接到具体内容页（笔记/附件/知识库），提供跳转信息；
- 对高频节点将其属性写入搜索索引（SearchIndex.keywords/content）以提升全文检索效果。

## 4. 关键代码改造建议（片段级思路）
- 参数解析与校验：
  - types = request.data.get('types', []); validate against allowed set
  - limit = min(int(options.get('limit', 50)), 200)
- 调用：
  - kg_service.search(query, user, types=types, limit=limit, offset=offset, scope=scope, include_edges=include_edges, timeout=8)
- 返回：
  - 添加 meta: { total_nodes, total_edges, page, page_size, has_more }
- 错误：
  - 区分 408 超时、429 超限、503 服务不可用等

—— 本次模块核查到此结束。建议优先落地“服务契约+权限与范围+分页与超时”的 P0 改造，以保证该功能在真实场景下可用且可控。
