# 同类产品功能差异及新增需求建议

说明：本文件在每次完成一个模块/功能核查后同步补充，按模块分类记录与3-5个竞品的差异与新增需求建议。

## 提醒模块（Reminder）
- 核查日期：2025-11-17
- 对标产品：
  - Apple Reminders（苹果提醒事项）：支持基于时间与位置的提醒、智能列表（按标签/时间/地点/优先级自动聚合）、子任务与附件、共享与分配、Siri/快捷指令；支持重复与“今天/计划”等智能分类。
  - Google Keep（及与Google日历联动）：支持时间与位置提醒、跨设备同步、与日历事件联动提醒；
  - Evernote（印象笔记）：支持提醒/重复提醒，部分版本支持与日历工具更紧密联动；
  - Notion：任务/提醒更多依赖日历/数据库视图，重复与自动化可通过集成实现；

- 本系统与竞品差异要点：
  1) 通道能力：
     - 本系统：预留邮件/推送/APNS/短信/WebSocket，但缺乏前端与配置管理的完备打通与默认落地（如未配置即降级）。
     - 竞品：移动端原生推送与系统级提醒强绑定，开箱即用稳定。
  2) 触发条件：
     - 本系统：时间型提醒+重复（天/周/月/年）；暂未实现位置提醒、对日历的强绑定、提前量个性化（仅默认15分钟）、“重复结束时间”未生效。
     - 竞品：普遍支持位置提醒、旅行/地理围栏、智能分组（今天/计划/已标记/共享）与灵活提前量。
  3) 组织与智能：
     - 本系统：具备priority/category/tags字段，但前端与后端的“智能列表/聚合视图”缺失。
     - 竞品：支持智能列表与聚合，自动分类与过滤，搜索/排序体验成熟。
  4) 协同与共享：
     - 本系统：暂未体现提醒共享/分配与协作。
     - 竞品：Apple Reminders/Google生态具备共享清单与成员分工。
  5) 日历联动：
     - 本系统：模型含calendar_event_id/calendar_id/last_sync_time，但未见完整的创建/更新/删除同步链路。
     - 竞品：与系统日历可无缝联动，编辑同步及时。

- 新增功能与落地建议：
  1) 位置型提醒（高优先级）
     - 场景：到达公司/家/超市触发待办；离开某地提醒带走物品。
     - 价值：提升提醒命中率与场景贴合度。
     - 建议：
       - 后端新增地理围栏字段（地点名称、经纬度、半径、触发方式到达/离开）；
       - 移动端接入系统定位/地理围栏API；
       - 权限与电量策略提示。
  2) 重复结束与跳过/贪睡（Snooze）
     - 场景：重复任务到特定日期终止；提醒到点后可“延后10/30/60分钟”。
     - 价值：避免无限通知，提升可用性。
     - 建议：
       - 启用repeat_end_date生效逻辑；
       - 新增snooze接口与通知重排（scheduled_time按延后策略重算）。
  3) 智能列表与聚合筛选
     - 场景：自动生成“今天/本周/逾期/高优先级/按标签”的视图。
     - 价值：提升检索效率与总览能力。
     - 建议：
       - 后端提供聚合查询API与固定过滤白名单；
       - 前端提供Smart List组件与可配置规则。
  4) 日历双向同步
     - 场景：在系统日历编辑事件可回写提醒，或在本系统创建提醒自动生成日历事件。
     - 价值：与用户主力时间管理工具协同。
     - 建议：
       - 明确支持的日历（iOS日历、Google Calendar）；
       - 建立双向同步的Webhook/回调与冲突解决策略（以更新时间为准/以来源为准）。
  5) 提前量与通知策略个性化
     - 场景：不同提醒设置不同提前量、重复策略与通知渠道组合。
     - 价值：减少打扰、提高命中。
     - 建议：
       - 模型层增加advance_minutes字段；
       - 用户级通知偏好细化到模块与优先级维度。
  6) 协作与共享提醒
     - 场景：共享清单，指定责任人，状态同步。
     - 价值：团队/家庭使用价值提升。
     - 建议：
       - 新增参与者/分配人字段与权限校验；
       - 通知联发与变更记录。

- 技术提示与参考：
  - Apple Reminders：支持时间/位置提醒与智能列表（标签/优先级/日期），官方资料显示在iOS端可创建基于位置的提醒与智能列表。
  - Google Keep/Calendar：时间与位置提醒、与日历联动提高可见性。
  - Notion/Evernote：通过数据库/集成可实现重复/日历联动，但多为进阶玩法。



## 搜索模块（Search）
- 核查日期：2025-11-17
- 对标产品：Notion（全文检索与数据库筛选）、Evernote（高级搜索语法）、Obsidian（强搜索语法与社区插件）、Apple Notes（对附件OCR与系统级检索集成）。
- 差异要点：
  1) 语义检索：竞品多无原生语义检索但生态丰富；本系统虽有TF‑IDF/向量检索代码，但向量一致性与数据层不统一导致不可用。
  2) 高级语法与筛选：竞品具备丰富的过滤器、保存的搜索与快捷入口；本系统缺保存搜索/语法操作符与可视化筛选面板。
  3) 附件与OCR：Apple Notes/Evernote支持附件文本检索；本系统尚未将附件/图片OCR产出纳入搜索索引。
- 新增需求建议：
  - 采用统一Embedding+向量库（FAISS/pgvector），提供“关键词+语义重排”的混合检索；
  - 定义高级搜索操作符（title:, tag:, type:, before:, after:, is:public 等）与“保存的搜索”；
  - 将OCR/语音转写结果写入SearchIndex.keywords/content；
  - 提供结果分面（按类型/标签/时间/作者）与排序选项。

## 同步模块（Sync）
- 核查日期：2025-11-17
- 对标产品：Apple Notes（iCloud多端同步）、Evernote（离线与冲突合并）、Notion（云端为准的协作与版本）。
- 差异要点：
  1) 冲突解决：竞品普遍有版本与冲突副本；本系统缺乐观锁/版本控制，覆盖风险高。
  2) 增量与压缩：竞品做delta/diff与批量；本系统逐条写入、无批量与delta。
  3) 安全：竞品在凭证/传输安全上成熟；本系统存在明文连接串与缺少服务端鉴权校验问题。
- 新增需求建议：
  - 引入版本/ETag与If‑Match比较；支持字段级或对象级合并策略；
  - 设计增量同步协议（变更游标/时间窗口），支持bulk_write与限流；
  - 强化安全（环境变量、最小权限、TLS、审计日志）。

## 笔记分享功能（Share）
- 核查日期：2025-11-17
- 对标产品：Notion（公开链接/域内限制/密码/到期）、Evernote（共享笔记/笔记本，权限控制）。
- 差异要点：
  1) 安全：竞品支持密码、到期、域限制与访问统计；本系统密码明文、分享码弱、无访问节流与审计。
  2) 模型一致性：竞品内部统一；本系统双ORM并存，易出错。
- 新增需求建议：
  - 分享码≥16位并唯一索引；密码哈希存储，错误次数与冷却；
  - 访问统计与审计（IP/UA 匿名化）；
  - 支持“仅组织内访问/仅受邀用户”。

## 笔记评论功能（Comment）
- 核查日期：2025-11-17
- 对标产品：Notion/Google Docs（行内评论、@提及、线程、解决、通知）。
- 差异要点：
  - 本系统缺@提及、通知、解决状态与权限联动；无分页和风控。
- 新增需求建议：
  - 引入线程化评论、@提及与通知；
  - 可配置是否允许在分享/协作场景评论；
  - 分页与速率限制，敏感词/长度校验。

## 笔记附件功能（Attachment）
- 核查日期：2025-11-17
- 对标产品：Evernote（附件OCR与预览）、Notion（多格式预览与上传限制）、OneNote（PDF打印稿批注）。
- 差异要点：
  - 本系统模型与视图对接不一致，预览/下载无流式与Range；无病毒扫描与MIME白名单；无缩略图。
- 新增需求建议：
  - 明确存储方案（GridFS/对象存储）并统一实现；
  - 限制大小与MIME，接入病毒扫描；
  - 生成缩略图与PDF首图预览，下载支持Range；
  - 将附件OCR结果接入搜索。

## 笔记版本功能（Version）
- 核查日期：2025-11-17
- 对标产品：Notion（版本历史）、Evernote（笔记历史）、Google Docs（版本命名/对比/恢复）。
- 差异要点：
  - 本系统模型与视图不匹配，当前版本标记/自动保存与恢复路径不完整；
- 新增需求建议：
  - 统一模型，提供差异查看/命名/标签；
  - 自动保存与保留策略（如90天）；
  - 恢复操作的审计与通知。

## 系统备份功能（Backup）
- 核查日期：2025-11-18
- 对标产品：
  - GitLab：一键备份为压缩包（tar/zip），包含数据库与附件；提供校验、计划任务、加密/外部存储配置与恢复流程；
  - MongoDB 官方工具（mongodump/mongorestore）与 Atlas 备份：支持增量/时间点恢复（PITR，企业/Atlas），支持大数据集分片与批处理；
  - Confluence/Atlassian：提供全量与空间级导出、定时计划、外部对象存储与加密；
  - Notion/Evernote：支持内容导出（Markdown/HTML/ENEX），但非数据库级别的系统全量备份；

- 本系统与竞品差异要点：
  1) 完整性与安全：
     - 本系统：ZIP 无哈希/签名/加密；导入时校验不严格。
     - 竞品：普遍提供 SHA 校验、压缩包签名、可选加密与外部存储（S3、对象存储）。
  2) 规模化能力：
     - 本系统：一次性读写，缺分页/批处理与游标，易内存暴涨；
     - 竞品：流式导出/分片、批量导入、失败重试与 ordered=false。
  3) 时间点与增量：
     - 本系统：仅全量快照类导出；
     - 竞品：提供增量/PITR 与计划任务，支持保留策略与清理。
  4) 类型还原与一致性：
     - 本系统：ObjectId 在恢复时未复原为原生类型；
     - 竞品：保持类型与索引一致，恢复后可自动重建索引。
  5) 审计与权限：
     - 本系统：缺细粒度权限与审计；
     - 竞品：区分备份/恢复/下载权限，记录操作审计与来源。

- 新增功能与落地建议：
  1) 完整性校验与加密
     - 生成 manifest.json（文件名/大小/SHA256），备份侧写入 .sha256；导入/恢复时强校验；
     - 提供可选压缩包加密（Zip AES/基于应用密钥的对称加密），管理密钥轮换。
  2) 批处理/流式与大数据集友好
     - 导出使用游标 batch_size（如2000）与分片 JSON/JSONL；
     - 恢复分批 insert_many（1000-5000/批，ordered=false），失败重试与统计。
  3) 增量与计划任务
     - 设计增量备份（按 updated_at/变更游标），并支持每日/每周计划；
     - 引入保留策略（retain_days）与自动清理；
     - 结合 MongoDB Oplog/Atlas PITR（如上云场景）。
  4) 类型与索引一致性
     - 恢复阶段将 _id 与白名单引用字段从字符串复原为 ObjectId；
     - 备份/恢复索引定义（可导出集合的索引信息并在恢复后重建）。
  5) 审计与权限
     - 细化权限：can_backup/can_restore/can_download；敏感操作需二次确认参数；
     - 记录操作审计（操作者、时间、集合数、大小、哈希、IP、结果）。
  6) 存储与可配置
     - 支持 backup.storage=local/s3，文件名包含备份ID与UTC时间；
     - 暴露 batch_size、encrypt、hash_verify、retain_days 等配置；
     - 下载接口提供 Content-Length/Etag，并记录下载审计。


## 分析与报表模块（Analytics）
- 核查日期：2025-11-18
- 对标产品：
  - Metabase：零SQL图形化问答、嵌入与权限、定时报表邮件、仪表盘交互过滤、简单RLS；
  - Apache Superset：SQL Lab、丰富图表与仪表盘、权限体系与嵌入、缓存；
  - Redash：多数据源查询编辑器、可视化面板、定时任务与告警、共享链接；
  - Grafana：多数据源、实时面板、告警、权限与团队、嵌入与插件生态。

- 本系统与竞品差异要点：
  1) 查询与可视化：
     - 本系统：固定报表逻辑，缺通用查询编辑器与图表配置；
     - 竞品：强查询编辑器（SQL/可视化）、字段选择、过滤器、丰富图表与即时预览。
  2) 调度与订阅：
     - 本系统：无定时生成与订阅推送；
     - 竞品：常规支持定时任务、邮件/消息推送、失败告警。
  3) 权限与共享：
     - 本系统：仅登录可用，缺细粒度权限与共享/嵌入；
     - 竞品：项目/空间/图表级别权限、共享链接、嵌入令牌、RLS。
  4) 缓存与性能：
     - 本系统：查询直打库、应用层聚合；
     - 竞品：查询结果缓存、增量刷新、异步执行、队列与并发控制。
  5) 告警：
     - 本系统：无；
     - 竞品：阈值/同比/环比告警，多渠道通知。

- 新增功能与落地建议：
  1) 查询与可视化平台化
     - 引入“数据源+查询模板+参数化+图表配置”的抽象；
     - 提供可视化编辑器与字段选择、过滤器、排序、聚合；
  2) 调度与订阅
     - 支持报表/仪表盘的定时任务与邮件/站内推送，失败重试与告警；
  3) 权限与共享
     - 报表/仪表盘/数据源的权限模型；支持共享链接与受控嵌入；
     - 行级权限在查询阶段注入过滤条件；
  4) 性能与缓存
     - 查询结果缓存（TTL/手动刷新）、大查询异步、任务队列与并发限流；
  5) 告警
     - 指标阈值、环比/同比规则与渠道（邮件/应用内/Webhook）。
