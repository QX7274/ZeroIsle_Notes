# 【搜索模块】优化实施记录

## 优化概述
根据《【搜索模块】核查详情与优化方案.md》中的建议，对搜索模块进行了全面优化，解决了ORM混用、向量空间不一致、性能问题等关键缺陷。

## 已完成的优化项

### 1. 统一数据访问层（mongodb_models.py & indexer_service.py）

#### 1.1 添加显示名称辅助方法
**问题**: SearchService 调用不存在的 get_index_type_display() 方法
**解决方案**:
- 在 SearchIndex (MongoEngine) 模型中添加 `get_index_type_display()` 方法
- 位置: mongodb_models.py 第61-63行
- 实现: 使用 dict(INDEX_TYPE_CHOICES).get() 返回显示名称

#### 1.2 统一 IndexerService 到 MongoEngine
**问题**: IndexerService 使用 Django ORM 的 SearchIndex，与 SearchService 使用的 MongoEngine SearchIndex 不一致
**解决方案**:
- 完全重写 indexer_service.py，移除 Django ORM 依赖
- 移除 `from django.contrib.contenttypes.models import ContentType`
- 移除 `from search.models import SearchIndex`
- 改为使用 `from search.mongodb_models import SearchIndex`
- 位置: indexer_service.py 第1-119行

**关键改动**:
1. content_type 改为使用类名字符串: `content_type = obj.__class__.__name__`
2. 使用 MongoEngine 的查询和保存方式:
   ```python
   # 查找现有索引
   index = SearchIndex.objects.get(content_type=content_type, object_id=str(obj.id))
   # 创建新索引
   index = SearchIndex(id=uuid.uuid4(), ...)
   index.save()
   ```
3. 删除操作改为 MongoEngine 方式:
   ```python
   deleted = SearchIndex.objects(content_type=content_type, object_id=str(obj.id)).delete()
   ```

### 2. 修复 SearchService 格式化方法（search_service.py）

#### 2.1 修复 _format_results 方法
**问题**: 调用 `result.content_type.model` 导致 AttributeError（content_type 是字符串字段）
**解决方案**:
- 直接使用 `result.content_type` 字符串
- 将 id 转换为字符串: `str(result.id)`
- 将 updated_at 转换为 ISO 格式: `result.updated_at.isoformat()`
- 位置: search_service.py 第331-365行

#### 2.2 修复 _format_results_with_scores 方法
**问题**: 同上，且 score 可能不是 float 类型
**解决方案**:
- 同样修复 content_type 引用
- 确保 score 为 float: `float(score) if score else 0`
- 位置: search_service.py 第367-401行

#### 2.3 修复 _record_search_results 方法
**问题**: 使用 Django ContentType，与 MongoEngine SearchResult 不兼容
**解决方案**:
- 移除 ContentType 依赖
- 直接使用字符串 content_type
- 添加 uuid 生成: `id=uuid.uuid4()`
- 添加异常处理，逐个保存结果
- 位置: search_service.py 第455-492行

### 3. 向量服务单例化与持久化（vector_service.py）

#### 3.1 实现单例模式
**问题**: 每个 VectorService 实例独立拟合，导致向量维度不一致
**解决方案**:
- 使用 `__new__` 方法实现单例模式
- 类级别共享 `_vectorizer`, `_is_fitted`, `_vocabulary_path`
- 位置: vector_service.py 第1-89行

**关键代码**:
```python
class VectorService:
    _instance = None
    _vectorizer = None
    _is_fitted = False
    
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super(VectorService, cls).__new__(cls)
            cls._instance._initialize()
        return cls._instance
```

#### 3.2 实现词表持久化
**问题**: 词表在进程重启后丢失，导致向量不可比
**解决方案**:
- 添加 `_load_vocabulary()` 方法，从文件加载词表
- 添加 `_save_vocabulary()` 方法，保存词表到文件
- 默认路径: `{BASE_DIR}/data/vector_vocabulary.pkl`
- 可通过 settings.VECTOR_VOCABULARY_PATH 配置
- 位置: vector_service.py 第66-89行

#### 3.3 优化 generate_vector 方法
**问题**: 每次调用都可能重新拟合，导致不一致
**解决方案**:
- 检查 `_is_fitted` 状态
- 未拟合时记录警告，建议先调用 `fit_corpus()`
- 作为降级方案，临时拟合当前文本并保存词表
- 添加空文本检查
- 位置: vector_service.py 第91-130行

#### 3.4 添加 fit_corpus 方法
**新功能**: 支持使用完整语料库拟合向量器
**实现**:
- 接受文本列表作为参数
- 使用 `vectorizer.fit(texts)` 拟合
- 自动保存词表
- 记录词汇量日志
- 位置: vector_service.py 第132-155行

#### 3.5 增强 calculate_similarity 方法
**问题**: 未检查向量维度一致性
**解决方案**:
- 添加空向量检查
- 添加维度一致性检查: `v1.shape[1] != v2.shape[1]`
- 维度不一致时返回 0.0 并记录警告
- 位置: vector_service.py 第157-187行

#### 3.6 添加辅助方法
**新增方法**:
- `is_fitted()`: 检查向量器是否已拟合
- `get_vocabulary_size()`: 获取词汇表大小
- 位置: vector_service.py 第189-197行

### 4. 性能优化（search_service.py）

#### 4.1 向量搜索性能优化
**问题**: 全量加载索引并逐条计算相似度，O(N) 复杂度
**解决方案**:
- 实现候选集预筛策略
- 限制最大候选集: `MAX_CANDIDATES = 1000`
- 设置相似度阈值: `SIMILARITY_THRESHOLD = 0.1`
- 有关键词时先用关键词筛选候选集
- 跳过低相似度结果
- 位置: search_service.py 第250-318行

**优化效果**:
- 从 O(N) 降低到 O(min(N, 1000))
- 减少内存占用
- 提升响应速度

#### 4.2 关键词搜索优化
**问题**: 无限制的 tokens 可能导致过多 OR 条件
**解决方案**:
- 限制最大 tokens 数量: `MAX_TOKENS = 10`
- 截断超出部分: `tokens = tokens[:MAX_TOKENS]`
- 位置: search_service.py 第220-253行

#### 4.3 参数验证与安全限制
**问题**: 缺少参数验证，可能被滥用
**解决方案**:
- 在 search() 方法中添加参数验证
- page 最小值为 1: `page = max(1, int(page))`
- page_size 限制在 1-100: `page_size = min(100, max(1, int(page_size)))`
- 调用 `_validate_filters()` 验证过滤条件
- 位置: search_service.py 第31-55行

#### 4.4 添加 _validate_filters 方法
**新功能**: 验证和清理过滤条件
**实现**:
- 检查 filters 是否为字典
- 验证 index_type 是否在有效选项中
- 过滤掉无效的 index_type
- 验证 is_public 为布尔值
- 位置: search_service.py 第190-220行

## 使用建议

### 初始化向量器
在系统启动时或首次使用前，建议使用完整语料库拟合向量器:

```python
from search.services.vector_service import VectorService

# 获取所有索引的文本
texts = []
for index in SearchIndex.objects.all():
    text = index.title
    if index.content:
        text += " " + index.content
    texts.append(text)

# 拟合向量器
vector_service = VectorService()
vector_service.fit_corpus(texts)
```

### 配置词表路径
在 settings.py 中配置:

```python
import os
VECTOR_VOCABULARY_PATH = os.path.join(BASE_DIR, 'data', 'vector_vocabulary.pkl')
```

## 未来优化方向

1. **搜索建议缓存**: 为热门搜索添加缓存（1分钟）
2. **高级搜索语法**: 支持 title:, tag:, type:, before:, after: 等操作符

1. **切换到 Sentence-BERT**: 使用预训练的语义模型，提升语义搜索质量
2. **向量数据库**: 集成 FAISS/pgvector/Milvus，支持大规模向量检索
3. **OCR 结果索引**: 将图片 OCR 和语音转写结果纳入搜索索引
4. **结果分面**: 提供按类型/标签/时间/作者的聚合统计
5. **搜索分析**: 记录点击率、停留时间等指标，优化排序

## 影响评估

### 正面影响
- 数据一致性：统一到 MongoEngine，消除 ORM 冲突
- 向量搜索可用：修复维度不一致问题
- 性能提升：候选集预筛大幅减少计算量
- 安全性提升：参数验证防止滥用
- 可维护性提升：单例模式和持久化简化管理

### 潜在风险
- 需要初始化词表（首次使用或数据变化后）
- 词表文件需要备份和版本管理
- 单例模式在多进程环境需要注意（每个进程一个实例）

## 回滚方案

- 可通过 Git 分支回滚
- 词表文件可删除，系统会自动重建
- 建议保留 Django ORM 模型文件作为备份（已废弃但不删除）
