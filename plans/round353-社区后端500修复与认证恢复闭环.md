# round353 社区后端500修复与认证恢复闭环

## 1. 本轮目标
- 延续 `round352` 之后的社区真机验收，优先把“看起来像网络问题、实际是后端/认证状态异常”的阻塞继续拆清楚。
- 在不误改成熟页面的前提下，继续验证并记录以下规范是否成立：
  - 顶部不被系统状态栏遮挡
  - 返回按钮统一使用已有淡蓝色方形箭头
  - 网络异常一律使用项目内统一样式弹窗，不使用默认安卓弹窗
  - 明显原始页面才调整，成熟部分不乱动
  - 真实数据不存在或后端失败时，只允许诚实承接，不伪造成功内容态

## 2. 本轮代码改动

### 2.1 社区帖子列表后端过滤兼容修复
- 文件：
  - `backend/community/views/post.py`
- 处理：
  - 去掉 `DjangoFilterBackend/filterset_fields` 对 MongoEngine QuerySet 的不兼容接入
  - 改为手工兼容 `category / status / is_pinned / is_featured / is_public`
- 目的：
  - 修复社区帖子接口在真实后端上因 QuerySet 兼容性问题导致的 `500`

### 2.2 社区关注接口分页与过滤兼容修复
- 文件：
  - `backend/community/views/follow.py`
- 处理：
  - 为 `ViewSet` 补齐：
    - `get_serializer`
    - `paginate_queryset`
    - `get_paginated_response`
  - 改为手工兼容 `content_type / is_active`
  - `following` 动作支持 `user_id`
- 目的：
  - 修复 `followers / following` 深层页在真实后端上的 `500` 与分页异常

### 2.3 认证恢复逻辑补齐
- 文件：
  - `src/redux/slices/authSlice.js`
- 处理：
  - 当开发联调模式下本地没有可用真实 token，且又不是 `SKIP_LOGIN_SCREEN=true` 的假登录路径时：
    - 自动尝试通过真实后端恢复开发态真实登录
    - 先发验证码
    - 再使用验证码直连登录
    - 恢复真实用户与真实 token
- 目的：
  - 避免平板因本地丢失认证态而被误判成“网络不通”
  - 避免社区页继续落成假性 `error`

### 2.4 评论接口分页缺失补齐
- 文件：
  - `backend/community/views/comment.py`
- 处理：
  - 为 `CommentViewSet` 补齐：
    - `get_serializer`
    - `paginate_queryset`
    - `get_paginated_response`
  - 去掉对 MongoEngine 不兼容的 `DjangoFilterBackend`
  - 改为手工兼容 `post / post_id / parent / parent__isnull / is_pinned`
- 目的：
  - 修复帖子详情页评论接口 `/api/v1/community/comments/by_post/` 的真实 `500`
