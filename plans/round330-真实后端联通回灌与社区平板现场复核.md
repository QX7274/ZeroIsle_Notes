# round330 - 真实后端联通回灌与社区平板现场复核

## 1. 本轮目标
- 把上一轮已经恢复的真实后端联通结果回灌到安卓平板真机，而不是只停留在本机接口层验证。
- 继续遵守既定页面规范，并把验证结果写入计划与台账：
  - 顶部风格统一；
  - 顶部不能被系统状态栏遮挡；
  - 返回按钮继续统一使用已有淡蓝色方形箭头；
  - 网络异常继续统一走项目内优美样式弹窗；
  - 不改成熟页面，只记录和处理明显原始或不一致的问题；
  - 重点检查社区页顶部状态栏、异常留白与发帖链闭环。
- 把开发环境默认 API 目标切换到当前已验证稳定的 `8001`，避免真机继续打到旧端口。

## 4. 真机现场复核结果

### 4.1 首页恢复正常渲染
- 重新拉起应用后，首页主内容可稳定渲染，不再停留在仅剩原生容器层的瞬时白屏。
- 现场证据：
  - `tmp_round330_reopen_screen.png`
  - `tmp_round330_reopen_ui.xml`
- 结论：
  - 当前首页内容区已经正常挂载；
  - 顶部安全区生效，内容从 `y=36` 开始，没有被平板系统状态栏压住；
  - 底部系统导航背景仅占 `1977-2000`，应用底部标签栏仍位于可视安全区内。

### 4.2 首页异常反馈样式复核
- 首页底部出现的是项目内样式化提示条：
  - `通知渠道创建失败，但应用将继续运行`
- 结论：
  - 当前看到的不是原生安卓弹窗；
  - “异常反馈继续统一走项目内样式”这一条本轮未被破坏。

### 4.3 社区页顶部安全区通过，但空态留白仍异常
- 已从底部 tab 真实进入 `社区` 页面。
- 现场证据：
  - `tmp_round330_community_screen.png`
  - `tmp_round330_community_ui.xml`
- 关键观察：
  - 页面顶部标题、搜索框、右上角操作按钮都没有被系统状态栏遮挡；
  - 页面头部起始高度正常，社区标题区在安全区之下；
  - 但是社区空态卡片结束后，到右下角 `发布` 按钮之间仍有很大一块不合理白区；
  - 这块留白不是系统栏遮挡，而是社区空内容态在平板大屏上的布局缺陷。
- 结论：
  - “顶部安全区”本轮通过；
  - “社区页仍存在异常留白，尤其空态场景”本轮继续记为活跃问题，不能误判为已彻底收口。

### 4.4 创建帖子页头部规范通过
- 已从社区右下角 `发布` 真实进入 `创建帖子` 页面。
- 现场证据：
  - `tmp_round330_publish_entry_screen.png`
  - `tmp_round330_publish_entry_ui.xml`
- 关键观察：

  - `发布` 按钮与标题 `创建帖子` 布局稳定；
  - 表单区仍为卡片化结构，没有再退回到更早期原始白板。
- 结论：
  - 发帖页头部规范、返回按钮统一规范本轮通过。

## 5. 发帖闭环现状

### 5.1 后端链已通
- 本机接口层已经确认 `POST /api/v1/community/posts/` 在 `8001` 返回 `201`。
- 本轮不再把“无法发帖”归因到后端网络不通。

### 5.2 真机自动化输入受第三方输入法干扰
- 在平板端尝试通过 `adb input text` 向标题框注入内容时，现场出现第三方输入法接管：
  - 首次仅稳定输入了部分内容；
  - 再次重试后成功输入了 `round330round330_post`，但自动化过程被输入法联想与焦点行为显著干扰。
- 现场证据：
  - `tmp_round330_publish_title_filled.png`
  - `tmp_round330_publish_title_retry.png`
- 结论：
  - 本轮“真机端没有自动完成整条发帖提交”不是网络故障；
  - 真实阻塞点是第三方输入法对 ADB 自动输入的干扰，属于真机自动化限制，应如实记录。
