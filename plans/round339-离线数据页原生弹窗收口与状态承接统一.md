# round339 离线数据页原生弹窗收口与状态承接统一

## 本轮目标
- 延续设置系深层页统一验收，优先处理 `离线数据` 页仍残留的原生弹窗问题。
- 继续遵守既定规范：
  - 顶部不得被平板系统状态栏遮挡
  - 返回按钮统一使用已有淡蓝色方形箭头
  - 设置深层页不得露出主底部 Tab
  - 网络/异常/确认提示尽量统一为项目内优美样式，不使用默认安卓弹窗
  - 只改明显原始实现，不破坏成熟卡片骨架

## 修复前确认到的真实问题

### 1. 离线数据页仍大量使用默认安卓弹窗
- 页面路径：
  - `我的 -> 应用设置 -> 离线数据`
- 真实问题：
  - `立即同步`
  - `重建搜索索引`
  - `清除离线数据`
- 上述动作中的成功、失败、确认仍直接走 `Alert.alert(...)`
- 这与前几轮已经逐步收口的设置系提示风格明显不一致，属于“看着就很原始”的页面实现。

### 2. 结果承接过度依赖弹窗
- 同步、重建、清除结果主要依赖弹窗承接，页内没有统一的状态卡片记录最近一次关键动作反馈。
- 在平板使用时，这类一次性系统弹窗中断感强，也不利于和已有设置页轻卡片体系保持一致。

## 本轮代码处理

### 1. 移除离线数据页默认安卓弹窗
- 修改文件：
  - `src/screens/settings/OfflineDataScreen.js`
- 本轮改动：
  - 移除 `Alert`
  - 引入项目内 `showToast`
  - 新增本地 `dialogState`
  - 用项目内一致的圆角确认弹层承接：
    - `重建搜索索引`
    - `清除离线数据`

### 2. 补齐页内状态承接
- 新增：
  - `statusCard`
  - `statusCardTone`
  - `statusCardStyles`
- 将下列动作的结果统一收口到 `Toast + statusCard`
  - 离线模式开关
  - 立即同步
  - 重建搜索索引
  - 清除离线数据
- 效果：
  - 成功/失败状态不再只靠一次性系统弹窗提示
  - 页内能持续看到最近一次关键动作结果

### 3. 保持既有成熟骨架不动
- 本轮继续保留：
  - 统一淡蓝色方形返回按钮
  - 顶部安全区承接方式
  - 现有浅蓝卡片分组骨架
  - 离线模式、同步状态、存储使用三大区块
- 仅收紧内容承接方式，不重做成熟版式。

## 本轮预期验收点
