## 本轮发现的问题

### 1. 首页底部仍有开发态技术提示条
- 现场现象：
  - 真机首页底部出现 `SplashScreen 超时未完成，触发初始化兜底放行`。
- 风险：
  - 这不是业务错误，但会污染后续真机验收判断。
  - 会和真正的项目内网络/失败提示抢同一块界面区域。

### 2. 社区页不再是“网络不通”，而是命中了真实后端500
- 现场现象：
  - 真机进入 `社区` 后，前台直接承接了 Django 调试页大段文本。
  - 核心报错为：
    - `ImportError at /api/v1/community/posts/`
    - `cannot import name 'GroupMember' from 'community.mongodb_models'`
- 说明：
  - 这证明平板和电脑后端之间的通讯已经打通。
  - 当前阻塞已从“网络问题”切换为“后端真实接口错误”。

### 3. 社区错误承接仍存在被调试页原文击穿的风险
- 现场现象：
  - 前台虽然已有中文错误映射与页内 `errorBanner`，但当后端直接返回 Django 调试页文本时，整段技术内容仍可能被当成字符串承接到界面。
- 风险：
  - 会直接泄露开发调试栈、路径和内部实现细节。
  - 不符合“统一项目内中文错误提示”和“不可暴露技术文案”的上线规范。

## 本轮代码修改

### A. 启动噪声进一步静默收口
- 文件：
  - `src/App.js`
- 修改内容：
  - 将以下非致命启动降级提示纳入开发态 suppress 与 `LogBox.ignoreLogs(...)`：
    - `SplashScreen 超时未完成，触发初始化兜底放行`
    - `SplashScreen 兜底初始化失败:`
    - `PersistBootstrapGate: 持久化恢复超过`
    - `PersistBootstrapGate: 当前以降级模式继续启动`
- 目标：
  - 这类“技术兜底已生效，但应用仍可继续运行”的日志不应再抢占真机界面提示位。

### B. 修复社区后端真实500的根因
- 文件：
  - `backend/community/services/permission_service.py`
- 修改内容：
  - 将错误导入：
    - `from ..mongodb_models import Post, GroupMember`
  - 改为：
    - `from ..mongodb_models import Post`
    - `from groups.mongodb_models import GroupMember`
- 说明：
  - `GroupMember` 的真实定义位置在 `backend/groups/mongodb_models.py`。
  - 旧导入路径错误，导致社区帖子列表首屏请求直接 500。

### C. 社区错误映射增加“调试页文本屏蔽”
- 文件：
  - `src/redux/slices/communitySlice.js`
- 修改内容：
  - 为社区错误解析增加 `devErrorSignals` 检测：
    - `Traceback (most recent call last)`
    - `ImportError at `
    - `Exception Type:`
    - `<!DOCTYPE html`
    - `<html`
  - 当后端返回字符串或嵌套 message/detail 中命中上述调试页特征时：
    - `5xx -> 社区服务暂时不可用，请稍后刷新重试`
    - 其他情况退回调用方 `fallbackMessage`
- 目标：
  - 即便后端再次返回 Django 调试页或 HTML 错误页，前台也只允许显示中文业务文案。
