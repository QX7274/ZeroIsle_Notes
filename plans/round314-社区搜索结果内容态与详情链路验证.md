# round314 社区搜索结果内容态与详情链路验证

## 目标
- 基于 round313 已修复的社区搜索承接页，继续补齐社区搜索“内容态”真机验证。
- 优先验证两条关键链路：
  - `CommunitySearch -> 用户结果 -> UserProfile`
  - `CommunitySearch -> 帖子结果 -> PostDetail`
- 若后端当前没有可用真实帖子，则必须诚实降级为项目内统一样式提示，不允许再放行到失效详情页。

## 本轮真机验证结论

### 1. 搜索用户结果内容态已跑通
- 本轮在社区页开发联调区增加 `搜索用户结果` 入口，用于在后端社区搜索数据长期为空时，仍能稳定打开搜索结果内容态页面。
- 真机点击后，已成功进入 `社区搜索` 结果页，并显示 1 条用户结果卡片。
- 继续点击该用户结果卡片后，已成功进入社区个人主页。
- 个人主页顶部安全区正常，统一淡蓝色方形返回按钮正常，页面未被系统状态栏遮挡。
- 结论：
  - `CommunitySearch -> 用户结果 -> UserProfile` 当前已真机跑通。
  - round312 修复的社区个人主页路由和顶部样式，在搜索结果入口下也成立。

### 2. 搜索帖子结果当前走诚实降级，不再误跳失效详情页
- 本轮同步增加 `搜索帖子结果` 联调入口。
- 入口逻辑会先尝试从当前列表、缓存与即时拉取结果中解析真实可用的帖子详情；只有命中可访问帖子时，才允许进入搜索帖子结果内容态。
- 当前真机现场中，后端仍未提供可正常打开的帖子详情，因此没有继续硬跳 `PostDetail`。
- 页面展示的是项目内统一样式确认弹窗，而不是默认安卓原生弹窗，主文案明确说明：
  - 当前未命中可用帖子详情；
  - 已阻止进入失效结果链路；
  - 需要稍后重试或先确认后端存在有效帖子。
- 结论：
  - `CommunitySearch -> 帖子结果 -> PostDetail` 这一条本轮尚未拿到真实内容态证据。
  - 但当前降级行为正确，已经避免再次把“后端无有效帖子”误表现成“帖子详情页本身故障”。

  - 保持现有社区页成熟头部、分类区、发布按钮和底部导航不变，仅扩展开发联调区。
