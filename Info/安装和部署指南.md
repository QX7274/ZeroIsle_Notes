## 开发环境配置

### 系统要求

- **操作系统**：Windows 10/11、macOS 10.15+、Ubuntu 20.04+
- **内存**：至少8GB RAM（推荐16GB以上）
- **存储**：至少10GB可用空间
- **处理器**：现代多核处理器

### 必要软件

1. **Node.js**：版本18.0.0或更高
   ```bash
   # Windows使用官方安装包
   # macOS使用Homebrew
   brew install node
   # Ubuntu
   curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
   sudo apt-get install -y nodejs
   ```

2. **Yarn**：版本1.22.0或更高
   ```bash
   npm install -g yarn
   ```

3. **Python**：版本3.10或更高
   ```bash
   # Windows使用官方安装包
   # macOS
   brew install python@3.10
   # Ubuntu
   sudo apt install python3.10 python3.10-venv python3.10-dev
   ```

4. **Git**：最新版本
   ```bash
   # Windows使用官方安装包
   # macOS
   brew install git
   # Ubuntu
   sudo apt install git
   ```

5. **React Native环境**：
   - 按照[React Native官方文档](https://reactnative.dev/docs/environment-setup)配置环境
   - 选择"React Native CLI Quickstart"选项
   - 根据您的操作系统和目标平台(Android/iOS)按步骤操作

## 后端安装

### 创建虚拟环境

```bash
cd backend

```

### 安装依赖

```bash
pip install -r requirements.txt
```

### 后端环境变量与服务启动

1) 在 `backend/.env` 配置关键变量（示例见 `backend/.env.example`）

- 文档转换与对象存储
  - OBJECT_STORAGE_PROVIDER=none|s3|minio
  - AWS_S3_BUCKET_NAME=your-bucket
  - AWS_S3_ENDPOINT_URL=https://s3.example.com   # MinIO/私有S3需要
  - AWS_S3_REGION_NAME=your-region
  - AWS_ACCESS_KEY_ID=your-ak
  - AWS_SECRET_ACCESS_KEY=your-sk
  - LIBREOFFICE_PATH=libreoffice  # 或 soffice 实际路径
  - PANDOC_PATH=pandoc
  - DOC_CONVERTER_MODE=lite       # 可选：lite|loffice
  - MAX_UPLOAD_MB=20
  - DOWNLOAD_TOKEN_TTL_SECONDS=600
  - CONVERSION_SOFT_LIMIT=240     # Celery 软超时（秒）
  - CONVERSION_HARD_LIMIT=300     # Celery 硬超时（秒）
  - DOC_CONVERTER_MAX_PAGES=200   # 0 表示不限制
  - DOC_CONVERTER_VIRUS_SCAN=false
  - CLAMAV_HOST=127.0.0.1
  - CLAMAV_PORT=3310

- Redis/Celery（已在 settings 中默认指向本地）
  - REDIS_HOST=127.0.0.1
  - REDIS_PORT=6379
  - CELERY_BROKER_URL=redis://localhost:6379/0
  - CELERY_RESULT_BACKEND=redis://localhost:6379/0

2) 启动依赖服务

- 启动 Redis（本地或容器）
- 启动 Celery Workers（在 backend 目录）

为了隔离任务，项目配置了两个队列：`default` 用于常规任务，`heavy_tasks` 用于耗时的文档转换。您需要为每个队列至少启动一个 worker。

**启动默认队列的 Worker:**
```bash
# 终端 1
celery -A backend.celery worker -l info -Q default
```

**启动文档转换队列的 Worker:**
```bash
# 终端 2
celery -A backend.celery worker -l info -Q heavy_tasks -c 2 # -c 2 表示并发数为2，请根据CPU核心数调整
```

**启动 Celery Beat (用于定时任务):**
```bash
# 终端 3
celery -A backend.celery beat -l info
```

3) 运行环境自检（可选）

```bash
python scripts/check_env.py
```

该脚本会检查：Redis/Celery 环境变量、LibreOffice 与 Pandoc 路径可用性、python-magic/pdf2image、对象存储配置完整性、MEDIA_ROOT 可写权限等。

### 文档转换模式说明

- lite 模式：优先对文本类（md/markdown/txt/html/htm）文件使用 pandoc 转 PDF，失败时回退 LibreOffice；其他类型直接走 LibreOffice。
- loffice 模式：统一通过 LibreOffice/soffice 进行转换，适合高保真需求（依赖 sofﬁce 命令可用）。

### 病毒扫描（可选）

- 设置 `DOC_CONVERTER_VIRUS_SCAN=true` 并配置 `CLAMAV_HOST/CLAMAV_PORT` 后，上传与 Base64 路径会调用 ClamAV 扫描。
- 若检测到感染，接口返回 422 与签名（signature）；若扫描服务不可用，将宽松放行并记录 warning 日志。

## 生产环境部署

### 后端部署

1. **环境自检 (重要)**

在启动服务前，务必运行环境自检脚本，确保所有依赖和服务都已正确配置。

```bash
# 在 backend 目录下
python scripts/check_env.py
```

**请根据脚本输出解决所有 `[FAIL]` 项后再继续下一步。** 常见问题排障见下文。


1. **使用Gunicorn和Nginx**

```bash
# 安装Gunicorn
pip install gunicorn

# 启动Gunicorn
gunicorn backend.wsgi:application --bind 0.0.0.0:8000 --workers 3 --timeout 120
```

2. **Nginx配置示例**

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location /static/ {
        alias /path/to/your/static/files/;
    }

    location /media/ {
        alias /path/to/your/media/files/;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

3. **使用Supervisor管理进程**

```ini
[program:zeroislenotes]
command=/path/to/venv/bin/gunicorn backend.wsgi:application --bind 0.0.0.0:8000 --workers 3 --timeout 120
directory=/path/to/backend
user=www-data
autostart=true
autorestart=true
redirect_stderr=true
stdout_logfile=/var/log/zeroislenotes.log
```

## 常见问题

### 依赖安装问题

**问题**：安装React Native依赖时出错
**解决方案**：
```bash
# 清除缓存并重新安装
yarn cache clean
rm -rf node_modules
yarn install
```

**问题**：文档选择器依赖冲突
**解决方案**：
```bash
# 移除冲突的依赖
yarn remove react-native-document-picker
# 确保使用正确的依赖
yarn add @react-native-documents/picker
# 清理并重新安装
cd android && ./gradlew clean && cd ..
cd ios && pod install && cd ..
```

### iOS构建问题

**问题**：Pod安装失败
**解决方案**：
```bash
cd ios
pod deintegrate
pod setup
pod install
```

### Android构建问题

**问题**：Gradle构建失败
**解决方案**：
```bash
cd android
./gradlew clean
cd ..
yarn android
```

### 后端连接问题

**问题**：前端无法连接到后端API
**解决方案**：
1. 检查API URL配置是否正确
2. 确保后端服务正在运行
3. 检查网络设置和防火墙配置

### 环境自检与排障

**问题**：`python scripts/check_env.py` 报告 `[FAIL]`
**解决方案**：根据失败项，参考下表进行排查。

| 检查项 | 失败原因 | 解决方案 |
| :--- | :--- | :--- |
| **Redis Connection** | Redis服务未启动、地址/端口错误、防火墙拦截 | 1. 确保Redis服务正在运行 (`redis-cli ping` 应返回 `PONG`)。<br>2. 检查 `.env` 中的 `REDIS_HOST` 和 `REDIS_PORT` 配置是否正确。 |
| **Celery Broker/Backend** | Redis连接问题或Celery配置错误 | 同上，确保Redis连接正常。 |
| **LibreOffice Path** | `libreoffice`/`soffice` 不在系统PATH中，或路径配置错误 | 1. 确保已安装LibreOffice。<br>2. 将其可执行文件路径添加到系统环境变量 `PATH` 中。<br>3. 或在 `.env` 中通过 `LIBREOFFICE_PATH` 指定完整路径 (`soffice` 在容器环境中更常见)。 |
| **Pandoc Path** | `pandoc` 不在系统PATH中，或路径配置错误 | 1. 确保已安装Pandoc。<br>2. 将其可执行文件路径添加到系统环境变量 `PATH` 中。<br>3. 或在 `.env` 中通过 `PANDOC_PATH` 指定完整路径。 |
| **python-magic Library** | `python-magic` 未安装或其依赖的 `libmagic` 库缺失 | 1. `pip install python-magic`。<br>2. (Linux/macOS) 安装 `libmagic`：`sudo apt install libmagic1` 或 `brew install libmagic`。 |
| **pdf2image Dependencies**| `poppler` 未安装 | 1. (macOS) `brew install poppler`。<br>2. (Linux) `sudo apt install poppler-utils`。<br>3. (Windows) 下载Poppler并将其 `bin` 目录添加到系统PATH。 |
| **Object Storage Config** | `OBJECT_STORAGE_PROVIDER` 设为 `s3` 或 `minio`，但缺少相关密钥配置 | 在 `.env` 中补全 `AWS_S3_BUCKET_NAME`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` 等必要配置。 |
| **MEDIA_ROOT Writable** | Django媒体目录 (`/backend/media`) 不存在或无写入权限 | 1. 确保 `/backend/media` 目录存在。<br>2. 检查运行服务的用户是否对该目录有写入权限 (`chmod -R 755 media`)。 |

4. 对于Android模拟器，使用`10.0.2.2`代替`localhost`
