# 系统优化执行宪章

> 目标：约束“如何做”，用于指导持续自我完善。  
> 事实记录请写入：[全系统优化执行总台账](D:/ZeroIsle_Notes/docs/全系统优化执行总台账.md)

## 1. 总原则
- 先保功能完整，再做视觉深挖；P0 问题优先级最高。
- 改动遵循最小侵入原则：不为重构而重构。
- 每次改造必须可验证、可回归、可回滚定位。

## 2. Code Review 红线（必须满足）
- 所有问题必须绑定到页面ID和子功能，不接受“模块级空泛描述”。
- 输出顺序固定：P0 -> P1 -> P2。
- 每条问题必须含：复现条件、用户影响、风险等级、建议修复点。
- 若未给出证据路径，问题仅可标注为“待确认”，不得进入“已修复”。

## 3. RTK 与状态治理标准（必须满足）
- 保持现有 RTK 架构，不引入无收益的新全局状态层。
- 异步交互统一三位一体：
- 函数级 guard（防重入）
- UI disabled（防误触）
- 可见反馈（loading/success/error）
- 禁止“仅 UI 禁用不做函数短路”或“仅函数短路不做 UI 禁用”。
- 跨页共享状态变更必须附带最小回归测试。

## 4. UI/UX 统一标准（ui-ux-pro-max）
- 视觉基线：蓝白体系 + 轻毛玻璃（半透明白卡、浅蓝边框、柔和阴影）。
- 禁止重灰黑主导卡片、过度渐变、过强炫光。
- 所有页面统一状态语义：empty/loading/error/success。
- 可读性红线：关键文字对比度必须可读，交互热区满足移动端点击需求。
- 新增/修改样式优先复用 theme/tokens，不新增散落硬编码。

## 5. 安卓真机验收标准（强制）
- 每个页面至少一组真机证据（`png+xml`），关键失败场景补 `logcat`。
- 每个子功能至少覆盖成功分支与失败分支。
- 验收脚本执行失败时不得跳过，应记录 BLOCKED 原因与替代证据方案。
- 任何标记 `DONE` 的功能都必须有证据路径和测试结果。

## 6. 文档更新协议
- 每轮改造后必须同步更新三处：
- `docs/页面能力矩阵.md`（状态）
- `docs/全系统优化执行总台账.md`（事实）
- 对应轮次记录（过程）
- 文档若出现乱码或重复段落，优先修复编码与结构，再继续功能改造。

## 7. 失败复盘模板（每轮选填高风险项）
| 字段 | 内容 |
|---|---|
| 现象 | 失败表现与触发条件 |
| 根因 | 技术原因（状态、并发、依赖、UI） |
| 漏检点 | 为什么在前一轮没发现 |
| 修复动作 | 本轮已实施措施 |
| 防再犯 | 新增规则/测试/脚本守卫 |

## 8. 完成判定
- P0 为 0，且核心回归通过。
- P1 均有明确计划且不阻断主链路。
- 页面矩阵、总台账、轮次记录三者一致。
