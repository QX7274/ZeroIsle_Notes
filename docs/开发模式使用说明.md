# 开发模式使用说明

## 概述

为了方便开发调试，项目已添加了开发模式功能，可以在开发环境下跳过登录步骤，直接进入应用进行使用和调试。

## 当前开发与真机测试约定（2026-07-15）

- Python 后端、脚本和测试统一使用 Conda 环境 `ZeroIsle`。Windows 当前安装目录为 `D:\APP\Anaconda`；PowerShell 未注册 `conda` 时使用 `D:\APP\Anaconda\condabin\conda.bat run -n ZeroIsle ...`，不要用系统 Python 或仓库 `.venv` 作为验收依据。
- 功能验收以 Android 平板真机为准，优先使用 USB + `adb reverse tcp:8081 tcp:8081`；模拟器不作为最终验收设备；Android 主链统一使用 `yarn android`。
- 登录、注册、验证码和第三方登录不属于本轮测试范围。启动后直接使用本地配置的开发者账号进入软件，再进行登录后的功能开发和测试。
- 开发者账号的密码只允许存在于本地安全配置或开发环境中，不能写入文档、代码仓库、截图和日志；前端直登使用 \`ZEROISLE_DEV_PASSWORD\`，后端开发认证使用 \`ZEROISLE_DEV_USER_PASSWORD\`；生产构建必须关闭开发态跳过登录/直登能力。
- `DJANGO_ENV=testing` 默认使用 `mongomock`，适合测试和最小契约检查；它会关闭开发认证中间件，不能用 `dev-token` 伪造社区/AI成功登录态。真实 API 成功验收需要本地安全开发者凭据、有效 JWT 和真实依赖服务。

## 功能特性

- ✅ Debug 构建下自动跳过登录界面并设置开发者用户状态
- ✅ 本地 Realm 可用于离线页面和本地数据调试
- ✅ 支持使用真实平板、Metro 和 ADB 反向端口联调
- ⚠️ 需要后端的功能仍依赖 API、认证令牌和外部服务就绪；开发者直达不等于服务端已认证

## 配置说明

### 主配置文件

当前实现位于 `src/config/index.js`、`src/services/auth/devSessionRestore.js` 和 `android/app/build.gradle`：

```javascript
export const DEV_MODE_CONFIG = {
  ENABLED: __DEV__ && true,
  FEATURES: { SKIP_LOGIN_SCREEN: true },
  DEV_ACCOUNT: { username: 'developer', nickname: '开发者' },
};

// 真实开发者直登只读取本地环境变量；密码不写入代码或文档。
const password = process.env.ZEROISLE_DEV_PASSWORD || '';
```

Debug 构建由 `android/app/build.gradle` 的 `debuggableVariants = ["debug"]` 保持 `__DEV__=true`；Release 构建不得启用跳过登录或开发者直达。修改配置后必须重新执行 `yarn android`。

### 开发/生产边界

- 开发态：使用 `yarn android`，直接进入开发者账号上下文，不测试登录、注册和验证码。
- 后端开发态：`DJANGO_ENV=development` 才加载 `DevAuthMiddleware`；密码由 `ZEROISLE_DEV_USER_PASSWORD` 提供。
- 测试态：`DJANGO_ENV=testing` 使用 `mongomock` 并关闭开发认证中间件，适合 pytest 和健康/契约检查，不代表社区/AI真实认证成功。
- 生产态：必须关闭 `__DEV__`、跳过登录和开发认证中间件，并使用外部生产密钥。

## 使用方法

### 1. 启动应用

```bash
yarn android
```

当开发模式启用时，应用会：
- 自动跳过登录屏幕
- 设置默认开发用户
- 直接进入主界面

### 1.1 启动本地共享链联调入口

当需要为“群组/协作 -> 屏幕共享”做本地双端联调时，当前仓库默认不要直接假设 Electron 或 React Native Web 主应用已经完整闭环，而是先启动本地联调壳：

```bash
yarn local:web
```

启动成功后可访问：

- `http://127.0.0.1:8091/shared-screen-lab/`
- `http://127.0.0.1:8091/index.html`

说明：

- `shared-screen-lab` 是批次05新增的本地共享链诊断页，用于汇总群组 ID、共享会话 ID、WebRTC 房间、连接现象与关键时间线，并支持复制联调摘要。
- 该入口的目标是把 `localhost:8091` 收敛成稳定可访问的本地联调入口，同时把 `localhost:8081` 留给 React Native Metro，降低共享链和真机调试的互相干扰。
- 该入口不等同于 React Native Web 主应用已补齐，也不等同于 Android 专用 MCP 真机可视化验证完成。
- Android 主链仍然统一使用 `yarn android`；真机调试继续优先使用 USB + `adb reverse tcp:8081 tcp:8081`。

### 1.2 启动共享链最小 API 联调脚本

当需要在真机前先确认“群组、共享 HTTP 契约”是否可达时，统一使用正式脚本，不再继续依赖临时 `tmp_*` 调试文件：

```bash
cd backend
conda run -n ZeroIsle python scripts/shared_screen_smoke.py --base-url http://127.0.0.1:8001/api/v1
```

推荐前置：

- `DJANGO_ENV=testing`，用于最小契约联调，默认走 `mongomock`
- 若要验证更接近真实共享链的 HTTP 路径，再切到 `DJANGO_ENV=development` 并自行准备 MongoDB

说明：该脚本内部仍会自动创建临时账号并完成一次鉴权，这是脚本自举所需的技术前置，不代表登录/注册功能验收。按当前验收口径，Android 平板上的功能测试直接使用本地开发者账号进入软件，不执行登录、注册和验证码测试。

脚本默认验证：

- `POST /api/v1/groups/`
- `POST /api/v1/groups/{id}/generate-join-code/`
- `POST /api/v1/groups/shared-screens/`
- `GET /api/v1/groups/shared-screens/`
- `GET /api/v1/groups/shared-screens/{id}/join/`

边界说明：

- 该脚本只证明共享 HTTP 最小契约链路可达
- 不等同于 WebRTC 端到端联调完成
- 不等同于 Android 专用 MCP 真机可视化验证完成

### 2. 控制台日志

启用开发模式后，日志只能记录非敏感状态，不得记录密码、完整令牌或连接字符串：

```
🔧 开发模式已启用
📝 跳过登录: 是
👤 开发用户: developer
Redux: 开发模式 - 跳过认证检查，自动设置为已认证
Realm数据库打开成功
```

## 工作原理

### 1. 配置检查

应用启动时读取 `DEV_MODE_CONFIG`，Debug 下由 `__DEV__` 和 `FEATURES.SKIP_LOGIN_SCREEN` 决定是否直接进入主界面：

```javascript
// 在 src/App.js 中
const { DEV_MODE_CONFIG } = require('./config');
const skipLogin = __DEV__ && DEV_MODE_CONFIG.FEATURES.SKIP_LOGIN_SCREEN;
```

### 2. 认证状态管理

Redux 使用本地开发者用户上下文；这不是可访问后端的 JWT。需要服务端成功响应时，必须配置真实开发者会话。

```javascript
// 在 src/redux/slices/authSlice.js 中
if (skipLogin) {
  // 使用 DEV_MODE_CONFIG.DEV_ACCOUNT 设置已认证的本地开发上下文。
  // 不在这里生成或记录伪造的服务端 JWT。
}
```

### 3. 服务端联调边界

`DevAuthMiddleware` 只在 `DJANGO_ENV=development` 且 `DEBUG=True` 时加载，并只接受开发令牌前缀；`DJANGO_ENV=testing` 会移除该中间件。开发者直达只解决“进入软件”的测试前置，不替代后端认证、MongoDB、Redis 或 Neo4j 的就绪检查。

## 注意事项

1. **仅在开发环境有效**：开发模式功能只在 `__DEV__` 为 `true` 时生效
2. **生产环境自动禁用**：在生产环境构建时，开发模式功能会被自动禁用
3. **数据隔离**：开发模式使用的是模拟数据，不会影响真实用户数据
4. **网络边界**：本地笔记页面可离线调试；社区、AI、同步和服务端搜索等功能必须单独验证网络、认证和依赖就绪

## 故障排除

### 问题1：开发模式未生效

**解决方案**：
1. 确认执行的是 Debug `yarn android`
2. 确认当前 `__DEV__` 为 `true`，并检查 `screen.home` UI XML
3. 重新运行 `yarn android`

### 问题2：应用仍然显示登录界面

**解决方案**：
1. 检查控制台日志，确认开发模式日志是否出现
2. 清除应用缓存：`yarn android --reset-cache`
3. 重新安装应用

### 问题3：想要恢复正常登录流程

**解决方案**：
1. 使用生产/非 Debug 构建验证登录界面
2. 不要在生产构建中保留 `SKIP_LOGIN_SCREEN` 或开发认证中间件
3. 重新执行 Release 配置、密钥和静态扫描门禁

## 自定义开发用户

如需修改开发者用户的非敏感展示字段，只能修改 `DEV_MODE_CONFIG.DEV_ACCOUNT`；密码仍必须通过环境变量注入：

```javascript
// 在 src/config/index.js 中修改非敏感字段
DEV_ACCOUNT: {
  id: 'your-dev-user-id',
  username: 'your-username',
  email: 'your-email@example.com',
  nickname: '您的昵称',
  // ... 其他非敏感字段
},
```

这样就可以实现在开发调试时跳过登录，直接进入应用进行使用和调试了
