# 发布物与管理后台解耦说明（阶段5）

> 版本：v1.0（2026-10-04）
> 分支：`feature/release-decoupling`
> 目的：确认产品发布物不会带上管理后台（admin_system），并记录 Electron 打包链路的一处悬空缺陷。

---

## 0. 结论摘要

| 发布物 | 是否含 admin_system | 依据 | 判定 |
|---|---|---|---|
| Android APK/AAB | **否** | Metro `blockList` 排除 + 入口仅指向 `src/App` | ✅ 安全 |
| iOS IPA | **否** | 同上（共用 Metro 配置） | ✅ 安全 |
| Docker 生产镜像 | **否** | `Dockerfile` 只 `COPY backend/ .` | ✅ 安全（但构建上下文仍含它，见 1.2） |
| Electron 桌面包 | **否**（结构上不含） | `electron-builder.yml` 只收 `electron/**` + `web-build/**` | ✅ 安全，但另有悬空缺陷 |
| 结题/源码提交包 | **是**（期望如此） | `generate_submission_code_zip.py` 显式包含 | ✅ 符合预期 |

**一句话**：管理后台不会被任何产品发布物带走；但它自己目前也发布不了（后端刚在阶段2 修好，前端仍无法连上后端）。另发现 Electron 打包链路存在一处与 admin_system 无关的独立缺陷（见第 3 节）。

## 1. 逐项核实（含文件:行号）

### 1.1 Android / iOS：Metro 打包边界

- `metro.config.js:33` — `excludedRoots` 列表包含 `admin_system`。
- `metro.config.js:17-54` — 共 36 个排除项（含 `backend`、`web`、`docs`、`android`、`ios` 等）。
- `index.js:84` — App 入口仅 `require("./src/App")`，不存在指向 `admin_system` 的 import 边。
- `package.json` 的 `bundle:verify` 使用 `--entry-file index.js`。

**双重保证**：即便 blockList 失效，没有 import 边也扫不到；即便有 import 边，blockList 也会拦下。

### 1.2 Docker 生产镜像

- `Dockerfile:48` — `COPY backend/ .`（仅主后端目录）。
- `Dockerfile:22` — `COPY backend/requirements.txt .`。
- `docker-compose.prod.yml` — build context 虽为仓库根，但指定 `dockerfile: Dockerfile`，实际拷贝范围仍由 Dockerfile 决定。

**结论**：`admin_system` 目录根本不会进入镜像层。

**但需注意一层细节**（由独立复核补充）：仓库根**没有 `.dockerignore`**。

```bash
$ ls -la .dockerignore
（不存在）
```

因此 docker 构建上下文仍会把 `admin_system` 一起发送给 daemon。
最终镜像不含它只是因为 `Dockerfile:48` 只 `COPY backend/`；
但上下文体积与构建传输时间仍被这部分浪费。
若后续要彻底解耦，建议补一个 `.dockerignore` 显式排除
`admin_system/`、`node_modules/`、`.git/` 等。

### 1.3 Electron 桌面包

- `electron-builder.yml:12-14` — `files` 仅收录 `electron/**/*` 与 `web-build/**/*`。
- `electron/main.js:63-68` — dev 走 8081，prod 走 `../web-build/index.html`。

**结论**：`admin_system` 不在收录范围内，不会被打包。

### 1.4 结题/源码提交包（期望包含）

- `scripts/generate_submission_code_zip.py:43` — `ROOT_DIRS` 显式列出 `admin_system`。
- `scripts/generate_closing_materials.py:436` — 同样包含。

**结论**：这是期望行为（源码提交需要完整代码），本轮不做改动。

## 3. 发现的独立缺陷：Electron web-build 悬空

### 3.0 更早的一层阻塞：electron-builder 根本没有被安装

在讨论 `web-build` 之前，先记一条**更早**的失败点（由独立复核补充）：

```bash
$ grep -n "electron" package.json
26:    "dist": "electron-builder"

$ ls -d node_modules/electron-builder
（不存在）

$ grep -c "^electron-builder@\|^\"electron-builder" yarn.lock
0
```

即：`package.json:26` 声明了 `"dist": "electron-builder"`，但 `electron` 与
`electron-builder` **从未出现在 dependencies / devDependencies 中**，
`yarn.lock` 里也没有该包（仅有 electron-to-chromium）。

**影响**：实际执行 `yarn dist` 会先在「命令不存在」这一步失败，
**根本走不到 `web-build` 缺失**。因此本节描述的是两层依次独立的阻塞，
修复时需按顺序处理：先补依赖，再解决 `web-build` 产物来源。

### 3.1 现象

- `electron-builder.yml:14` 要求打入 `web-build/**/*`；
- `electron/main.js` 在非 dev 模式加载 `../web-build/index.html`
  （本次修改前位于第 67 行，修改后该调用已移至第 88 行）；
- 但仓库中不存在 `web-build` 目录，且没有任何脚本生成它：

```bash
$ ls -d web-build
web-build MISSING

$ grep -rn "web-build" --include="*.json" --include="*.js" --include="*.yml" . \
    --exclude-dir=node_modules --exclude-dir=.git
./electron-builder.yml:14:  - web-build/**/*
```

（上述行号取自修改前的文件；本次修改后 `loadFile` 已移至 `electron/main.js:88`，
引用时请以文件当前内容为准，避免行号漂移造成误判。）

`package.json` 中也没有任何构建 `web-build` 的脚本。

### 3.2 影响

分两层（由先到后）：

1. `yarn dist` 先在「`electron-builder` 命令不存在」处失败（见 3.0）；
2. 即便补齐依赖，仍会因缺少 `web-build` 产物而无法产出可用包 ——
   要么打包阶段报错，要么打出包后在非 dev 模式启动即白屏（加载不存在的本地文件）。

### 3.3 本轮处置（不臆造路径）

**未做**：没有猜测 `web-build` 应该由哪个入口生成并硬编码进去。原因：
- 仓库里存在三个候选 web 资源（`admin_system/frontend` 的 React 后台、`web/` 的官网静态站、`scripts/serve-local-web.js` 的本地联调壳），用途完全不同，凭猜测接线会把「管理后台」或「官网」误打成桌面 App；
- 且当前不存在 React Native Web 构建入口（`index.js` 是 RN 的 entry，不是 web 的）。

**已做**：把隐性失败改为显性失败。在 `electron/main.js` 中于加载前校验产物是否存在，缺失时给出明确、可操作的报错，而不是抛一个难以定位的 ENOENT 或在窗口里白屏。

### 3.4 待决策项（需产品/架构确认后再实施）

**web-build 到底应该由什么产出？** 三个选项：

| 方案 | 含义 | 代价 |
|---|---|---|
| A. 新增 React Native Web 构建 | 让 RN 代码跑在浏览器/Electron 里 | 需要新增 RNW 依赖与 webpack/vite 配置，改动面大 |
| B. 指向管理后台前端 | 桌面端 = 管理后台 | 语义错误：桌面用户不该看到管理后台，且与「解耦」目标冲突 |
| C. 移除 Electron 目标 | 当前不交付桌面端 | 最小改动，删除 `dist` 脚本与 electron-builder 配置 |

**在做出选择前，不建议继续维护 `web-build` 相关配置。** 本分支只加显性报错，不改变既定产物结构。

## 4. 残留风险

| 风险 | 说明 | 建议 |
|---|---|---|
| Electron 桌面端仍不可用 | 缺少 `web-build`，`yarn dist` 无法产出可运行包 | 按 3.4 决策后再实施 |
| 未做真实打包验证 | 本机无签名证书、无 `web-build`，**未实际执行 `yarn dist`**；本节结论来自配置与文件系统的静态核实 | 决策落地后补一次真实打包 |
| `metro_blocklist_check.js` 为新增脚本 | 已提交入库，属开发期校验工具 | 可纳入 CI（纯 Node，无额外依赖） |
| `electron-builder` 依赖缺失 | `package.json` 声明了 `dist` 脚本但未声明依赖，`yarn dist` 直接命令不存在 | 若确定要交付桌面端，需补 devDependencies；否则按 3.4 方案 C 移除 |
| 无 `.dockerignore` | 构建上下文仍包含 `admin_system`（最终镜像不含，仅浪费传输） | 补 `.dockerignore` 显式排除 |
