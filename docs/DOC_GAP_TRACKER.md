# 生产上线整改 GAP 台账

> 定位：本台账用于承接生产上线整改的全部 GAP、批次、责任分派、验收与证据回写。  
> 唯一执行入口：`docs/生产上线整改总控.md`。  
> 当前基线提交：`a1931d5`，已进入 `main`。

## 1. 使用规则
- 状态统一为：`NOT_STARTED` / `IN_PROGRESS` / `BLOCKED` / `DONE`
- 优先级统一为：`P0` / `P1` / `P2`
- 每条整改项必须包含：唯一 ID、优先级、状态、责任智能体、验收标准、关联提交哈希、关联验证证据
- 任何整改项未补齐提交哈希与验证证据，不得标记为 `DONE`
- 后续执行批次以批次 `0~5` 为准，不再沿用旧版批次 A/B/C/D
- `archive/*` 只作历史参考，新增状态与执行结论不得回写到 archive

## 2. 批次定义

| 批次 | 名称 | 目标 |
|---|---|---|
| 0 | 基线与入口收敛 | 冻结当前基线、统一执行入口、整理历史映射 |
| 1 | 安全整改 | 补齐生产安全、鉴权、配置、权限与高风险暴露项 |
| 2 | 部署整改 | 补齐部署、环境、发布链路、回滚与可观测性前置项 |
| 3 | CI 整改 | 补齐流水线、质量门禁、构建稳定性与证据产出 |
| 4 | 移动可测试性整改 | 补齐可安装包、测试账号、日志采集、弱网/设备矩阵 |
| 5 | 真机验证与发布准入 | 完成真机回归、阻塞清零与发布前最终签收 |

## 4. 批次执行说明

### 4.1 批次 0
- 目标：冻结基线、统一入口、收敛历史台账口径
- 关键项：`GAP-BASELINE-001`、`GAP-BASELINE-002`
- 退出条件：总控文档、GAP 台账、archive 映射三份文档全部切换到本次上线整改语境

### 4.2 批次 1
- 目标：先清安全风险，再允许进入部署整改
- 关键项：`GAP-SEC-001`、`GAP-SEC-002`
- 退出条件：生产安全阻塞项无遗漏，未完成项全部标记 `BLOCKED`

### 4.3 批次 2
- 目标：补齐部署与发布运行前置
- 关键项：`GAP-DEPLOY-001`、`GAP-DEPLOY-002`、`GAP-DEPLOY-003`
- 退出条件：部署、回滚、监控三类材料齐备且可执行

### 4.4 批次 3
- 目标：建立 CI 质量门禁和证据自动沉淀
- 关键项：`GAP-CI-001`、`GAP-CI-002`、`GAP-CI-003`
- 退出条件：每次独立修复都能追踪到提交、构建与验证

### 4.5 批次 4
- 目标：让移动端进入可测状态，而不是直接宣称已验证
- 关键项：`GAP-MOBILE-001`、`GAP-MOBILE-002`、`GAP-MOBILE-003`
- 退出条件：包、账号、环境、日志、Android 专用 MCP/插件、设备接入全部就绪

### 4.6 批次 5
- 目标：完成真机回归与发布准入判定
- 关键项：`GAP-DEVICE-001`、`GAP-DEVICE-002`
- 退出条件：准入签收完成，或形成明确驳回与阻塞升级记录
