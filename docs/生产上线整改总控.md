> 唯一执行入口：本文件为本次生产上线整改的唯一执行入口。  
> 配套台账：`docs/DOC_GAP_TRACKER.md`。  
> 历史参考：`docs/ARCHIVE_TO_GAP_MAPPING.md`。  
> 当前基线提交：`a1931d5`，已进入 `main`。

## 1. 目标与成功标准

### 1.1 目标
- 将本次生产上线整改收敛到单一执行入口，避免多份旧文档并行失控
- 以批次化方式推进安全、部署、CI、移动可测试性、真机验证与发布准入
- 让每个整改项都可追溯到责任智能体、提交哈希、验证证据与风险结论

### 1.2 成功标准
- 所有整改任务均登记在 `docs/DOC_GAP_TRACKER.md`
- 批次0~5均具备清晰目标、退出条件、责任智能体与阻塞升级路径
- 每个可独立验收修复都具备中文提交记录、远端推送记录、验证证据与风险说明
- 未满足验证门槛的事项不得宣称完成
- Android 专用 MCP/插件未就位前，不得宣称 Android 真机平板验证完成

## 3. 任务状态

| 状态 | 含义 | 使用规则 |
|---|---|---|
| `NOT_STARTED` | 尚未开始执行 | 仅完成登记，未形成实际动作 |
| `IN_PROGRESS` | 正在执行 | 必须已经明确责任智能体与下一步 |
| `BLOCKED` | 受阻 | 必须写明阻塞原因、影响范围、升级路径 |
| `DONE` | 已完成 | 必须具备提交哈希、验证证据、风险结论 |

## 4. 责任智能体

| 责任智能体 | 负责范围 | 交付要求 |
|---|---|---|
| 文档统筹智能体 | 总控文档、GAP 台账、archive 映射与日更维护 | 保证口径统一、状态可追溯 |
| 安全整改智能体 | 安全、鉴权、权限、敏感信息暴露问题 | 输出核查结论、整改记录、风险状态 |
| 部署整改智能体 | 环境、部署、监控、回滚与上线流程 | 输出部署说明、回滚预案、监控前置 |
| CI 整改智能体 | 构建、流水线、门禁、验证证据归档 | 输出构建结果、验证报告、失败结论 |
| 移动测试性智能体 | 测试包、账号、日志、设备与 Android 插件前置 | 输出可测性清单与缺失项 |
| 真机验证智能体 | 真机执行、截图录屏、问题收口 | 输出真机回归证据与问题清单 |
| 发布守门智能体 | 审核准入条件、判断是否放行 | 输出准入/驳回结论 |

## 5. 验证门槛
- 每个整改项必须在 GAP 台账中存在唯一 ID
- 每个整改项必须登记优先级、状态、责任智能体、验收标准
- 每个整改项进入 `DONE` 前，必须补齐关联提交哈希与关联验证证据
- 验证证据可包括：构建记录、测试报告、截图、录屏、日志、回滚演练记录、评审纪要
- 真机验证类事项除通用证据外，还必须有设备信息、构建版本、执行日期、执行人或责任智能体
- Android 专用 MCP/插件未就位前，任何 Android 平板相关事项最多只能标记为“前置未完成”或 `BLOCKED`

## 6. Git 记录规则
- 当前基线提交 `a1931d5` 已进入 `main`，后续整改默认基于该基线开展
- 后续默认分支命名：`QX/上线整改-批次XX-主题`
- 每个可独立验收的修复，完成后应立即进行中文提交并推送
- 每次提交正文必须写清：问题、原因、修改、验证、风险
- 每个 GAP 在关闭前，必须能回溯到至少一个关联提交哈希
- 若一个提交覆盖多个 GAP，必须在各 GAP 的“关联提交哈希”中显式列出
- 若验证失败、回滚或方案切换，必须同步更新 GAP 状态与每日执行日志

## 7. 风险/阻塞

| 风险类型 | 判定条件 | 处理要求 |
|---|---|---|
| 安全阻塞 | 存在未关闭的 P0 安全问题 | 不得进入批次2 |
| 部署阻塞 | 缺少环境、回滚或监控前置 | 不得进入批次5 |
| CI 阻塞 | 无稳定构建或无验证证据产出 | 不得宣称修复已可验收 |
| 移动阻塞 | 无测试包、账号、设备、日志路径 | 不得进入真机验证 |
| Android 插件阻塞 | Android 专用 MCP/插件或平板接入未就位 | 不得宣称 Android 真机平板验证完成 |
| 证据阻塞 | 缺少提交哈希或验证证据 | 不得标记 `DONE` |

## 8. 真机验证前置条件
- 已有可安装测试包，且能映射到明确提交哈希
- 测试账号、网络环境、依赖服务、权限配置全部可用
- 日志采集、截图、录屏、错误回传路径全部确认
- 已准备设备矩阵，至少明确手机/平板、系统版本、网络场景
- Android 专用 MCP/插件、Android 设备接入、平板验证路径全部就绪
- 若任一前置条件缺失，相关任务状态应标记为 `BLOCKED`
