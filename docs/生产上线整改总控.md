### 1.2 成功标准

## 7. 局域网联调方案
- 当前未部署服务器，默认不把公网前后端互通作为阶段验收前提。
- 默认方案：使用手机热点，让电脑与平板处于同一局域网下，进行 Android 安装、页面检查、功能回归和日志采集。
- 推荐补充方案：
  - 真机阶段优先使用 USB 调试，并执行 `adb reverse tcp:8081 tcp:8081` 保证 Metro 连接稳定。
  - 对多设备或平板可视化检查，可再切换到热点同局域网方案。
  - 若需要更稳定的远程调试链路，可在同一局域网下启用无线 ADB，并把连接步骤写入执行日志。
  - 本地双端联调阶段，默认先执行 `yarn local:web`，把 `http://127.0.0.1:8081/shared-screen-lab/` 作为共享链本地诊断入口；该入口只用于联调排障，不代表 React Native Web 主应用已完整补齐。
  - 当前 Android 工程 `sdk.dir` 已切到 `C:\Users\QX\AppData\Local\Android\Sdk`，命令行 `adb` 也统一来自 `C:\Users\QX\AppData\Local\Android\Sdk\platform-tools\adb.exe`；本轮已确认 attached-device 构建实际使用该用户目录 SDK/NDK（`ndkVersion=26.1.10909125`），后续如再切换路径，必须同步更新 `local.properties`、环境变量和执行日志。
  - 若浏览器或 API 需要访问本机服务，统一记录本机局域网 IP、端口、设备访问路径和热点名称。
- 每次联调必须记录：
  - 电脑 IP
  - 平板型号
  - Android 版本
  - 屏幕分辨率与 ABI
  - 热点来源
  - 是否可达
  - `adb.exe` 实际路径与版本
  - `sdk.dir` 实际路径
  - `adb devices -l` 输出
  - 是否执行 `adb reverse tcp:8081 tcp:8081`
  - Metro 访问方式是 USB reverse 还是 `PC_IP:8081`
  - App 包名 `com.zeroisle_notes`
  - 构建类型 `debug` / `release`
  - Android 专用 MCP/插件名称、版本、设备 ID
  - 日志采集方式
