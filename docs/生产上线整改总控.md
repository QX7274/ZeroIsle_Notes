## 1. 目标与成功标准

### 1.1 总目标
- 把仓库从“可开发、可演示”推进到“可审查、可验证、可发布上线”的工程状态。
- 先解决阻塞上线的安全、部署、配置、CI、测试环境、移动端可测试性问题，再进入功能审查与 Android 真机平板验证。
- 在整改过程中同步完成软件瘦身，删除无用、过时、可再生噪声文件，但不删除规划功能本身，不删除未完成功能的规划与实现依据。

### 1.2 成功标准
- 所有整改项、功能审查项、真机验证项都登记在 `docs/DOC_GAP_TRACKER.md`。
- 代码、文档、验证证据、Git 记录四者同步闭环，不允许出现“代码改了但文档和验证缺失”。
- 每个可独立验收的修复完成后，必须立即更新文档、提交、推送；提交标题与正文全部使用中文，且正文至少写清“问题、原因、修改、验证、风险”。
- Android 专用 MCP/插件未就位前，不得宣称已完成 Android 真机平板验证。
- 软件瘦身只允许删除缓存、编译产物、临时报告、测试转储、可再生 dump 等无用资产；不得删除规划功能、实现计划、模块状态文档、未完成需求资产。
- 环境准备完成后，必须使用工具开展功能审查与测试，判断功能是否按规划完成、是否足够完整上线、体验是否顺畅、响应是否足够快。

## 2. 固定执行规则

### 2.1 Git 规则
- 基线提交 `a1931d5` 作为当前生产整改起点，已直接进入 `main`。
- 后续每个整改批次默认使用 `QX/上线整改-批次XX-主题` 分支。

- 任何未经过文档登记、未绑定提交哈希、未附验证结果的修复，都不计入“已完成”。

### 2.2 环境规则
- Python 统一使用 Conda `ZeroIsle` 环境。
- 当前已定位到本机 Conda 根目录为 `D:\APP\Anaconda`，系统 `PATH` 尚未暴露 `conda` 命令。
- Python 相关操作统一通过 `D:\APP\Anaconda\condabin\conda.bat` 或 `D:\APP\Anaconda\Scripts\conda.exe` 进入项目环境后执行，不使用系统默认 `python`。
- 当前可发现的项目环境实际目录名为 `Zeroisle`，文档中保留“ZeroIsle”作为项目规范名时，必须补充说明“实际 Conda env 名称以本机环境列表为准”。
- 推荐激活方式：`& 'D:\APP\Anaconda\condabin\conda.bat' activate Zeroisle`
- 推荐直接执行方式：`& 'D:\APP\Anaconda\Scripts\conda.exe' run -n Zeroisle python --version`
- 前端依赖安装统一使用 `yarn install`。
- Android 前端运行统一使用 `yarn android`。
- 仓库根目录的 `yarn install` / `yarn android` 仅对应 React Native 主应用。
- `admin_system/frontend` 是独立后台前端子项目，不受根目录 `yarn install` 自动覆盖；如需运行该子项目，必须进入对应目录单独安装与启动。
- 不再把 `npm install`、`npm run android` 作为默认文档命令；若排障时临时使用，必须在日志中说明原因与范围。

### 2.3 软件瘦身规则
- 允许删除：
  - `__pycache__`、`.pyc`、Gradle/pytest 本地缓存
  - 临时测试输出、Compose 临时日志、Android 工具盘点文本
  - 审计结果缓存、UI dump、可再生 XML/JSON/TXT 报告
- 禁止删除：
  - 规划中未完成功能对应的源码、测试、设计、说明文档
  - `archive/*`、`module-status/*`、`optimization-docs/*`、`PENDING_WORK_GUIDE.md` 等仍需参考的规划资产
  - 当前总控文档、GAP 台账、历史映射、实现计划与模块功能核查记录
- 每次瘦身必须先登记删除对象、删除原因、是否可再生、验证方式、影响范围与风险。
- 删除完成后必须验证不会影响当前规划功能与后续实施路径。

### 2.4 功能审查规则
- 环境准备完成后，立即使用可用工具开展功能审查与测试。
- 功能审查至少回答三个问题：
  - 规划功能是否已经实现
  - 功能是否足够完整，能否支持上线使用
  - 使用体验是否良好，速度是否可接受
- 当前尚未部署到服务器，默认不以公网前后端互通作为阶段验收前提。
- 在未部署阶段，默认使用手机热点或更稳定的同局域网方案，让电脑与平板处于同一网络，以便进行安装、联调、页面检查与日志采集。

## 7. 局域网联调方案
- 当前未部署服务器，默认不把公网前后端互通作为阶段验收前提。
- 默认方案：使用手机热点，让电脑与平板处于同一局域网下，进行 Android 安装、页面检查、功能回归和日志采集。
- 推荐补充方案：
  - 真机阶段优先使用 USB 调试，并执行 `adb reverse tcp:8081 tcp:8081` 保证 Metro 连接稳定。
  - 对多设备或平板可视化检查，可再切换到热点同局域网方案。
  - 若需要更稳定的远程调试链路，可在同一局域网下启用无线 ADB，并把连接步骤写入执行日志。
  - 当前 Android 工程 `sdk.dir` 指向 `D:\Android\Sdk`，而命令行 `adb` 实际来自 `C:\Users\QX\AppData\Local\Android\Sdk\platform-tools\adb.exe`；开始真机验证前必须记录并说明实际使用的 SDK / ADB 路径。
  - 若浏览器或 API 需要访问本机服务，统一记录本机局域网 IP、端口、设备访问路径和热点名称。
- 每次联调必须记录：
  - 电脑 IP
  - 平板型号
  - Android 版本
  - 屏幕分辨率与 ABI
  - 热点来源
  - 是否可达
  - `adb.exe` 实际路径与版本
  - `sdk.dir` 实际路径
  - `adb devices -l` 输出
  - 是否执行 `adb reverse tcp:8081 tcp:8081`
  - Metro 访问方式是 USB reverse 还是 `PC_IP:8081`
  - App 包名 `com.zeroisle_notes`
  - 构建类型 `debug` / `release`
  - Android 专用 MCP/插件名称、版本、设备 ID
  - 日志采集方式
