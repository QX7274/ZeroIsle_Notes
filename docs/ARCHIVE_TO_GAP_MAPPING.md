# Archive 到当前 GAP/批次映射

> 定位：本文件用于说明 `archive/*` 仅作历史参考，并将历史材料映射到当前生产上线整改批次与 GAP。  
> 执行规则：后续执行、状态流转、验收签收一律以 `docs/生产上线整改总控.md` 和 `docs/DOC_GAP_TRACKER.md` 为准。

## 1. 使用边界
- `archive/*` 只保存历史核查、旧方案、旧结论，不再作为执行入口
- 不在 `archive/*` 中新增负责人、状态、提交哈希、验收结论
- 如 archive 与当前总控/GAP 台账表述冲突，以当前总控/GAP 台账为准
- 历史材料仅用于追溯问题来源、补证、复盘，不作为放行依据

## 2. 映射状态说明
- `MAPPED`：已归入当前批次与 GAP
- `NEED_SPLIT`：需要拆成多个当前 GAP
- `REVIEW_REQUIRED`：需补证后再决定映射位置

## 3. 映射原则
- 历史文档中的安全、鉴权、权限、敏感信息问题，优先映射到批次1
- 历史文档中的部署、环境、回滚、监控问题，优先映射到批次2
- 历史文档中的流水线、构建、自动验证、质量门禁问题，优先映射到批次3
- 历史文档中的安装包、账号环境、日志、设备矩阵、测试准备问题，优先映射到批次4
- 历史文档中的真机回归、发布签收、发布阻塞问题，优先映射到批次5
- 纯文档口径、台账迁移、历史转办问题，归入批次0

## 5. 维护要求
- 新发现的历史问题，先补录到 `docs/DOC_GAP_TRACKER.md`，再回填本映射文件
- 已在当前 GAP 中关闭的问题，可在 archive 对应条目旁标注“已转办”，但不回写执行细节
- 若某条历史问题无法归入现有 GAP，先标记 `REVIEW_REQUIRED`，由文档统筹智能体决定是否新增 GAP
- Android 专用 MCP/插件未就位前，不得将任何 archive 中与 Android 平板相关的内容标注为“真机验证完成”
