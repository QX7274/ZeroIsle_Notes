# 零屿笔记同步策略文档

## 概述

零屿笔记采用分层同步策略，将数据分为关键数据和非关键数据两类，分别采用不同的同步策略。这种设计既保证了关键数据的及时同步，又避免了过度同步导致的网络和电池消耗。

## 数据分类

### 关键数据

关键数据是指对用户体验和应用功能至关重要的数据，包括：

1. **用户信息**：用户名、邮箱、头像、个人设置等
2. **应用设置**：主题、字体大小、通知设置等
3. **同步配置**：同步间隔、自动同步设置等

关键数据具有以下特点：
- 数据量小
- 变更频率低
- 对用户体验影响大
- 需要跨设备保持一致

### 非关键数据

非关键数据是指应用的主要内容数据，包括：

1. **笔记**：笔记内容、标签、分类等
2. **提醒**：提醒时间、内容、状态等
3. **知识图谱**：节点、关系等
4. **思维导图**：节点、连接等
5. **文件**：附件、图片等

非关键数据具有以下特点：
- 数据量大
- 变更频率高
- 可以接受短时间的不一致
- 同步需要考虑网络和电池消耗

## 同步策略

### 关键数据同步策略

关键数据采用**自动同步**策略，具体包括：

1. **定时同步**：每2分钟自动检查并同步一次关键数据
2. **网络恢复同步**：网络从离线恢复到在线时，立即同步关键数据
3. **应用启动同步**：应用启动时自动同步关键数据
4. **应用切换到后台同步**：应用切换到后台时自动同步关键数据

关键数据同步的特点：
- 无需用户手动触发
- 优先级高，在其他同步操作之前执行
- 使用专门的API端点：`/sync/key-data/`
- 双向同步，既上传本地更改，也下载云端更改

### 非关键数据同步策略

非关键数据采用**手动触发+条件自动**策略，具体包括：

1. **手动触发**：用户可以通过UI手动触发同步
2. **条件自动**：在特定条件下自动触发同步，如：
   - 创建或编辑笔记后
   - 添加或完成提醒后
   - 定期批量同步（可配置间隔，默认30分钟）

非关键数据同步的特点：
- 需要考虑网络条件和电池消耗
- 使用离线队列存储待同步操作
- 分类型同步，使用不同的API端点：
  - `/sync/notes/`
  - `/sync/reminders/`
  - `/sync/settings/`
- 支持增量同步，只同步变更的数据

## 离线操作处理

当设备离线时，所有的数据操作都会被存储在离线队列中，等待网络恢复后同步。离线队列的处理策略如下：

1. **队列存储**：所有离线操作按时间顺序存储在本地数据库中
2. **分类处理**：同步时按数据类型分组处理，减少API请求次数
3. **冲突解决**：采用"最新胜出"策略解决冲突，可在设置中配置
4. **重试机制**：同步失败的操作会自动重试，最多3次
5. **手动清理**：用户可以手动清理离线队列

## 同步流程

### 关键数据同步流程

1. 检查网络状态和同步状态
2. 收集本地关键数据（用户信息、设置）
3. 调用`/sync/key-data/`API
4. 处理服务器响应，更新本地数据
5. 更新同步时间和状态

### 非关键数据同步流程

1. 检查网络状态和同步状态
2. 处理离线队列中的操作
   - 按数据类型分组
   - 批量发送到相应的API端点
   - 标记成功同步的操作
3. 从服务器拉取更新
4. 合并本地和服务器数据，解决冲突
5. 更新同步时间和状态

## 同步状态管理

同步服务维护以下状态信息：

1. **上次同步时间**：记录最近一次成功同步的时间
2. **同步状态**：当前是否正在同步
3. **离线队列长度**：待同步操作的数量
4. **网络状态**：当前网络是否可用

这些状态可以通过UI展示给用户，让用户了解当前的同步情况。

## 同步设置

用户可以在设置中配置以下同步选项：

1. **自动同步**：是否启用自动同步
2. **同步间隔**：非关键数据的自动同步间隔（分钟）
3. **应用启动时同步**：是否在应用启动时同步
4. **应用切换到后台时同步**：是否在应用切换到后台时同步
5. **冲突解决策略**：如何解决数据冲突（最新胜出、本地优先、服务器优先）

## 技术实现

### 前端实现

1. **同步服务**：`syncService.js`
   - 提供同步API
   - 管理同步状态
   - 处理离线队列
   - 发送同步请求

2. **离线队列**：`OfflineQueue`模型
   - 存储待同步操作
   - 记录操作类型、集合、文档ID和数据

3. **网络监听**：`networkService.js`
   - 监听网络状态变化
   - 在网络恢复时触发同步

4. **同步UI**：`SyncButton`和`SyncSettingsScreen`
   - 显示同步状态
   - 提供同步设置界面

### 后端实现

1. **同步API**：
   - `/sync/key-data/`：关键数据同步
   - `/sync/notes/`：笔记同步
   - `/sync/reminders/`：提醒同步
   - `/sync/settings/`：设置同步

2. **同步服务**：`SyncService`
   - 处理同步请求
   - 合并数据
   - 解决冲突

3. **数据存储**：MongoDB Atlas
   - 存储所有同步的数据
   - 提供查询和更新API

## 最佳实践

1. **减少同步频率**：关键数据每2分钟同步一次，非关键数据根据需要同步
2. **批量处理**：同一类型的数据批量同步，减少API请求次数
3. **增量同步**：只同步变更的数据，减少数据传输量
4. **网络感知**：根据网络状态调整同步策略，如WiFi下可以更频繁地同步
5. **后台同步**：在应用切换到后台时同步，不影响用户体验
6. **错误处理**：妥善处理同步错误，提供重试机制
7. **用户反馈**：通过UI向用户展示同步状态和进度
