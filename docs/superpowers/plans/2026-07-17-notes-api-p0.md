# Notes API P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the intentionally throwing `notesApi` P0 methods with observable, testable note-editor behavior without claiming remote synchronization that has not been verified.

**Architecture:** Keep `notesApi` as the caller-facing module. Its implementation uses the existing `apiClient` seam for the authenticated attachment endpoint and Realm `Note`/`NoteBackup`/`OfflineQueue` records for local-first editing, version snapshots, and offline recovery. Remote version endpoints remain available through `noteVersionApi`; this batch makes the `notesApi` contract safe for Redux callers and local tablet development.

**Tech Stack:** React Native, JavaScript, Axios wrapper, Realm 20, Jest, Yarn, Android tablet via `yarn android`, Conda `ZeroIsle` for backend verification.

---

## Public behaviors

1. `uploadImage(formData, noteId)` maps the editor's `image`/`note_id` fields to the backend attachment contract `file`/`note`, returns a usable `{ success, url, attachment }` result, and returns the original local URI only for a real network/offline failure.
2. `autoSaveNote(id, noteData)` validates the note, merges the supplied fields into the local note, updates timestamps, and writes an auto snapshot without returning a placeholder.
3. `getNoteHistory(id)` returns newest-first snapshot records; `getNoteVersion(id, versionId)` returns the stored content; `restoreNoteVersion(id, versionId)` creates a new restore snapshot and returns the restored note.
4. `saveOfflineNote(note)` upserts a local note and creates at most one pending `OfflineQueue` item per `clientOpId`.
5. `getNoteCategories()` returns non-deleted local categories in stable name order using the existing `{ success, data }` response shape.
