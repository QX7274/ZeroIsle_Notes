# 全系统优化执行总台账

> 目标：用于记录“问题-改造-证据-结论”的事实闭环，不记录口号。  
> 配套规范见：[系统优化执行宪章](D:/ZeroIsle_Notes/docs/系统优化执行宪章.md)  
> 页面状态总览见：[页面能力矩阵](D:/ZeroIsle_Notes/docs/页面能力矩阵.md)

## 1. 使用说明
- 本台账只记录已执行事项与可复核证据。
- 每条记录必须绑定：页面ID、子功能、风险级别、证据路径、回归结果。
- 若条目未提供证据或回归结论，状态不得标记为 `DONE`。

## 2. 字段标准
| 字段 | 说明 |
|---|---|
| round | 轮次编号（例：round163） |
| page_id | 页面ID（与页面矩阵一致） |
| sub_feature | 子功能名称 |
| severity | P0 / P1 / P2 |
| issue | 具体问题（可复现） |
| change | 已实施改造（代码/配置/交互） |
| evidence | 真机证据（png/xml/log） |
| tests | 单测/组件测试/脚本验收结果 |
| status | TODO / IN_PROGRESS / DONE / BLOCKED |
| next_action | 下一步动作（可执行） |

## 3. 当前阶段目标（2026-05-16）
- 目标一：完成全系统页面与子功能的“可审查、可验证、可追踪”闭环。
- 目标二：统一蓝白轻毛玻璃视觉基线，消除跨页面样式割裂。
- 目标三：RTK/交互并发守卫策略统一，优先清零 P0。
- 目标四：安卓平板页面顶部必须按安全区计算可视高度，不能再按整块屏幕直接铺满，更不能仅靠隐藏状态栏来掩盖顶部遮挡问题。
